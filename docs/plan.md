# План разработки OneScriptJS

Разбивка переноса движка OneScript (C#) на TypeScript. Источник структуры —
[`docs/architecture.md`](architecture.md) и `reference/OneScript/docs/developer_docs.md`.

## Подход

1. **MVP-first (walking skeleton).** Сначала делаем рабочим приёмочный пример
   [`examples/hello.html`](../examples/hello.html): лексер → парсер → интерпретатор →
   браузерный вывод. Дальше наращиваем язык по слоям.
2. **Tree-walking интерпретатор, а не байткод-ВМ.** В оригинале AST компилируется в
   байткод стековой машины (`ScriptEngine/Compiler` + `Machine`). Для корректности
   семантики языка ВМ не нужна — это оптимизация. `shortcut: интерпретатор вместо ВМ,
   вернуться к компилятору/ВМ только если появятся требования к производительности`.
3. **TDD**: каждый нетривиальный таск начинается с падающего теста (Vitest), потом
   минимальная реализация (см. `AGENTS.md` §6–7).

## Definition of Done

`pnpm typecheck && pnpm test` — зелёные. Для тасков, меняющих сборку/входные точки —
дополнительно `pnpm build`.

## Фаза 1 — Walking skeleton (hello.html)

Цель фазы: `examples/hello.html` выполняет код, вывод `сообщить()` идёт в `console.log`.

### T1. Лексер
- **Цель**: исходник BSL → поток токенов. Идентификаторы (в т.ч. русские),
  строки, числа, даты, `Истина`/`Ложь`/`Неопределено`/`NULL`, операторы, ключевые
  слова, `;` (конец оператора), комментарии `//`, препроцессорные строки `#`.
- **Эталон**: `reference/OneScript/src/OneScript.Language/LexicalAnalysis/`
  (`LexemType`, `DefaultLexer`, `*LexerState`).
- **Файлы**: `src/lexer/` (`token.ts`, `token-type.ts`, `lexer.ts`), `tests/lexer.test.ts`.
- **Приёмка**: лексер разбирает `имя = "Никита"; возраст = 38; сообщить("..." + имя);`
  без ошибок; тесты покрывают каждый литерал/оператор/ключевое слово.
- **Зависит от**: —

### T2. AST и парсер
- **Цель**: токены → AST. Узлы-минимум: `Module`, `CodeBatch`, `VariableDefinition`,
  `If` (Branching), литералы/идентификаторы, `BinaryOperation`, `UnaryOperation`,
  `Call`, скобочное выражение.
- **Эталон**: `reference/OneScript/src/OneScript.Language/SyntaxAnalysis/`
  (`AstNodes/*`, `DefaultBslParser`).
- **Файлы**: `src/ast/` (`node.ts`, `nodes.ts`), `src/parser/` (`parser.ts`),
  `tests/parser.test.ts`.
- **Приёмка**: парсит вложенные `если/тогда/конецесли`, присваивания, вызовы;
  позиции узлов сохраняются для сообщений об ошибках.
- **Зависит от**: T1.

### T3. Система значений
- **Цель**: рантайм-значения и операции: `Строка`, `Число`, `Булево`, `Дата`,
  `Неопределено`, `NULL`, `Тип`; сравнение, `+` (числа и конкатенация строк),
  приведение типов (как в 1С: число↔строка, пустое↔ложь).
- **Эталон**: `reference/OneScript/src/OneScript.Core/Values/` (`BslValue` и производные).
- **Файлы**: `src/runtime/values.ts`, `tests/values.test.ts`.
- **Приёмка**: `"Привет, " + имя` даёт конкатенацию; `возраст > 18` сравнивает числа;
  таблица приведений покрыта тестами.
- **Зависит от**: —

### T4. Интерпретатор (tree-walking)
- **Цель**: выполнение AST: области видимости/переменные, присваивание, `если`,
  вычисление выражений, вызов глобальных функций.
- **Эталон**: семантика `reference/OneScript/src/ScriptEngine/Machine/` (упрощённо).
- **Файлы**: `src/runtime/interpreter.ts`, `src/runtime/scope.ts`, `tests/interpreter.test.ts`.
- **Приёмка**: скрипт из `hello.html` без `сообщить` выполняется, переменные и
  ветвления дают ожидаемый результат (проверяется через инъекцию фиктивного вывода).
- **Зависит от**: T2, T3.

### T5. Стандартная библиотека: глобальный контекст + `Сообщить`
- **Цель**: реестр глобальных функций стандартной библиотеки; `Сообщить`/`Message(message, status?)`
  выводит в JavaScript `console.log`. Двуязычные алиасы.
- **Эталон**: `reference/OneScript/src/ScriptEngine.HostedScript/SystemGlobalContext.cs`
  (метод `Echo`), `MessageStatusEnum`.
- **Файлы**: `src/runtime/context.ts`, `src/stdlib/global-context.ts`, `tests/global-context.test.ts`.
- **Приёмка**: `сообщить("x")` и `Message("x")` печатают в `console.log` (в Node — stdout);
  статусы `БезСтатуса`/`Важное`/`Внимание`/`Информация`/`Обычное`/`ОченьВажное`
  принимаются, по умолчанию — `Обычное`.
- **Зависит от**: T4.

### T6. Браузерный коннектор
- **Цель**: `<one-script>` берёт код из содержимого и исполняет; вывод `сообщить()`
  идёт в `console.log` браузера; сборка `dist/onescript.js` (уже настроена).
- **Эталон**: `examples/hello.html` (приёмочный сценарий).
- **Файлы**: `src/browser/onescript.ts`, `examples/hello.html`.
- **Приёмка**: `pnpm build:browser`, открыть `examples/hello.html` — в консоли браузера
  «Привет, ты указал: Никита, Иванченко», «возраст больше 30», «Добро пожаловать…».
- **Зависит от**: T5.

### T7. Node CLI
- **Цель**: запуск `.os`-файла из консоли, `сообщить()` → stdout (через `console.log`).
- **Файлы**: `src/node/cli.ts`, скрипт `pnpm run <file.os>`.
- **Приёмка**: `echo 'сообщить("hi");' | node ...` печатает `hi`.
- **Зависит от**: T5.

- `Pow` с decimal-точностью (`Pow(2, 0.5)` → `1.4142135623731`, а не `…951`).
- Арифметика дат (прибавка секунд с точностью 1С).

### T41. Валидация и граничные случаи
- `ПобитовыйСдвигВлево`/`Вправо` — ошибка при смещении вне диапазона (≥ 32 / ≤ −32).
- `СтрПолучитьСтроку`/`СтрЧислоСтрок` — обработка `\r\n`.

### T42. Методы тест-контекста
- `ПодробныеОписанияОшибок`, `ИмяВременногоФайла`, `ПроверитьТип` в `BslTestContext`.

### T43. Динамическое исполнение: `Выполнить` / `Вычислить`
- Оператор `Выполнить <строка>` — разобрать и исполнить строку кода в **текущей** области
  видимости (читает/меняет локальные переменные); значения не возвращает.
- Функция `Вычислить <строка>` — разобрать строку как выражение, вычислить в текущей
  области видимости и вернуть значение.
- Нужно дать `Interpreter` точку входа «исполнить в текущем `Scope`/`Ctx`» (сейчас
  `run`/`invokeMethod` создают свежие области). `Возврат` вне метода — ошибка.
- **Эталон**: `BuildExecuteStatement`, `Token.Evaluate`; `ScriptEngine/Machine`.
- **Разблокирует**: `eval.os`. **Зависит от**: T39 (`ЗагрузитьСценарийИзСтроки` — общий
  механизм «исходник → исполнение»).

### T44. События: `ДобавитьОбработчик` / `УдалитьОбработчик`
- Операторы `ДобавитьОбработчик <Событие>, <Обработчик>;` и `УдалитьОбработчик …`,
  где `<Событие>`/`<Обработчик>` — обращение к свойству или индексу (не произвольное
  выражение — иначе ошибка «неверное имя события/обработчика»).
- Рантайм: модель событий у `BslObject` (подписка/отписка по имени события),
  `ВызватьСобытие(Имя, Параметры)` и `ЭтотОбъект`.
- **Эталон**: `BuildEventHandlerOperation`, `Token.AddHandler`/`RemoveHandler`,
  `EventHandler`/`ExternalEventHandler` в ScriptEngine.
- **Разблокирует**: `events.os`. **Зависит от**: `ЭтотОбъект` (свойство модуля/объекта).

### T45. Парсер: вложенные и именованные аннотации
- `&Аннотация(Параметр = &Аннотация(…, П2 = &Аннотация(…)))` — именованные параметры
  и вложенные `&Аннотация` внутри списка параметров аннотации (сейчас `skipAnnotation`
  разбирает только плоские выражения через запятую).
- Полноценная рефлексия аннотаций (`Рефлектор`) — отдельная крупная подсистема, вне
  scope этой задачи: после правки парсера `annotations.os` перестанет падать на
  разборе, но тесты, читающие аннотации через `Рефлектор`, останутся красными.
- **Эталон**: `AnnotationNode`/`BuildAnnotation`, `DefaultBslParser` (блок аннотаций).
- **Файлы**: `src/parser/parser.ts`.

## Явно вне scope (из task.md)

Работа с файлами, сеть, процессы, COM, Native API — **недоступны в браузере** и не
переносятся в первую очередь. В Node допускается точечная поддержка файлов (`Файл`,
`ЧтениеТекста`) как отдельная опциональная задача, но не в MVP.
