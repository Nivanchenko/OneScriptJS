# План разработки OneScriptJS

Разбивка переноса движка OneScript (C#) на TypeScript. Источник структуры —
[`docs/architecture.md`](architecture.md) и `reference/OneScript/docs/developer_docs.md`.

## Подход

1. **MVP-first (walking skeleton).** Сначала делаем рабочим приёмочный пример
   [`examples/hello.html`](../examples/hello.html): лексер → парсер → интерпретатор →
   браузерный вывод. Дальше наращиваем язык по слоям.
2. **Tree-walking интерпретатор, а не байткод-ВМ.** В оригинале AST компилируется в
   байткод стековой машины (`ScriptEngine/Compiler` + `Machine`). Для корректности
   семантики языка ВМ не нужна — это оптимизация. `shortcut: интерпретатор вместо ВМ,
   вернуться к компилятору/ВМ только если появятся требования к производительности`.
3. **TDD**: каждый нетривиальный таск начинается с падающего теста (Vitest), потом
   минимальная реализация (см. `AGENTS.md` §6–7).

## Definition of Done

`pnpm typecheck && pnpm test` — зелёные. Для тасков, меняющих сборку/входные точки —
дополнительно `pnpm build`.

## Фаза 1 — Walking skeleton (hello.html)

Цель фазы: `examples/hello.html` выполняет код, вывод `сообщить()` идёт в `console.log`.

### T1. Лексер
- **Цель**: исходник BSL → поток токенов. Идентификаторы (в т.ч. русские),
  строки, числа, даты, `Истина`/`Ложь`/`Неопределено`/`NULL`, операторы, ключевые
  слова, `;` (конец оператора), комментарии `//`, препроцессорные строки `#`.
- **Эталон**: `reference/OneScript/src/OneScript.Language/LexicalAnalysis/`
  (`LexemType`, `DefaultLexer`, `*LexerState`).
- **Файлы**: `src/lexer/` (`token.ts`, `token-type.ts`, `lexer.ts`), `tests/lexer.test.ts`.
- **Приёмка**: лексер разбирает `имя = "Никита"; возраст = 38; сообщить("..." + имя);`
  без ошибок; тесты покрывают каждый литерал/оператор/ключевое слово.
- **Зависит от**: —

### T2. AST и парсер
- **Цель**: токены → AST. Узлы-минимум: `Module`, `CodeBatch`, `VariableDefinition`,
  `If` (Branching), литералы/идентификаторы, `BinaryOperation`, `UnaryOperation`,
  `Call`, скобочное выражение.
- **Эталон**: `reference/OneScript/src/OneScript.Language/SyntaxAnalysis/`
  (`AstNodes/*`, `DefaultBslParser`).
- **Файлы**: `src/ast/` (`node.ts`, `nodes.ts`), `src/parser/` (`parser.ts`),
  `tests/parser.test.ts`.
- **Приёмка**: парсит вложенные `если/тогда/конецесли`, присваивания, вызовы;
  позиции узлов сохраняются для сообщений об ошибках.
- **Зависит от**: T1.

### T3. Система значений
- **Цель**: рантайм-значения и операции: `Строка`, `Число`, `Булево`, `Дата`,
  `Неопределено`, `NULL`, `Тип`; сравнение, `+` (числа и конкатенация строк),
  приведение типов (как в 1С: число↔строка, пустое↔ложь).
- **Эталон**: `reference/OneScript/src/OneScript.Core/Values/` (`BslValue` и производные).
- **Файлы**: `src/runtime/values.ts`, `tests/values.test.ts`.
- **Приёмка**: `"Привет, " + имя` даёт конкатенацию; `возраст > 18` сравнивает числа;
  таблица приведений покрыта тестами.
- **Зависит от**: —

### T4. Интерпретатор (tree-walking)
- **Цель**: выполнение AST: области видимости/переменные, присваивание, `если`,
  вычисление выражений, вызов глобальных функций.
- **Эталон**: семантика `reference/OneScript/src/ScriptEngine/Machine/` (упрощённо).
- **Файлы**: `src/runtime/interpreter.ts`, `src/runtime/scope.ts`, `tests/interpreter.test.ts`.
- **Приёмка**: скрипт из `hello.html` без `сообщить` выполняется, переменные и
  ветвления дают ожидаемый результат (проверяется через инъекцию фиктивного вывода).
- **Зависит от**: T2, T3.

### T5. Стандартная библиотека: глобальный контекст + `Сообщить`
- **Цель**: реестр глобальных функций стандартной библиотеки; `Сообщить`/`Message(message, status?)`
  выводит в JavaScript `console.log`. Двуязычные алиасы.
- **Эталон**: `reference/OneScript/src/ScriptEngine.HostedScript/SystemGlobalContext.cs`
  (метод `Echo`), `MessageStatusEnum`.
- **Файлы**: `src/runtime/context.ts`, `src/stdlib/global-context.ts`, `tests/global-context.test.ts`.
- **Приёмка**: `сообщить("x")` и `Message("x")` печатают в `console.log` (в Node — stdout);
  статусы `БезСтатуса`/`Важное`/`Внимание`/`Информация`/`Обычное`/`ОченьВажное`
  принимаются, по умолчанию — `Обычное`.
- **Зависит от**: T4.

### T6. Браузерный коннектор
- **Цель**: `<one-script>` берёт код из содержимого и исполняет; вывод `сообщить()`
  идёт в `console.log` браузера; сборка `dist/onescript.js` (уже настроена).
- **Эталон**: `examples/hello.html` (приёмочный сценарий).
- **Файлы**: `src/browser/onescript.ts`, `examples/hello.html`.
- **Приёмка**: `pnpm build:browser`, открыть `examples/hello.html` — в консоли браузера
  «Привет, ты указал: Никита, Иванченко», «возраст больше 30», «Добро пожаловать…».
- **Зависит от**: T5.

### T7. Node CLI
- **Цель**: запуск `.os`-файла из консоли, `сообщить()` → stdout (через `console.log`).
- **Файлы**: `src/node/cli.ts`, скрипт `pnpm run <file.os>`.
- **Приёмка**: `echo 'сообщить("hi");' | node ...` печатает `hi`.
- **Зависит от**: T5.

## Фаза 7 — Браузерная интеграция (DOM и события)

Цель: `<one-script>` — не только «выполнить код», но и полноценный способ оживить
HTML-страницу на BSL: читать/менять DOM и подписываться на события элементов
(кнопки, поля ввода, наведение и т.п.).

Ограничения, которые определяют архитектуру:

- `src/stdlib/` **обязан оставаться Node-совместимым** (без `document`/`window`), иначе
  сломается сборка Node-библиотеки. DOM-слой живёт в `src/browser/` и подключается
  отдельной фабрикой контекста — по тому же принципу, что `src/node/files.ts` для Node.
- `Сообщить()` по-прежнему пишет в `console.log` (явное требование из `task.md`) — DOM
  меняется **только** явно, через объект `Документ`.
- Обработчик события — это BSL-код (строка), который должен видеть **переменные модуля**
  того `<one-script>`, откуда он привязан. Значит, после `run()` нужно сохранять область
  видимости модуля, а не выбрасывать её.

### T46. ✅ Браузерный контекст + объект `Документ` (DOM)
- Новая фабрика `createBrowserGlobalContext()` в `src/browser/context.ts`:
  `createGlobalContext()` + регистрация DOM-объектов. `src/browser/onescript.ts`
  переключается на неё.
- `src/browser/dom.ts` — обёртки над DOM, реализующие `BslObject`:
  - `Документ` (`document`): `ПолучитьЭлемент(Ид)` (или `Неопределено`), `СоздатьЭлемент(Тег)`,
    `ТелоКорпуса`, `Заголовок` (чтение/запись).
  - `Элемент`: свойства `Текст`, `Значение`, `Идентификатор`, `Класс`, `Стиль` (под-объект:
    `Установить(имя, значение)`), методы `УстановитьАтрибут`/`ПолучитьАтрибут`,
    `ДобавитьВ(родитель)`, `Удалить()`, `ДобавитьКласс`/`УбратьКласс`,
    `Родитель`, `Дети` (`Массив`).
  - `Стиль`: `Установить`/`Получить`; доступ через `Элемент.Стиль`.
- При отсутствии `document` (Node) — понятная ошибка «Документ недоступен вне браузера»
  (объекты создаются только браузерной фабрикой, но страховка нужна).
- Приёмка (Vitest + `happy-dom`, как в `tests/browser.test.ts`): создать элемент, задать
  текст/класс/стиль/атрибут, вложить в контейнер, прочитать обратно; `ПолучитьЭлемент`
  по несуществующему id → `Неопределено`.
- **Файлы**: `src/browser/context.ts`, `src/browser/dom.ts`, `src/browser/onescript.ts`,
  `tests/browser-dom.test.ts`, `examples/dom.html`. **Зависит от**: T6 (готово).

  Стиль/Родитель/Дети/ИмяТега, атрибуты, классы, `Добавить`/`ДобавитьВ`/`Удалить`),
  `СтильDOM`. 10 тестов на `happy-dom` + демо `examples/dom.html`.

### T47. ✅ Экземпляр скрипта + подписка на события из BSL
- Рантайм: `run()`/`Interpreter` должны отдавать «экземпляр модуля» — объект с доступом к
  области видимости модуля и возможность исполнить произвольный код в ней
  (`executeInModule(code)`). Сейчас `moduleCtx`/`moduleScope` приватны и теряются.
  Переиспользовать механизм `execDynamic` из T43.
- `Элемент.НаСобытие(Имя, Код)` / `СнятьСобытие(Имя)`: регистрирует обработчик-строку;
  при событии код исполняется в области видимости того скрипта, который подписался
  (значит, видит его переменные — замыкание по module scope).
- Поддерживаемые имена (RU/EN): `Нажатие`/`click`, `ДвойноеНажатие`, `Ввод`/`input`,
  `Изменение`/`change`, `Наведение`/`mouseenter`, `Уход`/`mouseleave`,
  `НажатиеКлавиши`/`keydown`, `Отправка`/`submit`.
- Объект `Событие` для обработчика (необязательно к полной реализации): `Цель`, `Отменить()`.
- Приёмка (happy-dom): счётчик на кнопке (`счёт = счёт + 1`) без потери значения между
  нажатиями; поле ввода зеркалирует текст в другой элемент; наведение меняет класс.
- **Файлы**: `src/runtime/interpreter.ts` (`executeInModule`), `src/browser/dom.ts`,
  `tests/browser-events.test.ts`.
- **Зависит от**: T46. **Не путать с T44**: T44 — BSL-события (`ДобавитьОбработчик`,
  `ВызватьСобытие`, `ЭтотОбъект`), здесь — события DOM.
- **Сделано**: `Интерпретатор.executeInModule(код, переменные?)` исполняет код в области
  видимости модуля (без подмены записи модульных переменных); `ЭлементDOM.НаСобытие(Имя, Код)`
  и `СнятьСобытие(Имя)`; слушатели хранятся в `WeakMap` по DOM-элементу (снять можно из
  любой обёртки); объект `Событие` (`Тип`, `Цель`, `Отменить()`,
  `ОстановитьРаспространение()`); ошибка в обработчике ловится и пишется в `console.error`,
  страница продолжает работать. 10 тестов на `happy-dom`, включая сквозной через `<one-script>`.
- **Важно**: чтобы обработчик менял переменную между вызовами, она должна быть объявлена
  через `Перем` (иначе присваивание создаёт локальную — как в 1С внутри процедуры).

### T48. Декларативная привязка событий через data-атрибуты
- Sugar над T47, чтобы не писать BSL-привязку для каждой кнопки:
  `<button data-os-click="счёт = счёт + 1; Отразить()">`.
- Событие берётся из второго сегмента атрибута: `data-os-click`, `data-os-input`,
  `data-os-change`, `data-os-mouseenter`, `data-os-mouseleave`, `data-os-dblclick`,
  `data-os-keydown`, `data-os-submit`.
- Контекст исполнения — область видимости скрипта, указанного атрибутом
  `data-os-script="<id>"` (ссылка на `<one-script id="…">`). Если атрибут не задан —
  первый `<one-script>` на странице. Без единого `<one-script>` — обработчики не
  активируются (и в консоль идёт предупреждение).
- Сканирование при инициализации + при добавлении новых узлов через `MutationObserver`
  (только если это не усложняет: базовый вариант — однократный разбор при загрузке).
- Приёмка (happy-dom): кнопка с `data-os-click` увеличивает переменную скрипта; два
  скрипта с разными id не мешают друг другу.
- **Файлы**: `src/browser/dom-events.ts`, `tests/browser-declarative.test.ts`.
- **Зависит от**: T47.

### Технические риски фазы 7 (осознанно принимаем)
- Модель «обработчик = строка кода» не даёт лямбд/функций-значений (их нет в языке) —
  это осознанный минимализм; при необходимости обработчики объявляются как процедуры
  модуля, а в привязке указывается вызов.
- Каждый `<one-script>` получает свой контекст; общий «глобальный» контекст страницы —
  отдельная задача, если понадобится.
- Нет сериализованной модели событий (`Событие` как объект) в минимальной версии.

## Явно вне scope (из task.md)

Работа с файлами, сеть, процессы, COM, Native API — **недоступны в браузере** и не
переносятся в первую очередь. В Node допускается точечная поддержка файлов (`Файл`,
`ЧтениеТекста`) как отдельная опциональная задача, но не в MVP.
