# OneScriptJS — статус (компактная сводка)

Движок OneScript (язык 1С/BSL), переписанный на TypeScript. Работает в Node и браузере.
Оригинал (эталон) — `reference/OneScript/` (C#), не коммитится.

## Состояние
- Перенос по старому плану **T1–T49 закрыт**: язык, стандартная библиотека, браузерная
  интеграция (DOM, события, декларативные `data-os-*`), xUnit-раннер и прогон эталонных тестов.
- `pnpm typecheck` ✓, `pnpm test` ✓ — **300 тестов** (43 файла Vitest).
- Текущая ветка — `feature/speckit_intergation`.
- Прогон `reference/OneScript/tests/*.os`: **18/66** файлов проходят целиком; ошибок разбора
  осталось 2 (`annotations.os`, `events.os`).
- Старый `docs/plan.md` удалён: незавершённые работы вынесены в спецификации `specs/`,
  реализация по ним ещё не начиналась.

## Архитектура (слои)
`src/lexer` (токены) → `src/parser` (AST + препроцессор `#`) → `src/runtime`
(`values`, `scope`+`Ref`, `context`, `interpreter` tree-walking, `enum`, `object`,
`type`, `error-info`, `runner`) → `src/stdlib` (global-context, collections, strings,
math, bitwise, json, types, enums, format) → `src/browser/onescript.ts` (`<one-script>`)
и `src/node/` (cli, context, files) → `src/testing` (xUnit-раннер).

Сборка: `dist/onescript.js` (браузер, IIFE), `dist/node/index.{js,cjs,d.ts}` (библиотека),
`dist/cli.mjs` (CLI).

## Что реализовано
- Язык: переменные, `если/иначеесли/иначе`, циклы (`Для`/`Пока`/`Для Каждого`,
  `Прервать`/`Продолжить`), процедуры/функции (`Знач`/по ссылке), исключения,
  `Перейти`/метки, аннотации, тернарный `?()`, `Новый`, препроцессор `#`.
- Структура модуля: `#Использовать` → `Перем` → методы → исполняемый код; локальные
  `Перем` — в начале метода. Объявления после кода и вложенные методы — ошибка разбора
  (как в `DefaultBslParser`). Контекст операторов тоже проверяется: `Возврат` — только в
  методе (в функции со значением, в процедуре без), `Прервать`/`Продолжить` — только в
  цикле, `ВызватьИсключение;` — только в блоке `Исключение`.
- Импорт файлов: `#Использовать "<файл>"` — модули-синглтоны с экспортными
  членами и классы (`ПриСозданииОбъекта`, `Новый`), кеш на `run()` и защита от
  циклов; Node читает через fs, браузер — через fetch по URL. Работает и из
  `ЗагрузитьСценарийИзСтроки` (относительно имени/текущего сценария).
- Значения/типы: числа, строки, булево, даты, `Null`/`Неопределено`, `Тип`/`ТипЗнч`,
  перечисления (`НаправлениеПоиска`, `СтатусСообщения`, `ХешФункция`, `ЦветКонсоли`,
  `КодировкаТекста`, `СпециальнаяПапка`, `ТипДиска`, `НаправлениеСортировки`,
  `СпособКодированияСтроки`) и `Символы`.
- Коллекции: `Массив` (многомерный), `Структура`, `Соответствие` (+ фиксированные),
  `СписокЗначений`, `ТаблицаЗначений`, `ДеревоЗначений`.
- Двоичные данные: `БуферДвоичныхДанных`, `ДвоичныеДанные` (hex/Base64/строка, BOM).
- Система: `СистемнаяИнформация`, `УникальныйИдентификатор`, переменные среды, `ПустаяСтрока`.
- `РегулярноеВыражение` (совпадения/группы/имена в нумерации .NET).
- `ГенераторСлучайныхЧисел` (диапазон uint32, воспроизводимость по seed).
- Сценарии: `ЗагрузитьСценарийИзСтроки`, `ЗагрузитьСценарий` (файл, Node), `ТекущийСценарий`, `СтартовыйСценарий` (тип `Сценарий`).
- `Pow` в decimal-точности 1С (29 значащих цифр для целой степени).
- Валидация смещений `ПобитовыйСдвиг*`; методы тест-контекста
  (`ПодробныеОписанияОшибок`, `ИмяВременногоФайла`, `ТестПровален`, `ПроверитьТип`).
- Динамическое исполнение: `Выполнить` (оператор) и `Вычислить` (функция) в текущей области
  видимости; `1/0` → «Деление на ноль»; переменная `Для … По …` после цикла = «по + 1»;
  `НСтр` извлекает язык из `ru='…';en='…'`.
- Браузер (Фаза 7): объект `Документ`, события DOM из BSL (`Элемент.НаСобытие(Имя, Код)`,
  объект `Событие`), декларативные `data-os-*` — только в браузерной сборке,
  `src/stdlib` остаётся Node-совместимым.
- Лексер: многострочные литералы с продолжением `|`.
- stdlib: `Сообщить` (со статусом), строковые, математические, поразрядные (uint32),
  JSON, `Формат` (число/дата), файловые (Node: `ЧтениеТекста`/`ЗаписьТекста`/`ОбъединитьПути`),
  `asserts` (`Ожидаем.Что(…).Равно(…)` + сравнения/`ЭтоНе`/`ИмеетДлину`/`Существует`/`Содержит`),
  динамический `Новый(Тип, …)`, двоичные данные (`БуферДвоичныхДанных`, `ДвоичныеДанные`,
  hex/Base64/строка).
- Парсер: `Перем a, b, c;` (с `Экспорт`), пропущенные аргументы `f(,23)`,
  конкатенация смежных строк `"a" "b"`, `ВызватьИсключение;` (перевыброс),
  конец блока как терминатор оператора без `;`, ключевые литералы как имена свойств
  (`Структура.Истина`), пустые операторы `;;`.
- Тестирование: xUnit-раннер `runTests` (`ЮнитТестирование` с `Проверить*`).

## Спецификации — работы в `specs/`

| Спека | Тема | Состояние |
|---|---|---|
| `001-bsl-event-handlers` | BSL-события: `ДобавитьОбработчик`/`УдалитьОбработчик`, `ВызватьСобытие`, `ЭтотОбъект` | spec + plan + tasks, реализация отложена |
| `002-nested-annotations` | Вложенные и именованные аннотации (парсер) | spec |
| `003-date-precision` | Точность и арифметика дат 1С (1/10000 с) | spec |
| `004-script-attach` | `ПодключитьСценарий` / `ЗагрузитьСценарий` из файла | spec; `ЗагрузитьСценарий` (US3) реализован |
| `005-system-settings` | `config.os`: `ОбновитьНастройкиСистемы` / `ПолучитьЗначениеСистемнойНастройки` | spec |
| `006-dynamic-names` | Разрешение имён в `Выполнить`/`Вычислить` («Неизвестный символ») | spec |
| `007-browser-playwright` | Приёмка в реальном браузере (Playwright) | spec |
| `008-use-directive` | `#Использовать "<файл>"`: модули и классы из файлов | реализовано |

Для незавершённых спек следующий шаг — `/speckit-plan` или `/speckit-tasks` в её каталоге; `008-use-directive` реализована.

## Известные пробелы
- `annotations.os` — после спеки 002 перестанет падать на разборе, но чтение аннотаций
  требует `Рефлектор` (вне scope 002).
- `events.os` — требует 001 (события) и 004 (`ПодключитьСценарий`, самоподключение файла).
- `#Использовать` (спека 008) импортирует только файлы: поиск библиотек по имени
  (`lib.config`, версии, `OSCRIPT_LIB`) не поддерживается; `#Использовать asserts` остаётся
  no-op. `ЗагрузитьСценарийИзСтроки` резолвит импорты (Node — с чтением с диска, браузер —
  только из предзагруженных источников).
- `eval.os`: `ТестДолжен_ПроверитьРаботоспособностьВПодключенныхСценариях` требует
  `#Использовать`/библиотеки (спека 008 покрывает импорт файлов; поиск библиотек по имени
  остаётся вне scope), остальные — 004 (`ЗагрузитьСценарий` реализован) и
  Node-контекст (`ОбъединитьПути`).
- `date-behavior.os` — заблокирован JSON/XML-подсистемами (`ЗаписьJSON`/`ЧтениеJSON` как
  объекты, `XMLСтрока`, `ФорматДатыJSON`), часовыми поясами и `ЗначениеЗаполнено` (вне 003).
- Вне старого плана и спецификаций (нужны отдельные спеки): `ТекстовыйДокумент`,
  `ЧасовойПояс`, `ХешированиеДанных`, `КвалификаторыЧисла`/`КвалификаторыСтроки`,
  `ЗначениеЗаполнено`, `ПолучитьИмяВременногоФайла`; объектные `ЗаписьJSON`/`ЧтениеJSON`
  (сейчас функции с одним аргументом); `Формат`: `ЧГ` с кастомными размерами, `ДП`/`ДД`.
- Сеть/HTTP, процессы, COM, XML — вне scope первой очереди (по `task.md`).
