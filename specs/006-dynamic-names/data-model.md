# Data Model: Разрешение имён в `Выполнить` и `Вычислить`

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-11-23

## Сущности

### 1. Динамический фрагмент (DynamicFragment)

Разобранный текст `Выполнить`/`Вычислить`, исполняемый как единица. Ошибка проверки
отменяет весь фрагмент.

| Поле | Тип | Описание |
|---|---|---|
| `program` | `Program` (AST) | Результат `parse(tokenize(text))`; для `Вычислить` — обёртка `сообщить(<выражение>);` |
| `kind` | `'execute' \| 'eval'` | Оператор или функция |
| `moduleVars` | `Set<string>` (lowercase) | `Перем` верхнего уровня — известны всему фрагменту |
| `moduleMethods` | `Set<string>` (lowercase) | методы верхнего уровня — известны всему фрагменту |
| `executable` | `Statement[]` | операторы верхнего уровня без `Перем`/методов |

Жизненный цикл фрагмента:

```text
parse ──► collect (moduleVars/moduleMethods) ──► check (AST-проход) ──► register
   │                                                    │                  │
   └─ ошибка разбора ──► BslRuntimeError                └─ «Неизвестный   └─ методы → ctx.methods,
      (как сейчас)                                         символ: X» ──►    Перем → dynamicScope
                                                           BslRuntimeError
                                                                              │
                                                       declareFrameLocals ◄───┘
                                                    (слоты кадра фрагмента)
                                                              │
                                                          execute
```

Инвариант: **до** `execute` не исполнено ни одной инструкции (FR-004); мутация
`ctx.methods`/`ctx.methodScopes` происходит только после успешной проверки. Слоты
локалей кадра (`declareFrameLocals` через `collectFrameLocals`) создаются после проверки
и до `execute`, поэтому присваивание видимой локали меняет её, а не создаёт тень.

### 2. Слоты локалей кадра (FrameLocals)

Локальные имена кадра, материализуемые до исполнения его тела: `collectFrameLocals`
собирает их по AST, `declareFrameLocals` создаёт слоты в области кадра. Эталон выделяет
слоты всех локалей на компиляции (`ExtractCompilerContext` → `_currentFrame.Locals`),
поэтому динамический код видит их как `Неопределено` ещё до присваивания.

| Поле | Тип | Описание |
|---|---|---|
| `declared` | `string[]` | явные `Перем` кадра — локальные, могут затенять внешние имена |
| `assigned` | `string[]` | имена, которым в кадре присваивают значение (`Assignment` по `Identifier`, переменные `Для`/`Для Каждого`), включая присваивания в ветках/циклах/`Попытка` |

Правило материализации: `declared` объявляются всегда; `assigned` — только если имя не
видно из внешних областей (иначе это запись в переменную модуля/вызывающего).

### 3. Окружение разрешения имён (NameEnvironment)

Снимок того, что видно фрагменту на момент исполнения.

| Поле | Тип | Источник |
|---|---|---|
| `scope` | `Scope` | область вызывающего кода (цепочка до `moduleScope`) |
| `methods` | `ReadonlyMap<string, MethodDeclaration>` | `ctx.methods` — методы модуля и ранее исполненных фрагментов |
| `env` | `RuntimeEnvironment` | глобальные функции/значения (stdlib, DOM/Node-оболочки) |

Проверяемые предикаты:

- `readable(name)` = `known.has(name)` ∨ `scope.findBinding(name)` ∨ `env.resolveGlobal(name) ≠ undefined` ∨ `env.hasGlobal(name)` ∨ `name ∈ {ЭтотОбъект, ThisObject}`;
- `callable(name)` = `moduleMethods.has(name)` ∨ `methods.has(name)` ∨ `name ∈ {Вычислить, ОписаниеОшибки, ИнформацияОбОшибке, ВызватьСобытие, Eval, ErrorDescription, ErrorInfo, RaiseEvent}` ∨ `env.hasFunction?.(name) === true` ∨ `env.hasFunction` отсутствует (непроверяемо — решает runtime).

### 4. Состояние проверки (KnownNames)

Изменяемое в текстовом порядке множество имён, объявленных в текущем тексте.

| Поле | Тип | Правило |
|---|---|---|
| `known` | `Set<string>` (lowercase) | стартует с `moduleVars`; пополняется присваиваниями, `Перем`, переменными циклов; для тела метода — с `moduleVars` + параметров |
| `moduleMethods` | `Set<string>` | методы верхнего уровня фрагмента (для тел методов и верхнего уровня одинаково) |

### 5. Ошибка неразрешённого имени (UnresolvedSymbol)

| Поле | Значение |
|---|---|
| Класс в BSL | обычное исключение исполнения (`BslRuntimeError` после оборачивания) |
| Текст | `Неизвестный символ: <имя>` (имя — как в исходнике) |
| Момент | до исполнения фрагмента |
| Перехват | `Попытка`; `ОписаниеОшибки()`/`ИнформацияОбОшибке().Описание` содержат текст |
| Побочные эффекты | нулевые: ни вывод, ни изменения переменных вызывающего |

## Правила обхода AST (текстовый порядок)

| Узел | Действие |
|---|---|
| `Identifier` (чтение) | `readable(name)` иначе ошибка |
| `Assignment` | сначала проверить `value`, затем `target`: `Identifier` → добавить в `known`; `Member`/`Index` → проверить `object`/`index`, ничего не объявлять |
| `CallExpression` | если `callee` — `Identifier`: `callable(name)` иначе ошибка; иначе проверить `callee`; затем аргументы слева направо |
| `Binary`/`Unary`/`Ternary`/`Await` | обход операндов в порядке исходника |
| `MemberExpression` | только `object` (имя свойства не символ) |
| `IndexExpression` | `object`, `index` |
| `NewObjectExpression` | аргументы; имя типа не проверяется (R9) |
| `ExpressionStatement` | выражение |
| `IfStatement` | условие → `thenBranch` → `elseBranch` (присваивания ветки видны дальше) |
| `ForLoop` | `from` → объявить переменную → `to` → тело (как `VisitForLoop` в эталоне) |
| `ForEachLoop` | `collection` → объявить переменную → тело |
| `WhileLoop` | условие → тело |
| `TryExceptStatement` | `tryBody` → `exceptBody` |
| `ReturnStatement`/`RaiseStatement` | значение, если есть |
| `ExecuteStatement` | выражение-строка (содержимое строки проверяется при её исполнении) |
| `AddHandler`/`RemoveHandler` | `eventSource`, `eventName`, `handlerTarget`, `handlerMethod` |
| `Break`/`Continue`/`Label`/`Goto` | ничего |
| `VariableDeclaration` | добавить имена в `known` (верхний уровень уже в `moduleVars`) |
| `MethodDeclaration` | отдельная проверка тела: `known = moduleVars ∪ параметры`, модульные методы = `moduleMethods`; `Перем`/присваивания тела пополняют локальное `known` |

## Матрица видимости (наблюдаемое поведение)

| Что читается | В динамическом фрагменте | В статическом коде (без изменений) |
|---|---|---|
| лексическая локаль/параметр/модульная переменная вызывающего (присвоенная) | видно, изменяемо | видно |
| лексическая локаль вызывающего ещё без значения (`Перем` без присваивания, присваивание позже) | видно как `Неопределено`, изменяемо (слот кадра) | видно как `Неопределено` |
| имя, присвоенное в этом же фрагменте раньше | видно | — |
| имя, присвоенное в этом же фрагменте позже | ошибка «Неизвестный символ» | — |
| имя, присвоенное в другом (завершённом) фрагменте | ошибка | — |
| имя, присвоенное в динамике, из метода модуля | не видно | — |
| неизвестное имя | ошибка «Неизвестный символ» | `Неопределено` (FR-008) |
| глобальная функция/значение/метод модуля | видно | видно |

## Трассировка требований

| Требование | Где обеспечивается |
|---|---|
| FR-001 | R2: `scope.findBinding` по цепочке вызывающего; присваивание через `setVariable` меняет существующую привязку |
| FR-002 | `execDynamic` создаёт дочернюю `Scope`; `known` сбрасывается на фрагмент |
| FR-003 | проверка `Identifier`/`CallExpression` → `Неизвестный символ: X` |
| FR-004 | проход до `execute`; мутации `ctx` — после проверки |
| FR-005 | последовательный обход; `Если`/циклы/`Попытка` в текстовом порядке |
| FR-006 | вложенный фрагмент получает `scope` объемлющего (цепочка `Scope`) |
| FR-007 | `BslRuntimeError` ловится `Попытка`, текст в `ОписаниеОшибки` |
| FR-008 | проверка вызывается только из динамических путей; статический `eval` не тронут |
| FR-009/SC-001 | перенос эталонного сценария в тест + прогон `eval.os` |
| FR-010/SC-004 | полный `pnpm test`; существующие тесты `tests/eval.test.ts` остаются зелёными |
