# Contract: Разрешение имён в динамическом коде

**Feature**: [006-dynamic-names](../spec.md) | **Plan**: [plan.md](../plan.md) | **Date**: 2026-11-23

Контракт — наблюдаемое поведение языка; он не описывает внутренние классы. Источник
истины для реализации и тестов.

## C1. Область видимости

`Выполнить`/`Вычислить` исполняются в области вызывающего кода:

- видят и **меняют** его локальные переменные, параметры и модульные переменные;
- локальные переменные вызывающего видны и тогда, когда объявлены, но ещё не присвоены:
  значение — `Неопределено`; присваивание из динамики меняет локаль вызывающего;
- видят методы модуля и глобальные функции/значения;
- имена, впервые присвоенные в тексте, локальны для одного исполнения: не видны после
  него, в следующем фрагменте и в вызываемых методах модуля;
- вложенный фрагмент видит имена объемлющего фрагмента, в том числе до присваивания —
  как `Неопределено`.

## C2. Ошибка неразрешённого имени

| Свойство | Значение |
|---|---|
| Когда | до исполнения фрагмента; ни одна инструкция не выполнена |
| Текст | `Неизвестный символ: <имя>` (имя в регистре исходника, без кавычек) |
| Класс | обычная ошибка исполнения |
| Перехват | `Попытка`; `ОписаниеОшибки()` и `ИнформацияОбОшибке().Описание` содержат текст |
| Побочные эффекты | ноль (нет вывода, нет изменений переменных вызывающего) |

Разрешённость вычисляется текстово-последовательно: имя, присвоенное раньше в тексте
(в том числе внутри `Если`), разрешено для последующих чтений; чтение до присваивания —
ошибка. `Перем` и методы фрагмента известны всему фрагменту независимо от позиции.

## C3. Статический код не меняется

Вне `Выполнить`/`Вычислить` чтение незаданной переменной по-прежнему даёт `Неопределено`.
Это осознанное расхождение с эталоном (FR-008), фиксируется в `docs/status.md` и тестом.

## C4. Примеры (исполняемые тесты)

```bsl
// видимость и изменение
Рез = 1;
Выполнить "Рез = Рез + 3";          // Рез = 4

// изоляция
Выполнить "Т = 5";
Выполнить "Сообщить(Т)";            // ошибка: Неизвестный символ: Т

// ошибка до исполнения
Попытка
  Выполнить "Сообщить(""до""); Х = Х + 1;";  // «до» НЕ печатается
Исключение
  Сообщить(ОписаниеОшибки());       // Неизвестный символ: Х
КонецПопытки;

// последовательное разрешение
Выполнить "Новое = 5; Новое = Новое + 8";    // успешно

// присваивание в ветке
Выполнить "Если Истина Тогда В = 1; КонецЕсли; Сообщить(В);";  // 1

// статика
Сообщить(Строка(НетТакой));         // Неопределено (без изменений)
```

## C5. Границы контракта

- Не проверяются: имя типа в `Новый <Тип>` (остаётся ошибкой исполнения «Тип … не
  найден»), имена свойств/методов после точки, содержимое строковых выражений до их
  собственного исполнения.
- Директивы `#` в динамическом тексте не обрабатываются (прежний `shortcut`).
- Кеш разбора не вводится; каждое исполнение разбирает и проверяет текст заново.

## C6. Совместимость окружений

Проверка глобальных **функций** использует опциональный
`RuntimeEnvironment.hasFunction(name)`. Окружение без этого метода (кастомные
`RuntimeEnvironment`) сохраняет прежнее поведение: неизвестный вызов доходит до
`env.call` и падает там. Стандартные `GlobalContext` (Node/browser/tests) предоставляют
предикат, поэтому для них контракт C2 действует полностью.
