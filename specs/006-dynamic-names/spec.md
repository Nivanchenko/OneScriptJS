# Feature Specification: Разрешение имён в `Выполнить` и `Вычислить`

**Feature Branch**: `feature/speckit_intergation`

**Created**: 2026-11-11

**Status**: Draft

**Input**: Остаток T43 из `docs/plan.md`. Разбор показал: `ТестДолжен_ПроверитьВызовыВыполнитьСПопытками` падает не из-за проброса исключения, а из-за отсутствия правила разрешения имён в динамическом коде: `Рез = Рез + 8` молча создаёт локаль вместо ошибки «Неизвестный символ».

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Динамический код видит окружение вызывающего (Priority: P1)

Разработчик выполняет код через `Выполнить`/`Вычислить` и ожидает, что он видит и меняет
переменные и параметры вызвавшего метода и модульные переменные — но не «протекает» в
соседние вызовы.

**Why this priority**: Это базовое правило области видимости `Выполнить`; без него динамический
код либо не видит нужных имён, либо загрязняет чужие области.

**Independent Test**: Метод с локальной `Рез` исполняет `Выполнить "Рез = Рез + 3"` — значение
меняется; после `Выполнить "Т = 5"` имя `Т` не видно ни в следующем `Выполнить`, ни в
вызываемом методе.

**Acceptance Scenarios**:

1. **Given** у вызывающего метода есть локальная переменная `Рез = 1`, **When** `Выполнить "Рез = Рез + 3"`, **Then** `Рез` равна 4 после исполнения.
2. **Given** `Выполнить "Т = 5"`, **When** затем выполняется `Выполнить "Сообщить(Т)"`, **Then** ошибка «Неизвестный символ: Т» (имя не протекло).
3. **Given** `Выполнить "Т = 5"`, **When** вызывается метод модуля, читающий `Т`, **Then** имя ему недоступно.
4. **Given** вложенный `Выполнить` внутри `Исключение`, **When** он читает локальную переменную объемлющего исполнения, **Then** она видна.

---

### User Story 2 - Неразрешённое имя — ошибка до исполнения (Priority: P2)

Разработчик опечатался в имени внутри динамического текста. Движок обязан сообщить
«Неизвестный символ: <имя>» и не исполнять текст частично: ни одна строка не должна дать
побочного эффекта до ошибки.

**Why this priority**: Сейчас опечатка превращается в `Неопределено`/конкатенацию и даёт неверный
результат без диагностики — это скрытый источник багов; ошибка должна быть видимой и ловиться
`Попытка`.

**Independent Test**: `Выполнить "Сообщить(""до""); Х = Х + 1;"` при отсутствующем `Х` не печатает
«до» и бросает ошибку, которую ловит охватывающая `Попытка`.

**Acceptance Scenarios**:

1. **Given** имени нет в окружении и оно не присваивалось раньше в этом же тексте, **When** выполняется `Выполнить`, **Then** ошибка «Неизвестный символ: <имя>».
2. **Given** охватывающая `Попытка`, **When** ошибка возникает, **Then** она перехватывается, и `ОписаниеОшибки` содержит имя символа.
3. **Given** текст `Рез = 5; Рез = Рез + 8`, **When** `Рез` не существует до вызова, **Then** исполнение успешно (последовательное разрешение).
4. **Given** ошибка в тексте, **When** он исполняется, **Then** ни одна инструкция текста не выполнена (включая `Сообщить` и внутренние `Попытка`).
5. **Given** имя присваивается в ветке `Если`, **When** далее оно читается, **Then** имя считается разрешённым (текстовое правило), значение может быть `Неопределено`.

### Edge Cases

- Правило применяется к `Выполнить` и `Вычислить`, включая вложенные вызовы.
- Переменные, впервые появившиеся в динамическом тексте, живут только до конца этого исполнения.
- Порядок важен: `Рез = Рез + 8` без присваивания раньше — ошибка; `Рез = 5; Рез = Рез + 8` — допустимо.
- Статический (нединамический) код сохраняет текущее поведение: чтение незаданной переменной даёт `Неопределено` (зафиксировано существующим тестом; расхождение с эталоном документируется).
- Модульные переменные и параметры метода разрешаются всегда; новое имя не считается модульным.
- Ошибка возникает до исполнения: побочные эффекты (вывод, изменение переменных вызывающего) — нулевые.
- Ошибка должна быть обычной ошибкой исполнения: перехватывается `Попытка`, видна в `ОписаниеОшибки`/`ИнформацияОбОшибке`.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `Выполнить` и `Вычислить` MUST исполняться в окружении вызывающего: видеть и менять его локальные переменные/параметры и модульные переменные.
- **FR-002**: Имена, впервые присвоенные внутри динамического текста, MUST быть локальны для одного исполнения: не видны после него, в следующем динамическом тексте и в вызываемых методах.
- **FR-003**: Чтение имени, которое нельзя разрешить (нет в окружении и не присвоено раньше в том же тексте), MUST приводить к ошибке «Неизвестный символ: <имя>».
- **FR-004**: Ошибка неразрешённого имени MUST возникать до исполнения текста: ни одна инструкция не выполняется, побочных эффектов нет.
- **FR-005**: Разрешение имён MUST быть последовательным/текстовым: имя, присвоенное раньше в тексте (в том числе внутри `Если`), считается разрешённым для последующих чтений.
- **FR-006**: Вложенные `Выполнить`/`Вычислить` MUST видеть локальные имена объемлющего динамического исполнения и вызывающего метода.
- **FR-007**: Ошибка MUST быть перехватываемой `Попытка` и отражаться в `ОписаниеОшибки`/`ИнформацияОбОшибке`.
- **FR-008**: Статический код MUST сохранить текущее поведение (чтение незаданной переменной — `Неопределено`); расхождение с эталоном документируется в `docs/status.md`.
- **FR-009**: Эталонный тест `ТестДолжен_ПроверитьВызовыВыполнитьСПопытками` MUST давать результат `0134567+`.
- **FR-010**: Изменение MUST не ломать существующие сценарии: общий набор тестов остаётся зелёным.

### Key Entities

- **Окружение динамического исполнения**: видимые имена (модуль + вызывающий метод) и локальные имена текущего текста.
- **Разрешённость имени**: вычисляется текстово до исполнения; определяет ошибку «Неизвестный символ».
- **Динамический батч**: разобранный текст `Выполнить`/`Вычислить`, исполняемый как единица (ошибка отменяет весь батч).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `ТестДолжен_ПроверитьВызовыВыполнитьСПопытками` даёт `0134567+` (сейчас `013457+`).
- **SC-002**: 100% сценариев разрешения имён из Edge Cases проходят: видимость вызывающего, отсутствие утечек, последовательное разрешение, вложенность.
- **SC-003**: Ошибка неразрешённого имени: побочных эффектов до ошибки — ноль, текст содержит имя символа, ошибка ловится `Попытка` (3 из 3).
- **SC-004**: Регрессии: существующий набор тестов остаётся зелёным, число регрессий — ноль; `Вычислить` работает как раньше в разрешённых сценариях.
- **SC-005**: Полный `eval.os` остаётся частично красным по причинам вне scope: 3 теста требуют файловой загрузки (спека 004) и `ОбъединитьПути` в Node-контексте; это фиксируется, а не скрывается.

## Assumptions

- Правило применяется только к динамическому коду; статический код остаётся с текущей мягкой семантикой (`Неопределено`) — осознанное и документированное отклонение от эталона, иначе ломается существующий тест `interpreter.test.ts`.
- Модель «разрешение до исполнения» реализуется текстово-последовательным проходом по разобранному тексту, без отдельной таблицы символов времени компиляции.
- Динамический код по-прежнему не проходит препроцессор (`shortcut` из T43): директивы `#` в `Выполнить` не интерпретируются.
- Кэширование разобранных батчей не вводится: каждое исполнение создаёт свои локали.
- Полный зелёный `eval.os` не является приёмкой этой фичи: часть тестов зависит от файловой загрузки (004) и Node-контекста.
