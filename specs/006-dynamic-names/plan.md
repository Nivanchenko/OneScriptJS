# Implementation Plan: Разрешение имён в `Выполнить` и `Вычислить`

**Branch**: `feature/006-dynamic-names` | **Date**: 2026-11-23 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/006-dynamic-names/spec.md`

## Summary

Динамический код (`Выполнить`/`Вычислить`) должен разрешать имена **до исполнения**, как
эталонный C#-OneScript, который компилирует фрагмент в отдельный модуль и только потом
исполняет: неразрешённое имя — ошибка «Неизвестный символ: <имя>», побочных эффектов нет.
Сейчас наш интерпретатор исполняет фрагмент как есть, а неизвестное имя молча даёт
`Неопределено` — из-за этого `Рез = Рез + 8` в `eval.os` создаёт локаль вместо ошибки и
`ТестДолжен_ПроверитьВызовыВыполнитьСПопытками` даёт `013457+` вместо `0134567+`.

Решение: добавить в `src/runtime` отдельный предварительный проход по разобранному AST
фрагмента (`dynamic-names.ts`), который последовательно-текстово вычисляет, какие имена
разрешены (область вызывающего + модульные `Перем`/методы + глобальные значения/функции +
объявленное ранее в самом фрагменте), и бросает ошибку до первой исполненной инструкции.
Статический код не меняется (FR-008), `Вычислить` и вложенные динамические вызовы
покрываются тем же проходом. Новых зависимостей нет; ядро остаётся браузеро-совместимым.

## Implementation Strategy

### Фаза A — Контракт и падающие тесты (TDD)

- `tests/eval-dynamic-names.test.ts`: сценарии US1 (видимость/изоляция/вложенность) и US2
  (ошибка до исполнения, `Попытка`, последовательное разрешение, `Если`-ветка, `Вычислить`,
  неизвестная функция); перенос `ТестДолжен_ПроверитьВызовыВыполнитьСПопытками` с ожиданием
  `0134567+`; тест FR-008 (статика — `Неопределено`).
- Тесты должны падать по ожидаемой причине (нет ошибки «Неизвестный символ»).

### Фаза B — Предварительный проход (`src/runtime/dynamic-names.ts`)

- Собрать «модульные» имена фрагмента: `Перем` и методы верхнего уровня (известны всему
  фрагменту, как таблица символов модуля в эталоне).
- Последовательный обход операторов: `Identifier`-чтение проверяется на разрешимость;
  присваивание сначала проверяет правую часть, затем объявляет имя; `Если`/циклы/
  `Попытка` обходятся в текстовом порядке; переменные циклов объявляются в точке цикла;
  `Выполнить`-оператор проверяет только выражение-строку (содержимое строки — при
  исполнении).
- Вызовы: `Идентификатор(...)` проверяется как метод модуля/фрагмента, встроенная функция
  интерпретатора или глобальная функция (`env.hasFunction`); `Новый <Тип>` и имена
  свойств не проверяются (вне scope спеки).
- Тела методов, объявленных во фрагменте, проверяются отдельно: известны окружение
  вызывающего + модульные имена фрагмента + параметры/локальные; присваивания фрагмента
  верхнего уровня методам фрагмента не видны (как module-scope в эталоне).
- Ошибка — `Error('Неизвестный символ: <имя>')`; интерпретатор оборачивает её в
  `BslRuntimeError`, как ошибку разбора.

### Фаза C — Подключение в интерпретатор

- `execDynamic`: разбор → проверка (до мутации `ctx.methods`) → регистрация методов и
  `Перем` → исполнение; `evalDynamicExpression`: разбор обёртки → проверка выражения → eval.
- `RuntimeEnvironment.hasFunction?` (опционально) + реализация в `GlobalContext`; окружения
  без предиката сохраняют прежнее поведение (непроверяемые вызовы доходят до runtime).
- Кеша разбора нет; слоты локалей кадра материализует `declareFrameLocals` (через
  `collectFrameLocals`) после проверки имён и до исполнения — как `_currentFrame.Locals`
  эталона. Это не «предобъявление имён в области»: проход по-прежнему разрешает имена в
  текстовом порядке, а слот получает значение `Неопределено`.

### Фаза D — Документация и приёмка

- `docs/reference.md`: динамика разрешает имена до исполнения, неизвестное имя — ошибка;
  статика по-прежнему `Неопределено` (осознанное расхождение).
- `docs/status.md`: спека 006 → реализовано; `eval.os` — цель зелёная, остаются 3 теста
  вне scope (Node-контекст/`ОбъединитьПути`, спека 004).
- Приёмка: `pnpm typecheck && pnpm test`, `pnpm build:browser`, прогон `eval.os`
  (`scripts/run-reference-tests.mjs`) — фиксация `0134567+`; браузерный тест script-блока.

### Фаза E — Исправление после ревью

- 8 регрессионных тестов на лексические локальные вызывающего (`tests/eval-dynamic-names.test.ts`):
  `Перем` без присваивания, присваивание позже, присваивание только в неисполненной ветке,
  модульный уровень, изменение локали из динамики, `Вычислить`, счётчик `Для`, вложенный фрагмент.
- `collectFrameLocals`/`declareFrameLocals` при входе в кадр: `run` (`moduleScope`),
  `invokeMethodGen`/`invokeAsyncGen`/`invokeMethodWithOutputsGen`/`callMethod` (`localScope`),
  `execDynamic` (`dynamicScope`) — после проверки имён и до исполнения; R4 переведён в Resolved.
- NIT-порядок счётчика `Для` в проходе проверки: переменная цикла объявляется до проверки
  выражения `По` (как `VisitForLoop` в эталоне).
- Синхронизация документации: R4 → Resolved, R8 (непроверенный паритет), 885 тестов / 87 файлов.
