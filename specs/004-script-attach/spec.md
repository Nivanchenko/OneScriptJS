# Feature Specification: Подключение сценариев как типов и загрузка из файла

**Feature Branch**: `feature/speckit_intergation`

**Created**: 2026-11-11

**Status**: Частично реализовано: US3 (`ЗагрузитьСценарий`) работает; US1–US2 (`ПодключитьСценарий`) — Draft

**Input**: Остаток T39 из `docs/plan.md`: `ПодключитьСценарий` (регистрация типа) и `ЗагрузитьСценарий` (из файла). Нужны файловые подсистемы; T43 фиксирует зависимость 3 тестов `eval.os`.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Файл BSL регистрируется как тип и создаётся через `Новый` (Priority: P1)

Разработчик подключает файл как тип (`ПодключитьСценарий("Класс.os", "Класс")`) и создаёт
экземпляры через `Новый Класс(…)`. Тело модуля исполняется при создании экземпляра, а наружу
видны только экспортные методы и переменные.

**Why this priority**: Это ядро задачи: без регистрации типа и создания экземпляра подключение
бесполезно, и `events.os` (самоподключаемый файл) не запускается.

**Independent Test**: Подключить файл с неэкспортной процедурой `ПриСозданииОбъекта`, создать
`Новый Класс`, вызвать экспортный метод и прочитать экспортную переменную — всё работает;
неэкспортный метод снаружи недоступен.

**Acceptance Scenarios**:

1. **Given** файл ещё не подключён, **When** выполняется `ПодключитьСценарий(путь, "Класс")`, **Then** возвращается `Неопределено`, и тело модуля не исполняется.
2. **Given** тип подключён, **When** создаётся `Новый Класс()`, **Then** тело модуля исполняется один раз и вызывается конструктор (если объявлен).
3. **Given** экземпляр создан, **When** вызывается экспортный метод или читается/пишется экспортная переменная, **Then** операция выполняется; неэкспортные члены снаружи недоступны.
4. **Given** экземпляр создан, **When** применяется `ТипЗнч`/`Строка`, **Then** отражается имя подключённого типа.

---

### User Story 2 - Конструктор и ошибки создания (Priority: P2)

Разработчик объявляет `ПриСозданииОбъекта` с параметрами и значениями по умолчанию. Движок
передаёт аргументы `Новый` в конструктор и сообщает понятные ошибки при неверной арности.

**Why this priority**: Без конструктора и его диагностики создание объектов с параметрами будет
непредсказуемым, а ошибки — неотличимыми от «тип не найден».

**Independent Test**: Класс с конструктором `(А, Б = 2)` создаётся как `Новый Класс(1)` и
`Новый Класс(1, 3)`; неверные варианты дают три разных сообщения из эталона.

**Acceptance Scenarios**:

1. **Given** конструктор с необязательным параметром, **When** `Новый Класс(1)`, **Then** параметр получает значение по умолчанию.
2. **Given** у модуля нет конструктора, **When** `Новый Класс(1)`, **Then** ошибка «Конструктор не определен, но переданы параметры конструктора.».
3. **Given** конструктор требует больше параметров, **When** передано меньше, **Then** ошибка с числом необходимых и переданных параметров.

---

### User Story 3 - Загрузка сценария из файла исполняет его сразу (Priority: P3)

Разработчик загружает файл как объект-сценарий (`ЗагрузитьСценарий(путь)`): тело исполняется
немедленно, вызовы дают независимые экземпляры, а `ТекущийСценарий` внутри загруженного модуля
указывает на загруженный файл.

**Why this priority**: Это второй самостоятельный сценарий T39 и условие трёх тестов `eval.os`;
но без US1 он не даёт новых возможностей.

**Independent Test**: Два вызова `ЗагрузитьСценарий(один файл)` дают независимые состояния;
`ТекущийСценарий().Источник` внутри модуля и его методов — путь загруженного файла.

**Acceptance Scenarios**:

1. **Given** файл существует, **When** вызывается `ЗагрузитьСценарий(путь)`, **Then** тело модуля исполнено и возвращён объект-сценарий с экспортными методами.
2. **Given** один и тот же файл, **When** загружен дважды, **Then** состояния экземпляров независимы.
3. **Given** внутри загруженного модуля вызывается `ТекущийСценарий()`, **Then** `.Источник`/`.Каталог` указывают на загруженный файл, а не на вызывающий.

### Edge Cases

- Повторное `ПодключитьСценарий` того же файла и имени — no-op; другое содержимое под тем же именем — ошибка «Type «X» already registered».
- Коллизия имени с уже существующим типом (включая встроенный) — ошибка регистрации.
- Несуществующий файл — ошибка ввода-вывода, а не «тип не найден».
- Относительный путь разрешается от текущего рабочего каталога процесса, а не от каталога скрипта.
- Ошибка синтаксиса подключаемого/загружаемого файла: для подключения — «Ошибка компиляции подключаемого сценария: …»; для загрузки — с префиксом «Ошибка компиляции…».
- Ошибка рантайма внутри загруженного модуля пробрасывается без обёртки.
- Имя типа проверяется как BSL-идентификатор.
- В браузере файловые функции недоступны (`Неизвестная функция`), `ЗагрузитьСценарийИзСтроки` продолжает работать.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `ПодключитьСценарий(Путь, ИмяТипа)` / `AttachScript` MUST читать файл, компилировать модуль и регистрировать тип без исполнения тела; возвращать `Неопределено`.
- **FR-002**: `Новый <Тип>`/`Новый("<Тип>")` MUST создавать экземпляр зарегистрированного типа, исполняя тело модуля один раз, затем конструктор.
- **FR-003**: Повторная регистрация того же типа с тем же текстом MUST быть no-op; с другим текстом или при коллизии с существующим типом MUST быть ошибкой.
- **FR-004**: Снаружи экземпляра MUST быть доступны только экспортные методы и переменные; внутри модуля — все.
- **FR-005**: Конструктор `ПриСозданииОбъекта`/`OnObjectCreate` MUST вызываться с подстановкой значений по умолчанию и MUST работать даже без модификатора `Экспорт`.
- **FR-006**: Ошибки конструктора MUST различать: нет конструктора, но переданы аргументы; не хватает обязательных параметров; обязательный параметр после необязательного не передан.
- **FR-007**: `ЗагрузитьСценарий(Путь)` / `LoadScript` MUST читать файл, компилировать и исполнять тело модуля немедленно, возвращая независимый объект-сценарий.
- **FR-008**: `ТекущийСценарий()` MUST отражать исполняемый в данный момент модуль (включая загруженные и вызываемые из них методы), а не последний запущенный.
- **FR-009**: Ошибки компиляции MUST быть обёрнуты в сообщение «Ошибка компиляции…», ошибки ввода-вывода и рантайма MUST пробрасываться без обёртки.
- **FR-010**: Файловые функции MUST регистрироваться только в Node-контексте; ядро и браузерная сборка MUST NOT импортировать Node-модули, а в браузере файловые функции MUST отсутствовать.
- **FR-011**: Движок MUST поддерживать `Перем Имя Экспорт` (экспорт модульной переменной) как предусловие видимости экземпляра.
- **FR-012**: Изменение MUST не ломать существующие сценарии: общий набор тестов остаётся зелёным, `ЗагрузитьСценарийИзСтроки` и `ТекущийСценарий` для обычных модулей работают как раньше.

### Key Entities

- **Подключённый тип**: имя (BSL-идентификатор), исходник, фабрика создания экземпляра.
- **Экземпляр сценария**: собственные данные модуля, экспортная поверхность (методы/переменные) и имя типа.
- **Загруженный сценарий**: экземпляр, созданный и исполненный из файла; связан с путём (`Источник`/`Каталог`).
- **Реестр типов**: соответствие «имя типа → фабрика», общее для рантайма; проверяет коллизии.
- **Стек текущего сценария**: какой модуль исполняется сейчас — для `ТекущийСценарий`.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Сценарий «подключить файл → создать экземпляр → вызвать экспортный метод» проходит; тело модуля исполняется ровно один раз на экземпляр.
- **SC-002**: Три сообщения об ошибках конструктора совпадают с эталонными символ-в-символ (3 из 3).
- **SC-003**: Видимость экспорта проверена в обе стороны: 100% неэкспортных методов/переменных недоступны снаружи, 100% экспортных — доступны.
- **SC-004**: В `eval.os` проходят тесты, требующие загрузки из файла (`issue712`, `evalDifferentThis`) — не менее 2 из 3 оставшихся; `eval-in-libraries` остаётся вне scope (`#Использовать`).
- **SC-005**: `events.os` после реализации T44 (спека 001) доходит до исполнения; самоподключение файла не зацикливается.
- **SC-006**: Регрессии: существующий набор тестов остаётся зелёным, число регрессий — ноль; браузерная сборка собирается.

## Assumptions

- Второй аргумент `ЗагрузитьСценарий` (`Структура` дополнительных переменных) не входит в первую версию: передача отклоняется понятной ошибкой. Это задокументированное расхождение.
- `#Использовать` в этой спеке — no-op; импорт файлов реализован отдельной спекой
  `008-use-directive`. `eval-in-libraries` по-прежнему вне scope.
- Рефлексия (`Рефлектор`) не требуется для T39 и вне scope.
- Кэширования загруженных файлов нет: каждый вызов создаёт независимый экземпляр.
- Путь разрешается относительно cwd процесса; BOM/`#!` в начале файла не ломают разбор.
- Существующий `ТекущийСценарий`, возвращающий объект с `Источник`/`Каталог`/`Имя`, сохраняется как совместимое надмножество эталонного `ИнформацияОСценарии`.
