# Data Model: Фоновые задания BSL

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Contract**: [contracts/background-jobs-contract.md](contracts/background-jobs-contract.md)

Модель делится на три уровня: async-рантайм (как исполнение приостанавливается), сущности
заданий (что видит BSL) и реестр (порядок/вытеснение). Имена и состояния сверены с
`reference/OneScript/src/OneScript.StandardLibrary/Tasks/`.

## 1. Async-рантайм

### 1.1 `MaybePromise<T>` и генераторный контракт

```ts
type MaybePromise<T> = T | Promise<T>;
type BslGenerator<T> = Generator<Promise<unknown>, T, unknown>;

function drive<T>(gen: BslGenerator<T>, opts?: DriveOptions): MaybePromise<T>;
// 1-й gen.next(): done === true  → значение синхронно (sync fast-path);
// иначе → Promise: resolve → gen.next(value), reject → gen.throw(error).

function* yieldMaybe<T>(value: MaybePromise<T>): BslGenerator<T>;
```

Инварианты:

- **I-A1**: синхронный скрипт (нет `yield`) не создаёт Promise; `run()` возвращает
  `undefined` — сохраняется контракт старых тестов.
- **I-A2**: `gen.throw(error)` доставляет исключение в точку `yield`; BSL-`Попытка` и
  `catch` сигналов (`ReturnSignal`, `BreakSignal`, `ContinueSignal`, `GotoSignal`) ловят его
  так же, как в синхронном интерпретаторе.
- **I-A3**: `drive` не глотает ошибки: необработанное исключение отклоняет возвращённый
  Promise.
- **I-A4**: `DriveOptions.slice` включает срез квантов (только задания и, при желании,
  async-исполнение основного скрипта); `DriveOptions.beforeStep/afterStep` позволяют
  выставить/восстановить `env.currentInterpreter`.

### 1.2 Точки приостановки

| Источник | Контракт | Поведение |
|---|---|---|
| `Приостановить(мс)` / `Sleep` | `sleep(ms): Promise<void>` | `setTimeout`; `< 0` — ошибка аргумента, `0` — уступить управление |
| `ОжидатьЗавершения(Таймаут)` | `waitWithTimeout(completion, ms)` | ждёт `completion` задания; возвращает `Булево` |
| `ОжидатьВсе` / `ОжидатьЛюбое` | ожидание набора `completion` | `Promise.all`/`Promise.race` + таймаут |
| `ОжидатьЗавершенияЗадач` | ожидание снимка реестра | после ожидания проверяет аварийные |
| Квант задания | `yieldToHost()` | макротаск (`MessageChannel`, fallback `setTimeout(0)`) раз в ~10 мс |

### 1.3 Контексты исполнения

| Контекст | Состав | Общее с основным |
|---|---|---|
| Основной скрипт | `Ctx` интерпретатора модуля, `currentJob = null` | — |
| Задание (fork) | свой `Ctx`: `currentJob = task`, `currentError = null` | `methods`, `moduleScope`, `moduleVars`, `exportedVars`, `ownerObject` |

**I-A5**: fork не копирует модульные данные — изменения из задания видны основному скрипту
после ожидания (общая память); блокировок нет.

## 2. Фоновое задание (`ФоновоеЗадание` / `BackgroundTask`)

### 2.1 Поля

| Поле | Тип | Источник | Инвариант |
|---|---|---|---|
| `id` | `string` (UUID) | `BslUniqueIdentifier` | уникален в менеджере; создаётся при `Выполнить` |
| `taskId` | `number` | внутренний счётчик | ключ реестра, уникален и возрастает |
| `target` | `BslObject` | аргумент `Объект` | BSL-объект; валидируется при создании |
| `methodName` | `string` | аргумент `ИмяМетода` | непустой; проверяется наличие/экспорт при создании |
| `parameters` | `Value[] \| undefined` | копия `Параметры` | `Неопределено`, если не переданы |
| `state` | `BackgroundJobState` | — | см. 2.2 |
| `result` | `Value` | возврат метода-функции | по умолчанию `Неопределено`; заполняется только при успехе |
| `error` | `BslErrorInfo \| undefined` | перехваченная ошибка | только при `ЗавершеноАварийно` |
| `completion` | `Promise<void>` | внутренний | **никогда не reject-ится** |
| `fork` | `Interpreter` | создаётся при старте | общий `moduleCtx`, свой `Ctx` |

### 2.2 Состояния и переходы

```text
                  start (следующий квант/микротаск)
НеВыполнялось ─────────────────────────────────▶ Активно
                                                   │
                                    успех          │          ошибка
                                                   ▼            ▼
                                              Завершено   ЗавершеноАварийно
```

**I-B1**: переходы только вперёд; `НеВыполнялось → …` необратим.
**I-B2**: `Активно` не означает «прямо сейчас исполняется» — задание может ждать
(`Приостановить`, ожидание другого задания); в кооперативной модели оно «активно», пока не
завершилось.
**I-B3**: `Результат` для процедуры = `Неопределено`; `Результат` функции заполняется только
при `Завершено`.
**I-B4**: `ИнформацияОбОшибке` заполняется только при `ЗавершеноАварийно`;
`ОжидатьЗавершения` при аварии возвращает `Истина` и не бросает.
**I-B5**: `ОжидатьЗавершения` уже завершённого задания — `Истина` немедленно.
**I-B6**: порядок запуска заданий — FIFO; старт «в ближайшем доступном кванте», сразу после
`Выполнить` состояние может быть `НеВыполнялось` или `Активно` (не гарантируется).

## 3. Реестр заданий

### 3.1 Структура

- односвязный список записей: **активные в порядке запуска**, затем **завершённые в порядке
  завершения**;
- индекс `taskId → запись`; ёмкость `capacity = 1000`;
- при завершении запись переносится в конец, `firstCompleted` указывает на самую раннюю
  завершённую;
- при `count > capacity` вытесняются завершённые с начала очереди завершённых.

### 3.2 Инварианты

**I-C1**: активные задания не вытесняются никогда, даже если их больше `capacity`.
**I-C2**: вытеснение не влияет на саму задачу — скрипт, держащий ссылку на `ФоновоеЗадание`,
продолжает читать свойства и ждать.
**I-C3**: `Очистить` очищает реестр, но не отменяет задания; завершение очищенного задания не
возвращает его в реестр.
**I-C4**: `ПолучитьФоновыеЗадания()` возвращает снимок в порядке 3.1; фильтр не меняет
порядок.
**I-C5**: `ПолучитьТекущее()` вне задания → `Неопределено`; внутри — ровно это задание;
после `Очистить` изнутри задания → `Неопределено`.
**I-C6**: `ОжидатьЗавершенияЗадач` работает со снимком: после успеха удаляет задания снимка
из реестра; при ошибках — бросает и **не** удаляет их.

### 3.3 Фильтр `ПолучитьФоновыеЗадания(Фильтр)`

| Ключ (RU / EN) | Допустимое значение | Сравнение |
|---|---|---|
| `Состояние` / `State` | `BslEnumValue` типа `СостояниеФоновогоЗадания` | по типу и имени; не-enum → фильтр игнорируется |
| `ИмяМетода` / `MethodName` | строка | без учёта регистра (осознанное расхождение с эталоном) |
| `Объект` / `Object` | BSL-объект | по `equals`/ссылке |
| `УникальныйИдентификатор` / `UUID` | `УникальныйИдентификатор` | по значению UUID |

**I-C7**: неизвестные ключи фильтра игнорируются (как в эталоне).

## 4. Перечисление

| Тип | Значения |
|---|---|
| `СостояниеФоновогоЗадания` / `BackgroundJobState` | `НеВыполнялось`/`NotRunned`, `Активно`/`Active`, `Завершено`/`Completed`, `ЗавершеноАварийно`/`Failed` |

Регистрируется как системное перечисление (`BslEnumNamespace`) рядом с остальными в
`src/stdlib/enums.ts`; значения сравниваются по `typeName`+`name`.

## 5. Публичная BSL-поверхность (сводка типов)

| Объект | Вид | Члены (RU / EN) |
|---|---|---|
| `ФоновыеЗадания` / `BackgroundJobs` | глобальное значение-менеджер | `Выполнить`/`Execute`, `Очистить`/`Clear`, `ОжидатьВсе`/`WaitAll`, `ОжидатьЛюбое`/`WaitAny`, `ОжидатьЗавершенияЗадач`/`WaitCompletionOfTasks`, `ПолучитьФоновыеЗадания`/`GetBackgroundJobs`, `ПолучитьТекущее`/`GetCurrent` |
| `ФоновоеЗадание` / `BackgroundTask` | объект-результат | свойства `УникальныйИдентификатор`/`UUID`, `ИмяМетода`/`MethodName`, `Объект`/`Object`, `Состояние`/`State`, `Параметры`/`Parameters`, `Результат`/`Result`, `ИнформацияОбОшибке`/`ExceptionInfo`; метод `ОжидатьЗавершения`/`Wait` |
| `МенеджерФоновыхЗаданий` | тип-имя | конструктор недоступен (`Новый` → ошибка) |
| `Приостановить` / `Sleep` | глобальная функция | `(Миллисекунды)` → `Неопределено`; приостанавливает текущий поток |

## 6. Правила валидации и ошибок

| Ситуация | Результат |
|---|---|
| `Объект` не BSL-объект | исключение при `Выполнить` |
| `ИмяМетода` пустое / не найдено / не экспортное | исключение при `Выполнить` |
| `Параметры` не `Массив` и не `Неопределено` | исключение при `Выполнить` |
| `Таймаут < 0` | исключение о неверном аргументе |
| элемент массива ожидания — не `ФоновоеЗадание` | исключение о неверном типе |
| пустой массив в `ОжидатьЛюбое` | исключение (как `Task.WaitAny` в .NET) |
| пустой массив в `ОжидатьВсе` | `Истина` |
| таймаут истёк | `Ложь` / `-1`; задания продолжают работу |
| ошибка внутри задания | `ЗавершеноАварийно` + `ИнформацияОбОшибке`; не бросается в ожидание |
| `ОжидатьЗавершенияЗадач` при авариях | исключение с перечнем аварийных заданий |
