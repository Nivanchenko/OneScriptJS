# Contract: Фоновые задания BSL

**Feature**: [spec.md](../spec.md) | **Plan**: [plan.md](../plan.md) | **Data model**: [data-model.md](../data-model.md)

Контракт фиксирует пользовательскую поверхность BSL (имена, аргументы, возвраты, ошибки) и
минимальный контракт рантайма, на который она опирается. Имена и семантика — из
`reference/OneScript/src/OneScript.StandardLibrary/Tasks/` (`BackgroundTasksManager.cs`,
`BackgroundTask.cs`, `TaskStateEnum.cs`) и глобальной `Приостановить` из
`StandardGlobalContext.cs`.

## 1. Глобальное значение `ФоновыеЗадания` / `BackgroundJobs`

Единственный экземпляр `МенеджерФоновыхЗаданий` / `BackgroundTasksManager`.
`Новый МенеджерФоновыхЗаданий` НЕ поддерживается: тип не регистрируется как конструктор
(ошибка «Тип … не найден» / «создание невозможно»).

### 1.1 `Выполнить` / `Execute`

| Позиция | Имя | Тип | По умолчанию | Примечание |
|---|---|---|---|---|
| 1 | `Объект` / `Object` | BSL-объект | — | цель вызова; не объект → ошибка |
| 2 | `ИмяМетода` / `MethodName` | строка | — | должен существовать и быть экспортным |
| 3 | `Параметры` / `Parameters` | `Массив` \| `Неопределено` | `Неопределено` | копируется на момент вызова |
| 4 | `Длительное` / `LongRunning` | булево | `Ложь` | принимается для совместимости; в кооперативной модели не влияет |

Возврат: `ФоновоеЗадание`. Побочные эффекты: задание ставится в реестр и планируется к
исполнению; текущий логический поток продолжает работу, не дожидаясь его.

Ошибки (синхронно, до постановки в реестр): цель не BSL-объект; метод не найден/не
экспортный; `Параметры` не `Массив` и не `Неопределено`; `Длительное` не приводится к
булеву — как обычно в BSL-приведении (`toBoolean`).

### 1.2 `Очистить` / `Clear`

Без аргументов, без результата. Удаляет все задания из реестра. Не отменяет исполняющиеся
задания; их завершение не возвращает их в реестр.

### 1.3 `ОжидатьВсе` / `WaitAll`

| Позиция | Имя | Тип | По умолчанию |
|---|---|---|---|
| 1 | `Задания` / `Tasks` | `Массив` из `ФоновоеЗадание` | — |
| 2 | `Таймаут` / `Timeout` | число (мс) | `0` |

Возврат: `Булево` — `Истина`, если все задания завершились; `Ложь`, если истёк таймаут.
Аварийные задания не являются ошибкой ожидания. `Таймаут < 0` → ошибка. Элемент не
`ФоновоеЗадание` → ошибка типа. Пустой массив → `Истина`.

### 1.4 `ОжидатьЛюбое` / `WaitAny`

Аргументы как у `ОжидатьВсе`. Возврат: `Число` — индекс первого завершившегося элемента
массива; `-1`, если истёк таймаут. Пустой массив → ошибка.

### 1.5 `ОжидатьЗавершенияЗадач` / `WaitCompletionOfTasks`

Без аргументов. Ждёт завершения снимка текущих заданий реестра (активных на момент вызова).
Если среди них есть `ЗавершеноАварийно` — бросает исключение; в описании перечислены
аварийные задания. При успехе удаляет задания снимка из реестра. При ошибке задания из
реестра не удаляются.

### 1.6 `ПолучитьФоновыеЗадания` / `GetBackgroundJobs`

| Позиция | Имя | Тип | По умолчанию |
|---|---|---|---|
| 1 | `Фильтр` / `Filter` | `Структура` \| `Неопределено` | `Неопределено` |

Возврат: `Массив` заданий. Порядок: активные в порядке запуска, затем завершённые в порядке
завершения. Ключи фильтра: `Состояние`/`State`, `ИмяМетода`/`MethodName` (без учёта
регистра), `Объект`/`Object`, `УникальныйИдентификатор`/`UUID`; неизвестные ключи
игнорируются; значение неверного типа для известного ключа игнорируется.

### 1.7 `ПолучитьТекущее` / `GetCurrent`

Без аргументов. Возврат: `ФоновоеЗадание`, если вызов происходит внутри задания этого
менеджера, иначе `Неопределено`. В основном потоке и после `Очистить` — `Неопределено`.

## 2. `ФоновоеЗадание` / `BackgroundTask`

### 2.1 Свойства (только чтение)

| RU | EN | Тип | Значение |
|---|---|---|---|
| `УникальныйИдентификатор` | `UUID` | `УникальныйИдентификатор` | создаётся при `Выполнить`, уникален |
| `ИмяМетода` | `MethodName` | строка | как передано в `Выполнить` |
| `Объект` | `Object` | BSL-объект | цель задания |
| `Состояние` | `State` | `СостояниеФоновогоЗадания` | текущее состояние |
| `Параметры` | `Parameters` | `Массив` \| `Неопределено` | копия на момент создания |
| `Результат` | `Result` | значение | результат функции; `Неопределено` для процедуры и до успеха |
| `ИнформацияОбОшибке` | `ExceptionInfo` | `ИнформацияОбОшибке` \| `Неопределено` | заполняется при аварии |

### 2.2 `ОжидатьЗавершения` / `Wait`

| Позиция | Имя | Тип | По умолчанию |
|---|---|---|---|
| 1 | `Таймаут` / `Timeout` | число (мс) | `0` (= бесконечно) |

Возврат: `Булево` — `Истина`, если задание завершилось; `Ложь`, если истёк таймаут.
`Таймаут < 0` → ошибка. Ошибка задания не пробрасывается — она в `ИнформацияОбОшибке`.
Повторный вызов допустим.

## 3. Перечисление `СостояниеФоновогоЗадания` / `BackgroundJobState`

| RU | EN |
|---|---|
| `НеВыполнялось` | `NotRunned` |
| `Активно` | `Active` |
| `Завершено` | `Completed` |
| `ЗавершеноАварийно` | `Failed` |

## 4. Глобальная `Приостановить` / `Sleep`

`Приостановить(Миллисекунды)` / `Sleep(Milliseconds)` → `Неопределено`.
Приостанавливает текущий логический поток (задание или основной скрипт), не блокируя
хост/страницу. `0` — уступить управление; `< 0` — ошибка аргумента; нечисловое значение —
стандартное BSL-приведение к числу.

## 5. Контракт async-рантайма (внутренний, для реализации)

```ts
type MaybePromise<T> = T | Promise<T>;

interface DriveOptions {
  slice?: boolean;                       // срез квантов (задания)
  beforeStep?(): void;                   // выставить env.currentInterpreter
  afterStep?(): void;                    // восстановить
}

// Синхронный быстрый путь: value, если генератор завершился до первого yield.
function drive<T>(gen: Generator<Promise<unknown>, T, unknown>, opts?: DriveOptions): MaybePromise<T>;

// Точки входа рантайма возвращают MaybePromise:
// Interpreter.run/invokeMethod/callExportedMethod/invokeMethodWithOutputs/executeInModule
// Runner.run, runScript, runTests, ModuleLoader.importAll
// BslObject.callMethod/getProp/getIndex/setIndex, EventProcessor.raise

interface RuntimeEnvironment {
  call(name: string, args: Value[]): MaybePromise<Value>;
  construct(typeName: string, args: Value[]): MaybePromise<Value>;
  resolveGlobal?(name: string): Value | undefined;   // остаётся синхронным
  events?: EventProcessor;
  flushAsync?(): MaybePromise<void>;                 // дождаться активных заданий
}
```

**Инварианты**: `drive` сохраняет синхронность при отсутствии `yield`; исключения
доставляются в точку `yield` (`gen.throw`) и ловятся BSL-`Попытка`; `completion` задания
никогда не reject-ится; `flushAsync` ждёт все активные задания и не бросает из-за их ошибок.

## 6. Контракт хостов

| Хост | Поведение |
|---|---|
| `<one-script>` | дожидается `run()` (Promise) и только потом вызывает `scheduleDeclarativeBinding`; ошибки — `console.error` |
| CLI | `await run(...)`; вывод `Сообщить` — по мере выполнения; код возврата при ошибке — 1 |
| `runScript`/`run` (JS API) | возвращает `undefined` для синхронного скрипта и Promise для скрипта с ожиданиями; вызывающий код может `await` оба варианта |
| DOM-обработчики (`data-os-*`, `НаСобытие`) | fire-and-forget: результат не ожидается, ошибка ловится и пишется в `console.error` |
