# Quickstart: проверка фоновых заданий BSL

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Contract**: [contracts/background-jobs-contract.md](contracts/background-jobs-contract.md)

## Prerequisites

- Node.js >= 20 (в DSH — системный node из nvm, см. `AGENTS.md` §6).
- Установленные зависимости: `pnpm install`.
- Браузерные проверки — `happy-dom`; ручная приёмка — `examples/jobs.html` + `pnpm dev`.

## 1. Автоматические проверки

```bash
export PATH="$HOME/.nvm/versions/node/v24.22.0/bin:$PATH"
pnpm typecheck
pnpm test
pnpm build:browser
```

| Проверка | Ожидание |
|---|---|
| `pnpm typecheck` | без ошибок |
| `pnpm test` | зелёные прежние 56 файлов/435 тестов (не переписаны) + новые `tests/background-jobs*.test.ts`, `tests/async-runtime.test.ts`, `tests/browser-jobs.test.ts` |
| `pnpm build:browser` | `dist/onescript.js` собирается; `grep -c "node:" dist/onescript.js` → `0` |
| `pnpm test -- background-jobs` | все сценарии заданий зелёные |

## 2. Ключевые сценарии (что именно проверяется)

### 2.1 Одиночное задание и неблокирующее ожидание

```bsl
Функция Посчитать(Знач Начало, Знач Конец) Экспорт
    Приостановить(100);
    Сумма = 0;
    Для Сч = Начало По Конец Цикл
        Сумма = Сумма + Сч;
    КонецЦикла;
    Возврат Сумма;
КонецФункции

Параметры = Новый Массив;
Параметры.Добавить(1);
Параметры.Добавить(100);

Задание = ФоновыеЗадания.Выполнить(ЭтотОбъект, "Посчитать", Параметры);
Сообщить("после запуска");
Сообщить(Задание.Состояние);
Задание.ОжидатьЗавершения();
Сообщить(Задание.Состояние);
Сообщить(Задание.Результат);   // 5050
```

Ожидание: «после запуска» выводится раньше результата; состояния — активное/`НеВыполнялось`
до ожидания и `Завершено` после; результат `5050`. В браузере во время `Приостановить`
страница обрабатывает таймеры.

### 2.2 Ошибка в задании

```bsl
Процедура Упасть() Экспорт
    Приостановить(20);
    ВызватьИсключение "Я ошибка в коде";
КонецПроцедуры

Задание = ФоновыеЗадания.Выполнить(ЭтотОбъект, "Упасть");
Ожидание = Задание.ОжидатьЗавершения();          // Истина, не бросает
Сообщить(Задание.Состояние);                     // ЗавершеноАварийно
Сообщить(Задание.ИнформацияОбОшибке.Описание);   // Я ошибка в коде
```

### 2.3 Групповые ожидания и таймауты

```bsl
Медленное = ФоновыеЗадания.Выполнить(ЭтотОбъект, "Посчитать", Параметры);
Все = ФоновыеЗадания.ПолучитьФоновыеЗадания();
Сообщить(ФоновыеЗадания.ОжидатьВсе(Все, 10));   // Ложь — таймаут
Сообщить(ФоновыеЗадания.ОжидатьЛюбое(Все, 10)); // -1 — таймаут
ФоновыеЗадания.ОжидатьВсе(Все);                 // Истина
Завершенные = ФоновыеЗадания.ПолучитьФоновыеЗадания(Новый Структура("Состояние", СостояниеФоновогоЗадания.Завершено));
```

### 2.4 Реестр, фильтры, `Очистить`

- `ПолучитьФоновыеЗадания()` — активные в порядке запуска, затем завершённые в порядке
  завершения.
- Фильтры по `Состояние`, `ИмяМетода` (без учёта регистра), `Объект`,
  `УникальныйИдентификатор`; неизвестные ключи игнорируются.
- `Очистить()` убирает задания из реестра, но не отменяет их; `ПолучитьТекущее()` изнутри
  очищенного задания → `Неопределено`.
- Больше 1000 завершённых: вытеснено самое раннее завершившееся; активные не вытесняются.

### 2.5 Обратная совместимость

- Скрипт без `Приостановить`/заданий по-прежнему исполняется синхронно: `run(...)` —
  `undefined`, `Сообщить` выводит сразу.
- Все 435 прежних тестов проходят без правок.
- `run(...)` со скриптом, где есть `Приостановить`, возвращает Promise; `await` над
  результатом корректен в обоих случаях.

## 3. Ручная проверка в браузере (основная среда)

1. Собрать бандл: `pnpm build:browser`, поднять dev-сервер: `pnpm dev`.
2. Открыть `examples/jobs.html`. В консоли должны появиться: маркер до результата, смена
   состояний, результат задания.
3. Открыть `examples/hello.html` — прежний приёмочный сценарий не сломан.
4. Пока задание «спит», страница должна реагировать на клики/таймеры (проверяется вручную и
   в `tests/browser-jobs.test.ts`).

## 4. Проверка Node/CLI

```bash
pnpm build
echo 'Приостановить(50); Сообщить("ok");' > /tmp/jobs.os
node dist/cli.mjs /tmp/jobs.os        # ожидается "ok", код возврата 0
```

## 5. Сверка с эталоном

`reference/OneScript/tests/tasks.os` — 25 тестов, из них в объём входят сценарии без
настоящих потоков: создание задания, состояния, результат, ошибка и `ИнформацияОбОшибке`,
`ОжидатьВсе`/`ОжидатьЛюбое`/`ОжидатьЗавершения`, поиск по фильтрам, `Очистить`, порядок и
вытеснение, `ПолучитьТекущее`, событие внутри задания. Сценарии `ТекущийПоток`,
`БлокировкаРесурса`, изоляция данных потоков, обработчики завершения потока, файловые
ресурсы и дочерние процессы исключены — они требуют настоящих потоков и зафиксированы в
[spec.md](spec.md) (Assumptions) и `docs/status.md`.
