# Contract: директива #Использовать — модули и классы

**Date**: 2026-11-11 | **Plan**: [plan.md](../plan.md) | **Spec**: [spec.md](../spec.md)

Контракт описывает наблюдаемую поверхность: синтаксис директивы, правила путей, что видно
снаружи модуля/класса, точки входа и тексты ошибок. Реализация — `src/parser/preprocessor.ts`,
`src/runtime/modules.ts`, `src/runtime/module-objects.ts`, `src/node/module-source.ts`,
`src/browser/module-source.ts`.

## 1. Синтаксис директивы

```text
use-directive := '#' ('Использовать' | 'Use') WS quoted-path [WS '//' comment] EOL

quoted-path   := '"' (any-char | '""')* '"'      // '""' — экранированная кавычка
```

| Форма | Поведение |
|---|---|
| `#Использовать "lib/Модуль.os"` | импорт файла |
| `#Use "lib/Module.os"` | то же (английский алиас) |
| `#Использовать asserts` | не импорт: имя встроенной библиотеки, no-op (совместимость) |
| `#Использовать "a.os" // комментарий` | импорт `a.os`; комментарий отбрасывается |
| `#Использовать ""` | ошибка «пустой путь» |

Директива — строчная, до конца строки. Регистр имён директив не важен. Несколько директив
в файле разрешаются в порядке появления **до** исполнения первой строки кода файла.
Директивы в неактивных ветках `#Если` не исполняются и не загружаются.

Директива допустима только до первого `Перем`, объявления метода или исполняемого оператора
(в эталоне `#Использовать` — аннотация модуля). Директива после кода — ошибка §5.

## 2. Разрешение путей

| Среда | Относительный путь | Путь от `/` |
|---|---|---|
| Node | от каталога импортирующего файла (`path.resolve(dirname(importer), p)`) | абсолютный путь файловой системы (`/home/user/lib.os`, `C:\lib.os`) |
| Браузер | URL относительно адреса документа: `new URL(p, document.baseURI)` | корень origin сервера: `new URL(p, base)` от `/` |

- Канонический ключ кеша — результат разрешения, нормализованный (`..`, `.`); разные
  написания одного файла дают одну запись.
- Имя для доступа — последний сегмент пути без `.os` (или без последнего расширения),
  регистр сохраняется в сообщениях, сравнение — без учёта регистра.
- Имя обязано быть BSL-идентификатором; иначе — ошибка (§5).
- Расширение `.os` не подставляется автоматически.
- В браузере источник получается `fetch(url)`; не-2xx и сетевые ошибки — ошибка импорта.

## 3. Вид скрипта и поверхность

| Признак | Вид | Импорт | Создание |
|---|---|---|---|
| нет `ПриСозданииОбъекта`/`OnObjectCreate` | модуль | тело исполняется один раз при импорте | — (синглтон) |
| есть `ПриСозданииОбъекта`/`OnObjectCreate` | класс | тип регистрируется, тело не исполняется | `Новый Имя(…)`, тело на экземпляр, затем конструктор |

| Обращение | Модуль | Экземпляр класса |
|---|---|---|
| `Объект.ЭкспортнаяПеременная` | чтение/запись | чтение/запись |
| `Объект.ЭкспортныйМетод(...)` | вызов | вызов |
| `Объект.НеэкспортныйЧлен` | ошибка | ошибка |
| `Объект.ПриСозданииОбъекта(...)` | ошибка (вне класса) | ошибка (конструктор не вызывается снаружи) |
| `ИмяКласса.Метод` | — | ошибка: класс не модуль |
| `Новый ИмяМодуля` | ошибка: модуль не класс | — |
| `ТипЗнч(Экземпляр)` | — | имя класса |

Конструктор: обязательные параметры — без значения по умолчанию; необязательные —
`Параметр = <выражение>`; значения по умолчанию вычисляются в области модуля.

## 4. Точки входа

### 4.1 `run(source, env, options?)`

Публичная функция движка; обратная совместимость сохраняется.

| Поле `options` | Тип | Назначение |
|---|---|---|
| `path?` | `string` | путь исполняемого файла (как раньше) |
| `basePath?` | `string` | база для импортов главного файла (по умолчанию `path ?? ''`) |
| `modules?` | `Map<string, string>` | предзагруженные исходники: канонический путь → текст |
| `resolve?` | `(path: string, importer: string) => string` | платформенное разрешение пути |
| `loadSource?` | `(path: string) => string` | ленивое чтение источника; Node-контекст задаёт его по умолчанию (fs/UTF-8/BOM) |

Если в исходнике есть импорт файла, а `modules` пуст/не содержит ключ — ошибка §5
(«файл не найден»). `runScript(source)` (без базового пути и карты) файлы не грузит.

### 4.2 Node

- `collectModuleSources(entryPath, entrySource): Map<string, string>` — синхронный обход
  дерева импортов (`node:fs`), нормализация `node:path`, UTF-8, снятие BOM.
- CLI (`oscript файл.os`) читает входной файл, вызывает `collectModuleSources` и передаёт
  карту, `resolve` и `loadSource` (`fs.readFileSync`) в `run`.
- Модуль `src/node/module-source.ts`; ядро остаётся без `node:*`.

### 4.3 Браузер

- `preloadModuleSources(entrySource, entryUrl): Promise<Map<string, string>>` — обход
  дерева импортов через `fetch`, URL-резолвинг `new URL(p, importerUrl)`, снятие BOM.
- `<one-script>`: `connectedCallback` выполняет асинхронную предзагрузку (`document.baseURI`
  — база), затем синхронный `run({ modules, resolve })`. Ошибка предзагрузки/исполнения
  выводится через `console.error`; страница продолжает работать.
- Модуль `src/browser/module-source.ts`; `dist/onescript.js` остаётся единым IIFE-бандлом.

### 4.4 `ЗагрузитьСценарийИзСтроки(Текст, Имя?)`

- Импорты динамического исходника резолвятся загрузчиком текущего `run()` относительно
  каталога `Имя`; если `Имя` не задано — относительно пути текущего сценария.
- Кеш импорта общий с главным сценарием: модуль, импортированный из обоих, загружается один раз.
- Node: отсутствующие в карте файлы читаются через `loadSource`; `createNodeGlobalContext` задаёт его по умолчанию (`fs` + UTF-8 + снятие BOM).
- Браузер: runtime-`fetch` невозможен в синхронном движке, поэтому импорт работает только
  для уже предзагруженных страницей источников; иначе — ошибка «Файл не найден».

## 5. Диагностика

| Ситуация | Сообщение |
|---|---|
| Файл не найден (Node/ядро) | `Файл не найден: '<разрешённый путь>' (директива #Использовать, строка <n>)` |
| HTTP/сеть (браузер) | `Не удалось загрузить '<url>': HTTP <status> (директива #Использовать, строка <n>)` |
| Ошибка разбора/лексеров во вложенном файле | `Ошибка в импортируемом файле '<путь>': <сообщение>` |
| Имя файла не идентификатор | `Имя импортируемого файла '<имя>' не является допустимым идентификатором: '<путь>'` |
| Путь пустой | `Пустой путь в директиве #Использовать (строка <n>)` |
| Директива после кода | `Директива #Использовать должна быть расположена в начале модуля (строка <n>)` |
| Конфликт имени | `Имя '<имя>' уже занято (файл '<путь>')` |
| Ранний доступ при цикле | `Модуль '<имя>' ещё загружается (циклический импорт)` |
| Нет свойства/метода (в т.ч. неэкспортного) | `Свойство '<имя>' не найдено у типа <тип>` / `Метод '<имя>' не найден у типа <тип>` |
| Класс использован как модуль | `Класс '<имя>' не является модулем; создайте экземпляр: Новый <имя>(...)` |
| Модуль создан через `Новый` | `Модуль '<имя>' не является классом; создание через Новый невозможно` |
| Неверная арность конструктора | `Параметры конструктора: необходимых параметров: <req>, передано параметров: <n>` |
| Контекст без реестра | `Импорт файлов не поддерживается текущим контекстом исполнения` |

Ошибка останавливает текущий скрипт; вложенная ошибка рантайма пробрасывается без обёртки.
Ошибка импорта удаляет запись кеша.

## 6. Кеш и циклы

- Кеш — на один `run()`; два запуска/два `<one-script>` независимы.
- Первый импорт файла создаёт запись `loading`, регистрирует имя, загружает зависимости,
  исполняет тело (модуль) или регистрирует тип (класс), затем `ready`.
- Повторный импорт — no-op (тот же синглтон/тот же тип).
- A↔B: второе обращение к A возвращает `loading`-запись, тело B продолжается; доступ
  B к членам A до завершения A — ошибка §5; после завершения оба доступны.
- Ошибка импорта удаляет запись; исполнение не продолжается.

## 7. Совместимость

- `#Использовать asserts` остаётся no-op; `Ожидаем`/`Expect` регистрируются как раньше.
- `ЗагрузитьСценарийИзСтроки` резолвит импорты по §4.4; `ЗагрузитьСценарий` (файл) остаётся
  в спеке 004. В браузере динамический импорт ограничен предзагруженными источниками.
- Существующие тесты (300) и `examples/hello.html` не меняют поведения.
