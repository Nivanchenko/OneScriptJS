# Feature Specification: Упрощённая директива #Использовать: модули и классы из файлов

**Feature Branch**: `008-use-directive`

**Created**: 2026-11-11

**Status**: Draft

**Input**: Упрощённая реализация директивы `#Использовать "<путь>.os"`: подключение одного
файла, два вида скриптов (модуль-синглтон и класс с конструктором `ПриСозданииОбъекта`),
экспортные методы и переменные, кеш рантайма, защита от повторной и циклической загрузки,
разрешение путей от текущего файла и от корня в Node и браузере.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Подключение модуля и обращение к его экспортной поверхности (Priority: P1)

Разработчик выносит часть кода в отдельный файл `НекийСкрипт.os`, объявляет там экспортные
переменные и экспортные процедуры/функции, а в главном скрипте пишет
`#Использовать "path/to/НекийСкрипт.os"`. После этого модуль доступен по имени файла без
расширения: можно читать и писать экспортные переменные (`НекийСкрипт.Поле = 123`) и вызывать
экспортные методы (`НекийСкрипт.Сложить(1, 2)`). Код модуля, написанный после объявлений методов,
выполняется в момент импорта, а не при каждом обращении.

**Why this priority**: Это минимально полезный срез: без модуля-синглтона подключение файлов
ничего не даёт, а именно модули составляют большинство переиспользуемых BSL-файлов.

**Independent Test**: Запустить главный скрипт, который импортирует модуль, вызывает его
экспортную функцию, читает и меняет экспортную переменную, и убедиться, что инициализация модуля
выполнилась один раз, а неэкспортные члены снаружи недоступны.

**Acceptance Scenarios**:

1. **Given** файл модуля с экспортными переменной и функцией, **When** главный скрипт содержит `#Использовать "<путь>"`, **Then** имя модуля (имя файла без `.os`) доступно в главном скрипте, и вызов `Модуль.Функция(...)` возвращает результат.
2. **Given** модуль подключён, **When** выполняется `Модуль.Поле = 123` и затем `Модуль.Поле`, **Then** запись и чтение экспортной переменной работают.
3. **Given** модуль содержит исполняемый код после объявлений методов, **When** он импортируется, **Then** этот код выполняется ровно один раз в момент импорта; повторное `#Использовать` того же файла не исполняет его снова, и доступно то же состояние модуля.
4. **Given** модуль подключён, **When** главный скрипт обращается к неэкспортной процедуре или переменной модуля, **Then** возникает ошибка «член не найден», а не тихий доступ к внутренностям.
5. **Given** страница браузера с `<one-script>`, **When** скрипт импортирует файл по относительному URL (рядом со страницей) или по пути от корня сервера, **Then** модуль загружается с сервера и работает так же, как в Node.

### User Story 2 - Класс с конструктором и независимыми экземплярами (Priority: P2)

Разработчик объявляет в файле процедуру `ПриСозданииОбъекта` с обязательными и необязательными
параметрами. Такой файл считается классом: он не является синглтоном, не доступен как модуль и
создаётся через `Новый НекийКласс(<аргументы>)`. Каждый экземпляр хранит собственное состояние,
полученное в конструкторе, а снаружи видны только экспортные методы и переменные экземпляра.

**Why this priority**: Классы нужны для объектного кода и повторного использования, но без
работающего импорта модулей их не на чем строить.

**Independent Test**: Подключить файл класса с конструктором `(Обязательный, Необязательный = "")`,
создать два экземпляра с разными аргументами, проверить их независимое состояние и то, что
необязательный параметр получает значение по умолчанию.

**Acceptance Scenarios**:

1. **Given** подключён файл с `ПриСозданииОбъекта`, **When** выполняется `Новый НекийКласс("Привет")`, **Then** создаётся экземпляр, конструктор получает аргумент, а экземпляр доступен через экспортные методы и переменные.
2. **Given** конструктор `(Обязательный, Необязательный = "")`, **When** создаётся `Новый НекийКласс("А")`, **Then** `НеОбязательный` получает значение по умолчанию; при `Новый НекийКласс("А", "Б")` — переданное значение.
3. **Given** класс подключён, **When** созданы два экземпляра, **Then** изменение экспортной переменной одного не меняет состояние другого.
4. **Given** класс с конструктором, **When** имя класса используется как модуль (`НекийКласс.Метод()`), **Then** возникает ошибка: класс доступен только через `Новый`.
5. **Given** модуль без `ПриСозданииОбъекта`, **When** выполняется `Новый Модуль`, **Then** возникает ошибка об отсутствии конструктора.
6. **Given** конструктор вызывается с меньшим числом аргументов, чем обязательных, **When** выполняется `Новый НекийКласс()`, **Then** ошибка называет число обязательных и переданных параметров.

### User Story 3 - Надёжная и однократная загрузка: кеш, повторные импорты, циклы (Priority: P3)

Разработчик подключает один и тот же файл из нескольких мест и сталкивается с взаимными
импортами (файл A импортирует B, а B — A). Движок загружает каждый файл не более одного раза за
время жизни рантайма, не зависает на циклах и разрешает один и тот же файл, записанный по-разному,
в одну запись кеша.

**Why this priority**: Без этого реальные проекты с общими модулями работают непредсказуемо:
повторная инициализация ломает состояние, а циклы приводят к зависанию или переполнению стека.

**Independent Test**: Импортировать один модуль двумя разными способами (разные написания пути и
повторная директива) и проверить, что его код выполнился один раз; затем запустить пару файлов с
взаимным импортом и убедиться, что выполнение завершается, а тело каждого файла исполнено один раз.

**Acceptance Scenarios**:

1. **Given** модуль уже импортирован, **When** другой файл импортирует его же по тому же пути в другом написании (`./m.os`, `sub/../m.os`), **Then** используется та же запись кеша, код модуля повторно не исполняется.
2. **Given** два файла импортируют друг друга, **When** выполняется запуск, **Then** загрузка завершается без зацикливания, тело каждого файла исполняется не более одного раза, а после завершения оба модуля доступны.
3. **Given** идёт циклическая загрузка, **When** код обращается к члену ещё не инициализированного модуля, **Then** возникает понятная ошибка с именем модуля, а не зависание и не тихий `Неопределено`.
4. **Given** в файле две директивы подряд до кода, **When** файл исполняется, **Then** оба импорта выполнены до первой строки исполняемого кода этого файла.
5. **Given** директива находится в неактивной ветке `#Если Ложь Тогда`, **When** файл исполняется, **Then** указанный в ней файл не загружается.

---

### Edge Cases

- `#Использовать asserts` без кавычек (имя встроенной библиотеки) продолжает работать как раньше: файл не ищется, стандартная библиотека доступна.
- Директива после объявлений или исполняемого кода: ошибка «Директива #Использовать должна быть расположена в начале модуля» с номером строки.
- Файл не найден по разрешённому пути: ошибка называет разрешённый путь и место директивы; исполнение главного скрипта прекращается.
- Имя файла не является допустимым BSL-идентификатором (`my-script.os`, `1Скрипт.os`): ошибка на этапе импорта, а не «модуль с недоступным именем».
- Два разных файла с одинаковым именем (`a/Модуль.os` и `b/Модуль.os`) подключены в одном рантайме: ошибка о конфликте имени модуля; то же — при совпадении с именем встроенного типа или глобальной функции.
- Синтаксическая ошибка в импортируемом файле: сообщение указывает путь импортируемого файла и строку, а не только главный скрипт.
- Неэкспортная процедура или переменная модуля/класса снаружи недоступна; экспортная доступна и на запись (переменная).
- Импорт класса не создаёт экземпляр: `ПриСозданииОбъекта` выполняется только при `Новый`.
- Класс, подключённый из двух файлов, остаётся одним типом; экземпляры независимы.
- Один и тот же файл, подключённый в двух разных рантаймах (два `<one-script>` или два отдельных запуска), загружается независимо: кеш принадлежит рантайму, а не процессу.
- В браузере сервер отвечает ошибкой (404/500) или сеть недоступна: ошибка называет URL и статус.
- Путь с `..` не выходит за разрешённую область в браузере: URL нормализуется как обычный URL страницы.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Движок MUST распознавать директиву `#Использовать "<путь>"` (и английский алиас `#Use`) как импорт ровно одного файла сценария и MUST NOT исполнять её как пользовательский код.
- **FR-002**: Директива без кавычек (`#Использовать asserts`) MUST трактоваться как имя встроенной библиотеки и оставаться no-op: поиск файла по такому имени не выполняется, существующее поведение стандартной библиотеки сохраняется.
- **FR-003**: Движок MUST определять вид импортируемого скрипта по наличию процедуры `ПриСозданииОбъекта` / `OnObjectCreate`: без неё — модуль, с ней — класс.
- **FR-004**: Модуль MUST быть доступен по имени файла без расширения и вести себя как синглтон в пределах рантайма: экспортные процедуры/функции вызываются, экспортные переменные читаются и записываются.
- **FR-005**: Исполняемый код модуля (включая инициализацию экспортных переменных) MUST выполняться при первом импорте, а не при каждом обращении; экспортные переменные после импорта доступны снаружи.
- **FR-006**: Неэкспортные процедуры, функции и переменные модуля и класса MUST быть недоступны снаружи; обращение к ним MUST завершаться ошибкой.
- **FR-007**: Класс MUST создаваться только через `Новый ИмяКласса(<аргументы>)`, при этом каждый вызов MUST создавать независимый экземпляр со своим состоянием; использование имени класса как модуля MUST быть ошибкой.
- **FR-008**: Конструктор `ПриСозданииОбъекта` / `OnObjectCreate` MUST вызываться при создании экземпляра с подстановкой значений по умолчанию для необязательных параметров; сам конструктор MUST NOT быть доступен как вызываемый снаружи метод.
- **FR-009**: Неверное число аргументов конструктора MUST давать ошибку, различающую: модуль без конструктора, не хватает обязательных параметров, переданы лишние параметры.
- **FR-010**: Повторный импорт уже загруженного файла MUST быть no-op (тот же модуль-синглтон или тот же тип класса), а код модуля MUST NOT исполняться повторно.
- **FR-011**: Кеш импорта MUST принадлежать рантайму (контексту исполнения), а не процессу; ключом MUST быть нормализованный разрешённый путь, чтобы разные написания одного пути давали одну запись.
- **FR-012**: Запись кеша MUST создаваться до исполнения тела импортируемого файла; при взаимном импорте A↔B оба тела MUST исполниться не более одного раза, загрузка MUST завершаться без зацикливания.
- **FR-013**: Обращение к члену модуля, который ещё находится в процессе циклической инициализации, MUST давать понятную ошибку, называющую модуль; после завершения цикла члены MUST быть доступны.
- **FR-014**: Директивы одного файла MUST быть расположены до первого `Перем`, метода или исполняемого оператора (как аннотации модуля в эталоне) и MUST разрешаться до исполнения кода; директива после кода MUST быть ошибкой, директивы в неактивных ветках `#Если` MUST игнорироваться.
- **FR-015**: В Node путь MUST разрешаться относительно каталога импортирующего файла; путь, начинающийся с `/`, MUST считаться абсолютным путём от корня файловой системы.
- **FR-016**: В браузере относительный путь MUST разрешаться как URL относительно адреса документа (как для `<script>`/изображений), а путь от `/` — от корня сервера; источник MUST загружаться с сервера по URL, без сборки и без файловой системы.
- **FR-017**: В браузере все импорты страницы MUST быть получены с сервера до исполнения скрипта, который их объявляет; ошибка HTTP или сети MUST сообщать URL и статус (если есть) и место директивы.
- **FR-018**: Ошибки импорта MUST быть диагностируемыми: отсутствующий файл, синтаксическая ошибка во вложенном файле, недопустимое имя (не BSL-идентификатор) и конфликт имён MUST называть путь/имя и приводить к остановке текущего скрипта с ошибкой, а не к тихому пропуску.
- **FR-019**: Изменение MUST не ломать существующие сценарии: `#Использовать asserts` и стандартная библиотека работают как раньше, существующий набор тестов остаётся зелёным, браузерный контракт (`onescript.js`, `<one-script>`, `Сообщить()` → `console.log`) сохраняется.
- **FR-021**: `ЗагрузитьСценарийИзСтроки(Текст, Имя?)` MUST резолвить `#Использовать` относительно `Имя` (или пути текущего сценария) и MUST использовать кеш импорта текущего запуска; в браузере источник обязан быть уже предзагружен, иначе MUST быть ошибка «файл не найден».
- **FR-020**: Ядро движка MUST NOT зависеть от Node-модулей или DOM из-за импорта: платформенная загрузка файлов/URL MUST быть изолирована в средах Node и браузера.

### Key Entities

- **Импортируемый скрипт**: разрешённый путь, имя для доступа (имя файла без `.os`), вид (модуль/класс), исходник, экспортная поверхность.
- **Запись кеша рантайма**: разрешённый путь, состояние загрузки (загружается/готов), готовый модуль-синглтон или фабрика экземпляров класса.
- **Экспортная поверхность**: набор экспортных процедур/функций и экспортных переменных, видимых снаружи модуля или экземпляра класса.
- **Конструктор класса**: процедура `ПриСозданииОбъекта`/`OnObjectCreate` с обязательными и необязательными параметрами, задающая начальное состояние экземпляра.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Программа из двух файлов (главный + модуль) выполняется и печатает ожидаемый результат; код инициализации модуля исполняется ровно 1 раз независимо от числа обращений и повторных импортов.
- **SC-002**: Класс с обязательным и необязательным параметрами конструктора создаёт два независимых экземпляра: 2 из 2 экземпляров имеют корректное состояние, изменение одного не влияет на другой.
- **SC-003**: Взаимный импорт двух файлов завершается менее чем за 1 секунду без зависания; тело каждого файла исполняется не более 1 раза.
- **SC-004**: 100% проверенных ошибочных ситуаций (отсутствующий файл, недопустимое имя, конфликт имён, неверная арность конструктора) дают сообщение с путём или именем и не завершаются молча.
- **SC-005**: Браузерная страница с `<one-script>`, импортирующим файл по относительному URL и по URL от корня сервера, работает без сборки и без ручной подстановки исходников; при недоступном URL в консоли есть ошибка с URL.
- **SC-006**: Регрессии: существующий набор тестов зелёный (0 падений), сборка браузерного бандла успешна, приёмочная страница `examples/hello.html` по-прежнему выводит ожидаемые строки.

## Assumptions

- Область первой версии — только файловые пути. Поиск библиотек в каталогах установки, `lib.config`, переменные окружения вроде `OSCRIPT_LIB`, версии и пакеты не поддерживаются; нераспознанные имена без кавычек остаются no-op.
- Расширение `.os` не добавляется автоматически: путь используется как указан. Имя для доступа — имя файла с отброшенным `.os`; при другом расширении отбрасывается последнее расширение.
- В Node путь от `/` — абсолютный путь файловой системы (включая Windows-пути с буквой диска), а не «корень проекта»: `#Использовать "/home/user/file.os"` загружает файл по этому пути, если у процесса есть права. В браузере `/` — корень сервера.
- Кеш импорта живёт в пределах одного контекста исполнения. Два элемента `<one-script>` на странице и два отдельных запуска получают независимые кеши и независимое состояние модулей.
- Изменения файла после первого импорта не подхватываются: горячей перезагрузки модулей нет.
- Имена конструктора двуязычные (`ПриСозданииОбъекта`/`OnObjectCreate`) и директивы двуязычные (`#Использовать`/`#Use`) — по конституции проекта.
- Динамическое подключение как отдельная тема — спека 004 (`ПодключитьСценарий`, `ЗагрузитьСценарий`). В 008 `ЗагрузитьСценарийИзСтроки` дополнительно резолвит импорты (FR-021); в браузере динамический импорт работает только для источников, уже предзагруженных страницей, — runtime-`fetch` в синхронном движке невозможен.
- `ТекущийСценарий()` для импортированных файлов не переопределяется в первой версии: импорт выполняется как часть запуска, без отдельного объекта-сценария.
- Импорт класса не исполняет тело файла: код модуля класса (вне методов) выполняется при
  создании каждого экземпляра перед конструктором — как в эталонной модели сценария-объекта
  (`ScriptDrivenObject.OnInstanceCreation` → тело модуля, затем `ПриСозданииОбъекта`).
- Циклы поддерживаются в объёме «не зависнуть и загрузить один раз»; порядок, при котором каждый модуль гарантированно видит полностью готовые экспортные данные друг друга до первого обращения, не гарантируется — обращение к ещё не готовому члену даёт ошибку.
- Кодировка импортируемых файлов — UTF-8; BOM в начале файла не должен ломать разбор (как и для запускаемого скрипта).
