# Feature Specification: Встроенный `.osjs` в HTML — редакторные инструменты внутри `<script type="text/osjs">`

**Feature Branch**: `feat/linter`

**Created**: 2026-11-12

**Status**: In Progress — слой A реализован; слой B — спека 017, слой C — спека 018 (грамматическая инъекция реализована)

**Input**: Запрос владельца проекта: вся LSP-логика должна работать внутри встроенных
блоков при открытом HTML. После оценки форм встраивания владелец выбрал канон
`<script type="text/osjs">` (см. [`specs/016-osjs-script-tag/spec.md`](../016-osjs-script-tag/spec.md));
эта спека описывает редакторные инструменты для такой формы. Первичная идея
зафиксирована в [`specs/014-osjs-editor-tooling/spec.md`](../014-osjs-editor-tooling/spec.md).

## Context

Продукт OneScriptJS — **браузерный** движок: главный пользовательский сценарий — BSL-код
внутри `<script type="text/osjs">` на HTML-странице (см. `task.md`, `examples/*.html`). Спека 014 дала
редакторные инструменты для файлов `.osjs` (грамматика, LSP-сервер, диагностика,
подсказки, semantic tokens, навигация), но код **внутри страницы** остаётся без поддержки:
редактор видит HTML, а BSL внутри тега — просто текст.

Эта спека описывает поддержку **встроенных блоков**: инструменты 014 применяются к
содержимому каждого `<script type="text/osjs">` при открытом HTML-документе. Ключевая модель —
**«гость в чужом формате»**: `.html`/`.htm` остаются языком HTML и его инструментов;
мы не заявляем их, не форматируем и не подменяем HTML-сервер, а добавляем поддержку
только внутри границ `<script type="text/osjs">…</script>`.

Что известно о рантайме (влияет на требования, но не диктует реализацию):

- Браузерный вход исполняет **каждый** блок `<script type="text/osjs">` отдельно, в свежем
  контексте; содержимое такого тега — HTML **raw text** (см. спеку 016), поэтому `<`, `>`,
  `&` не интерпретируются, а `textContent` совпадает с сырым текстом файла (кроме
  нормализации переводов строк). Импорты `#Использовать` разрешаются относительно
  `document.baseURI`.
- Единственное расхождение raw text с «кодом как есть» — последовательность `</script>`
  обрывает блок. По решению владельца это обязательная Error-диагностика линтера
  (спека 016, FR-007); сканер 015 её реализует.
- 014 даёт готовый чистый анализатор (`analyze(text)`), провайдеры и LSP-сервер;
  `DocumentStore` сейчас намеренно принимает только `languageId === 'osjs'` — это
  осознанная граница, которую эта спека расширяет режимом встроенных блоков.
- Оценка из обсуждения (не обязательство): полезный v1 после появления клиента VS Code —
  порядка 1–2 недель работы; главный риск — границы HTML и поведение чужих инструментов,
  а не анализ BSL.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Код в `<script type="text/osjs">` подсвечивается как `.osjs` (Priority: P1)

Разработчик открывает HTML-страницу с `<script type="text/osjs">` и видит, что BSL-код внутри тега
подсвечен как `.osjs` (ключевые слова RU/EN, строки, числа, даты, комментарии, директивы,
`Асинх`/`Ждать`, аннотации), а разметка вокруг остаётся HTML. Вне тега подсветка не
меняется. Файл по-прежнему остаётся HTML-документом: language id не наш, HTML-инструменты
работают.

**Why this priority**: Подсветка — минимальная ценность и самый дешёвый шаг: работает без
пересылки позиций и без «умных» провайдеров. Она же визуально подтверждает главную
границу: мы поддерживаем только содержимое тега.

**Independent Test**: HTML-фикстура с двумя `<script type="text/osjs">` и разметкой вокруг; в редакторе
с поддержкой TextMate-инъекций/embedded languages содержимое блоков получает scope
`source.osjs`, а разметка — HTML-скоупы. Автоматизируемая часть — грамматика инъекции и
snapshot-проверка scope на фикстуре (без запуска редактора).

**Acceptance Scenarios**:

1. **Given** HTML с `<script type="text/osjs">`, внутри — BSL, **When** документ открыт в редакторе с
   нашей инъекционной грамматикой, **Then** конструкции FR-002 из 014 подсвечены внутри
   тега, а HTML-разметка снаружи — как HTML.
2. **Given** два `<script type="text/osjs">` на странице, **When** документ открыт, **Then** содержимое
   обоих подсвечено, границы блоков не «протекают» друг в друга и в разметку.
3. **Given** `.html` без `<script type="text/osjs">`, **When** документ открыт, **Then** наша подсветка
   не появляется (только HTML-инструменты).
4. **Given** `<!-- <script type="text/osjs"> … </script> -->` в HTML-комментарии, **When** документ
   открыт, **Then** содержимое комментария не считается BSL-блоком.

---

### User Story 2 - Диагностика внутри блоков, привязанная к HTML-позициям (Priority: P2)

Разработчик печатает BSL внутри `<script type="text/osjs">` и видит ошибки прямо в HTML-документе:
подчёркивание в правильном месте страницы, несколько ошибок из разных блоков
одновременно, очистка после исправления. Вне `<script type="text/osjs">` наши диагностики не
появляются; HTML-валидатор продолжает показывать своё.

**Why this priority**: Это ядро «линтера» для встроенного кода; требует маппинга позиций
между виртуальным блоком и HTML-документом — главной технической работы спеки.

**Independent Test**: протокольный тест с `languageId: html`: открыть страницу с блоками,
получить диагностики только внутри блоков с корректными HTML-диапазонами (включая
CRLF/BOM/кириллицу/эмодзи); исправить одну ошибку — набор обновился; вне блоков — пусто.

**Acceptance Scenarios**:

1. **Given** HTML с ошибкой разбора в `<script type="text/osjs">` на 3-й строке блока, **When** документ
   открыт, **Then** в течение 1 секунды публикуется диагностика, чей диапазон указывает на
   правильные строку/колонку **HTML-файла**.
2. **Given** три блока с независимыми ошибками, **When** документ открыт, **Then** показаны
   все три с диапазонами внутри соответствующих блоков.
3. **Given** ошибка внутри блока, **When** она исправлена, **Then** диагностика исчезает в
   течение 1 секунды, остальные диагностики не «съезжают».
4. **Given** HTML-разметка вне блоков и валидный BSL внутри, **When** документ открыт,
   **Then** наши диагностики не публикуются вовсе (ошибки HTML — не наша зона).
5. **Given** документ с чужим содержимым (`languageId` не html и не osjs), **When** сервер
   его получает, **Then** он ничего не публикует.

---

### User Story 3 - Подсказки, подсветка от сервера и переходы внутри блока (Priority: P3)

Разработчик работает внутри `<script type="text/osjs">`: автодополнение (`Сооб` → `Сообщить`), hover с
сигнатурой, semantic tokens, переход к определению локального символа и импортированного
`.osjs`-файла — с учётом того, что блок исполняется отдельно, а импорты разрешаются
относительно страницы. Вне блока подсказок языка нет; между блоками символов не видно.

**Why this priority**: Полный паритет с 014 внутри блока; опирается на готовый анализатор и
на маппинг из US2, поэтому идёт после диагностики.

**Independent Test**: протокольные/unit-тесты: completion/hover внутри блока как в `.osjs`;
semantic tokens только внутри блоков; definition локального символа и `#Использовать`
(относительно URL страницы); вне блока — пустые ответы; символы одного блока не видны в
другом.

**Acceptance Scenarios**:

1. **Given** курсор внутри `<script type="text/osjs">` после `Сооб`, **When** запрошен completion,
   **Then** есть `Сообщить`/`Message` с сигнатурой; вне блока — пустой ответ.
2. **Given** курсор на `Сообщить(`, **When** запрошен hover, **Then** возвращается
   сигнатура/описание, совпадающее с `docs/reference.md`.
3. **Given** два `<script type="text/osjs">` с разными локальными переменными, **When** запрошены
   semantic tokens и definition, **Then** токены/переходы не выходят за границы своего
   блока, имена другого блока не считаются известными.
4. **Given** `#Использовать "lib/Модуль.osjs"` внутри блока, **When** запрошен definition,
   **Then** возвращается файл, разрешённый относительно URL HTML-документа (как
   `document.baseURI` в рантайме).
5. **Given** страница с блоками и обычной разметкой, **When** запрошены подсказки вне
   блока, **Then** наш сервер возвращает пусто и не мешает HTML-инструментам.

---

### User Story 4 - Сосуществование с HTML-инструментами (Priority: P4)

Разработчик продолжает пользоваться HTML-сервером, валидатором, форматтером и Emmet:
наша поддержка не заявляет `.html`, не меняет language id, не форматирует страницу и не
подменяет outline HTML. Диагностики различимы по источнику; поведение вне блоков
остаётся полностью за HTML-инструментами.

**Why this priority**: Без явной политики «гостя» поддержка встроенного кода начнёт
конфликтовать с чужими расширениями — это главный риск спеки.

**Independent Test**: открыть HTML в окружении с HTML-сервером и нашим сервером: language
mode остаётся HTML, HTML-диагностики идут своим каналом, наши — с `source: 'osjs'`,
форматирование/rename/outline ведут себя как раньше.

**Acceptance Scenarios**:

1. **Given** установлены HTML-инструменты и наш сервер, **When** открыт `.html`, **Then**
   language id остаётся `html`, HTML-диагностики продолжают работать.
2. **Given** HTML-документ с блоками, **When** выполнено форматирование HTML-инструментом,
   **Then** наш сервер не добавляет своих правок/диагностик о форматировании и не
   претендует на `.html`.
3. **Given** `#Область`/методы внутри блока, **When** открыт Outline, **Then** иерархия
   HTML-документа не ломается (BSL-символы не подмешиваются в outline в первой версии;
   см. Out of Scope).
4. **Given** страница без `<script type="text/osjs">`, **When** наш сервер получает документ, **Then**
   он не публикует диагностик и не отвечает подсказками.

### Edge Cases

- **Несколько блоков**: каждый анализируется отдельно, контексты не разделяются (как в
  рантайме — свежий контекст на элемент); переходы между блоками не поддерживаются.
- **Незакрытый блок** (нет `</script>` до EOF): содержимое до конца документа трактуется
  как блок; ошибку HTML-структуры сообщает HTML-валидатор, не мы.
- **`<!-- <script type="text/osjs"> … </script> -->`**: игнорируется (не блок).
- **Атрибуты тега** (`<script type="text/osjs" id="…">`): учитываются при сканировании, содержимое —
  между `>` и `</script>`.
- **Регистр тега и `type`**: имя тега и значение `type` сравниваются без учёта регистра
  (HTML); сканер обязан находить блок независимо от регистра.
- **`<`, `>` и `&` в коде**: raw text — работают как в BSL без экранирования и без
  пробелов (`A<B` — валидное сравнение). Это главное преимущество формы (016).
- **`</script>` в BSL-строке/комментарии**: обрыв блока; диагностируется обязательным
  Error-правилом `OSJS4001` (016 FR-007) с диапазоном и подсказкой.
- **`<script` или `<!--` внутри BSL-строки**: legacy-состояния script-data; по умолчанию
  только документируется и (опционально) предупреждается; обязателен только `</script>`.
- **CRLF/BOM/кириллица/эмодзи**: позиции и диапазоны в HTML-документе считаются в UTF-16
  code units; диапазоны не выходят за границы блока.
- **Блоки в `<head>` и в середине текста**: поддерживаются настолько, насколько браузер
  исполняет элемент; инструменты следуют расположению тегов.
- **Очень большая страница / много блоков**: сканирование O(n), анализ по блокам с общим
  лимитом диагностик; редактор не должен зависать.
- **Untitled-буфер HTML**: блоки анализируются, `#Использовать`-переходы ограничены
  отсутствием URL (как в 014 для untitled).
- **HTML-сущности в пути импорта** и странные символы: резолвер возвращает `null`,
  исключения не пробрасываются.
- **Чужой languageId**: сервер не публикует ничего и не отвечает подсказками.
- **Наши диагностики внутри блока в `Попытка`/`Исключение`**: логика 014 не меняется —
  это BSL-диагностика, а не HTML.
- **Расширение/сервер выключены**: HTML открывается как обычно, `.osjs`-инструменты
  работают как в 014.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Инструменты ДОЛЖНЫ применяться только к содержимому элементов `<script type="text/osjs">`
  (без самих тегов); вне блоков не должно быть ни диагностик, ни completion, ни hover, ни
  semantic tokens, ни definition от нашего сервера.
- **FR-002**: HTML-документы НЕ ДОЛЖНЫ заявляться нашим языком: `languageId` остаётся
  `html`, расширения `.html`/`.htm` не переименовываются и не переопределяются; наша
  поддержка подключается как дополнительный провайдер/сервер, а не как владелец формата.
- **FR-003**: Сканер блоков ДОЛЖЕН находить все `script[type="text/osjs"]` в сыром тексте
  HTML (значение `type` — без учёта регистра), устойчиво к атрибутам, нескольким блокам и
  HTML-комментариям; незакрытый блок трактуется как содержимое до EOF. Ошибки
  HTML-структуры диагностирует HTML-инструмент, не мы.
- **FR-004**: Каждый блок ДОЛЖЕН анализироваться тем же анализатором, что в 014, как
  отдельный виртуальный документ; таблицы символов изолированы по блокам (как контексты
  исполнения в рантайме).
- **FR-005**: Позиции ДОЛЖНЫ двунаправленно отображаться между виртуальным блоком и
  HTML-документом: 1-based движка ↔ 0-based LSP, UTF-16 code units; диапазоны не выходят за
  границы блока; CRLF/BOM/кириллица/эмодзи не сдвигают диапазоны.
- **FR-006**: Диагностика ДОЛЖНА включать синтаксис и консервативную семантику 014 (те же
  коды/severity/сообщения) с диапазонами в координатах HTML; лимит на **HTML-документ**
  (не более 200 суммарно), очистка устаревших наборов, отсутствие диагностик вне блоков.
- **FR-007**: Completion и hover ДОЛЖНЫ работать внутри блока с тем же поведением и
  данными, что в 014 (stdlib, локальные символы блока, контекстные `Асинх`/`Ждать`), и НЕ
  возвращать подсказок вне блоков; имена импортированных модулей известны в пределах блока.
- **FR-008**: Semantic tokens ДОЛЖНЫ строиться по токенам блока и отображаться в
  HTML-координаты (без пересечений, с разбиением многострочных литералов); вне блоков
  токенов нет.
- **FR-009**: Definition ДОЛЖЕН разрешать локальные символы в пределах блока и файл из
  `#Использовать` относительно URL HTML-документа (как `document.baseURI` в рантайме);
  переходы между блоками не поддерживаются.
- **FR-010**: Анализ ДОЛЖЕН идти по сырому срезу между тегами (координаты редактора); для
  script data block он совпадает с рантаймовым содержимым (кроме нормализации переводов
  строк). Единственное расхождение — обрыв по `</script>`, он обязан диагностироваться
  правилом `OSJS4001` (016 FR-007).
- **FR-011**: Политика «гостя»: мы НЕ форматируем HTML, не делаем rename/refactor, не
  реализуем `foldingRange` для HTML, не подмешиваем BSL-символы в outline HTML в первой
  версии; наши диагностики имеют `source: 'osjs'`, HTML-диагностики не трогаются.
- **FR-012**: Подсветка ДОЛЖНА доставляться двумя путями: инъекционная TextMate-грамматика
  (поверх `source.html`, содержимое `script[type="text/osjs"]` → `source.osjs`; учесть, что
  HTML-грамматика по умолчанию даёт script-содержимому `source.js` — нужен override) для семейства
  VS Code/TextMate и semantic tokens сервера — для остальных LSP-клиентов; отдельная
  BSL-грамматика не заводится (переиспользуется `editors/osjs/`).
- **FR-013**: Встроенный режим ДОЛЖЕН включаться явно на стороне клиента (documentSelector/
  конфигурация «обслуживать html»), а не «по умолчанию для всех html»: сервер не
  подключается сам и не навязывает поддержку.
- **FR-014**: Производительность: сканирование страницы O(n); анализ по блокам в бюджете
  014 (≤1 с на типичную страницу, набор не блокируется); лимиты диагностик и semantic
  tokens — на документ.
- **FR-015**: Проверка ДОЛЖНА быть автоматической: сканер блоков (фикстуры HTML), round-trip
  маппинга позиций (CRLF/BOM/кириллица/эмодзи), протокольные тесты с `languageId: html`
  (только внутри блоков, чужие документы — пусто), изоляция блоков, definition импорта.
  Ручная проверка в редакторе — дополнительно, не вместо тестов.
- **FR-016**: Документация: README/`docs/status.md`/`docs/architecture.md`, гайдлайн
  авторинга (`</script>` и `<script`/`<!--` в строках, многострочные строки), явное указание, что для
  VS Code embedded language mode нужен будущий клиент, а для прочих редакторов —
  инъекции/семантические токены по их возможностям.
- **FR-017**: Эта спека НЕ меняет движок и браузерный бандл: переход на
  `<script type="text/osjs">` и удаление прежней формы (ранее `<one-script>`) — спека
  016. 015 зависит от неё и реализует только редакторный слой над блоками.

### Key Entities

- **HTML-документ с блоками** — исходный файл, `languageId: html`, владелец — HTML-инструменты.
- **Блок `<script type="text/osjs">`** — диапазон содержимого в HTML-координатах (начало/конец,
  исключая теги), привязка к порядковому номеру.
- **Виртуальный документ** — текст блока + `Analysis` из 014; кэш по версии HTML-документа.
- **Карта позиций** — двунаправленное отображение HTML ↔ блок с учётом UTF-16 и переводов
  строк.
- **Набор диагностик HTML-документа** — сумма диагностик всех блоков с лимитом на документ
  и `source: 'osjs'`.
- **Режим встроенной поддержки** — клиентская настройка/selector, включающая обслуживание
  HTML; без неё сервер ничего не делает.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: На HTML-странице с двумя `<script type="text/osjs">` подсветка/диагностика/подсказки/
  токены появляются только внутри блоков; в разметке вне блоков — ничего (проверяется
  грамматическим и протокольным тестом).
- **SC-002**: Ошибки из трёх разных блоков видны одновременно; диапазоны указывают на
  правильные HTML-строки/колонки (в т.ч. CRLF, BOM, кириллица, эмодзи); после исправления
  одной ошибки набор обновляется ≤1 с, остальные не сдвигаются.
- **SC-003**: Completion для `Сооб` внутри блока содержит `Сообщить`/`Message`; hover на
  `Сообщить(` совпадает с `docs/reference.md`; вне блока — пусто.
- **SC-004**: Semantic tokens покрывают лексемы внутри блоков, не пересекаются и не съезжают
  после вставки/удаления строк; вне блоков токенов нет.
- **SC-005**: Definition локального символа ведёт на объявление в том же блоке; definition
  из `#Использовать` — на файл относительно URL страницы; переходы между блоками
  отсутствуют.
- **SC-006**: С установленными HTML-инструментами language id остаётся `html`, HTML-
  диагностики/форматирование/outline работают как раньше; наши диагностики отличимы по
  `source: 'osjs'`; мы не форматируем и не переименовываем.
- **SC-007**: Страница ~2000 строк с 10 блоками анализируется ≤1 с; набор текста не вызывает
  заметных (более 1 с) зависаний.
- **SC-008**: Сервер работает офлайн, без телеметрии и рантайм-скачиваний (наследуется
  от 014).
- **SC-009**: `pnpm typecheck && pnpm test && pnpm build` — зелёные; новые тесты покрывают
  сканер, маппинг и протокол; браузерный бандл не содержит LSP-кода; `.osjs`-функционал
  014 не сломан.
- **SC-010**: Документация обновлена: README/`docs/status.md`/`docs/architecture.md`,
  гайдлайн авторинга (`</script>`/`<script`/`<!--` в строках) и про необходимость клиента
  VS Code для embedded language mode.

## Out of Scope

- Тонкий клиент VS Code (`.vsix`) — **предусловие** для embedded language mode/инъекций;
  отдельная работа (014, FR-018).
- Поддержка `<script type="text/osjs">` и любые изменения браузерного entry/рантайма.
- Форматирование, rename, рефакторинг, quick fixes, foldingRange для HTML.
- Подмешивание BSL-символов в outline HTML-документа в первой версии.
- Диагностика самого HTML и замена/конкуренция с HTML-сервером.
- Workspace-индексация, переходы между блоками и между разными HTML-файлами.
- Эмуляция script-data: расхождения из-за `</script>`/`<script`/`<!--` не «исправляются»
  инструментами; `</script>` обязана диагностировать (016), остальное — гайдлайн.
- Редакторы без поддержки инъекций/LSP — для них гарантируется только то, что даёт
  semantic tokens их клиента.

## Assumptions

- **Спека 014 реализована** (анализатор, провайдеры, сервер) и переиспользуется без
  форка: встроенный режим — слой виртуальных документов и маппинга над `src/lsp`.
- **«Гость в HTML»** — осознанная модель: `.html` не наш формат; мы добавляем провайдер
  только на явно включённых клиентом HTML-документах.
- **Каноническая форма** — `<script type="text/osjs">` (спека 016); прежний
  `<one-script>` (ранее; заменён спекой 016) не поддерживается, инструменты
  проектируются только под script-блоки.
- **Сырой срез как источник координат**: анализ идёт по тексту между тегами, позиции — в
  координатах редактора; для script data block текст совпадает с рантаймовым, кроме
  нормализации переводов строк; обрыв по `</script>` диагностируется (016).
- **Изоляция блоков** соответствует рантайму: каждый `<script type="text/osjs">` — отдельный контекст;
  импорты разрешаются относительно `document.baseURI` (для локального файла — каталог
  документа; для http-страницы, открытой с диска, возможны расхождения URL/пути).
- **Лимиты** — на HTML-документ: не более 200 диагностик суммарно, semantic tokens — как в
  014 (≤10 000 строк на блок/документ); первые N блоков при экстремальных страницах.
- **Один HTML-документ — один анализ-цикл** (полная синхронизация, как в 014), без
  инкрементальности.
- **Браузерная приёмка** к инструментам неприменима (они не исполняют BSL); проверка —
  тестами и, дополнительно, ручной проверкой в редакторе (в среде без редактора —
  протокольные тесты, ограничение фиксируется в `docs/status.md`, как в 014).
- **Оценка 1–2 недели** после появления клиента VS Code — не обязательство, а порядок
  величины для планирования.
