# Feature Specification: Структура модуля и контекст операторов

**Feature Branch**: `feat/includes`

**Created**: 2026-11-11

**Status**: Implemented (ретро-спека: описывает уже реализованное поведение)

**Input**: Паритет парсера с эталонным `DefaultBslParser`: порядок секций модуля
(`#Использовать` → `Перем` → методы → код), локальные `Перем`, контекст `Возврат`,
`Прервать`/`Продолжить` и `ВызватьИсключение;`.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Порядок секций модуля (Priority: P1)

Разработчик пишет файл в каноническом порядке: импорты, объявления переменных, процедуры и
функции, затем исполняемый код. Парсер отвергает объявления, встреченные после кода, вместо
того чтобы молча их «поднимать»: иначе невалидный для OneScript файл исполнялся бы у нас.

**Why this priority**: Это основа совместимости: без проверки порядка движок принимает файлы,
которые эталон не компилирует, и скрывает ошибки структуры.

**Independent Test**: Разобрать канонический модуль — успешно; поставить `Перем` или метод после
оператора — ошибка с понятным сообщением; локальный `Перем` после оператора в методе — ошибка.

**Acceptance Scenarios**:

1. **Given** `Перем X;` → `Процедура П()` → `X = 1;`, **When** файл разбирается, **Then** AST содержит `VariableDeclaration`, `MethodDeclaration`, `Assignment` в этом порядке.
2. **Given** исполняемый оператор, затем `Функция Ф()`, **When** файл разбирается, **Then** ошибка «объявление метода должно быть расположено до исполняемого кода».
3. **Given** метод, затем `Перем X;`, **When** файл разбирается, **Then** ошибка «объявления переменных должны быть расположены в начале модуля, процедуры или функции».
4. **Given** метод с `Перем` в начале, **When** файл разбирается, **Then** успех; **Given** `Перем` после оператора или внутри блока — ошибка.
5. **Given** вложенная процедура/функция, **When** файл разбирается, **Then** ошибка объявления метода.
6. **Given** `#Область`, пустые операторы и аннотации `&…` перед объявлениями, **When** файл разбирается, **Then** они не мешают порядку секций.

---

### User Story 2 - Контекст операторов (Priority: P2)

Разработчик использует `Возврат`, `Прервать`, `Продолжить` и `ВызватьИсключение;` только там,
где они допустимы. Парсер проверяет контекст и сообщает ошибку до исполнения, как эталон.

**Why this priority**: Без проверок такие операторы дают невнятные ошибки рантайма или тихо
ломают исполнение; эталон отвергает их на компиляции.

**Independent Test**: `Возврат` на верхнем уровне — ошибка; `Возврат;` в функции — ошибка;
`Возврат 1;` в процедуре — ошибка; `Прервать`/`Продолжить` вне цикла — ошибка;
`ВызватьИсключение;` вне `Исключение` — ошибка; валидные случаи разбираются.

**Acceptance Scenarios**:

1. **Given** `Возврат 1;` на верхнем уровне, **When** файл разбирается, **Then** ошибка «Оператор "Возврат" может использоваться только внутри метода».
2. **Given** функция с `Возврат;` без значения, **When** файл разбирается, **Then** ошибка «Функция должна возвращать значение».
3. **Given** процедура с `Возврат 1;`, **When** файл разбирается, **Then** ошибка «Процедуры не могут возвращать значение».
4. **Given** `Прервать;` или `Продолжить;` вне цикла, **When** файл разбирается, **Then** ошибка «может использоваться только внутри цикла».
5. **Given** `ВызватьИсключение;` вне блока `Исключение`, **When** файл разбирается, **Then** ошибка; внутри `Исключение` — успех.
6. **Given** валидные `Возврат` в функции/процедуре и `Прервать` в цикле, **When** файл разбирается, **Then** ошибок нет.

---

### User Story 3 - Одни правила для любого источника (Priority: P3)

Те же проверки применяются к импортируемым файлам и к коду, загруженному через `Выполнить`,
`ЗагрузитьСценарийИзСтроки` и `ЗагрузитьСценарий`: все они проходят один парсер.

**Why this priority**: Иначе валидность зависела бы от способа запуска, а динамический код
мог бы обходить структурные требования.

**Independent Test**: Динамический исходник с `Возврат` вне метода падает с тем же сообщением,
что и обычный; импортируемый файл с `Перем` после метода — ошибка с путём файла (обёртка 008).

**Acceptance Scenarios**:

1. **Given** `Выполнить "Возврат 1;"`, **When** строка исполняется, **Then** ошибка «только внутри метода».
2. **Given** импортируемый файл с нарушением порядка секций, **When** он загружается, **Then** ошибка обёрнута путём импортируемого файла.

---

### Edge Cases

- Аннотации `&…` перед `Перем` и методами допустимы; пустые операторы `;;` не считаются кодом для порядка секций.
- `#Область`/`#КонецОбласти` не влияют на порядок; неактивные ветки `#Если` не считаются кодом.
- Импорт после кода (`#Использовать`) — отдельное правило спеки 008 (FR-014), здесь не дублируется.
- `Возврат` внутри `Если`/цикла в методе наследует контекст метода; на верхнем уровне — ошибка.
- Ошибка указывает строку и колонку токена, на котором обнаружено нарушение.
- `Перейти`/метки и `Асинх` — вне scope (см. Assumptions).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Модуль MUST разбираться в порядке `#Использовать` → `Перем` → методы → исполняемый код; объявления, встреченные после кода, MUST быть ошибкой.
- **FR-002**: `Перем` MUST быть допустим в начале модуля и в начале метода; `Перем` после операторов или внутри блока MUST быть ошибкой «объявления переменных должны быть расположены в начале модуля, процедуры или функции».
- **FR-003**: Вложенные `Процедура`/`Функция` MUST быть ошибкой «объявление метода должно быть расположено до исполняемого кода».
- **FR-004**: `Возврат` вне метода MUST быть ошибкой «Оператор "Возврат" может использоваться только внутри метода».
- **FR-005**: `Возврат;` в функции MUST быть ошибкой «Функция должна возвращать значение».
- **FR-006**: `Возврат <значение>;` в процедуре MUST быть ошибкой «Процедуры не могут возвращать значение».
- **FR-007**: `Прервать`/`Продолжить` вне цикла MUST быть ошибкой «Оператор "…" может использоваться только внутри цикла».
- **FR-008**: `ВызватьИсключение;` без аргумента MUST быть допустим только лексически внутри блока `Исключение`; иначе — ошибка.
- **FR-009**: Ошибки MUST содержать позицию (строка, колонка) и не менять поведение валидных скриптов.
- **FR-010**: Импортируемые файлы и динамический код (`Выполнить`, `ЗагрузитьСценарийИзСтроки`, `ЗагрузитьСценарий`) MUST проходить те же проверки; ошибка импортируемого файла MUST быть обёрнута его путём (спека 008).
- **FR-011**: Изменение MUST не ломать существующие сценарии: набор тестов и браузерные примеры остаются зелёными, примеры и фикстуры приведены к каноническому порядку.

### Key Entities

- **Секция модуля**: импорты, объявления переменных, методы, исполняемый код; порядок фиксирован.
- **Контекст разбора**: вид текущего метода (`процедура`/`функция`), глубина цикла, глубина блока `Исключение` — определяет допустимость операторов.
- **Диагностика**: сообщение эталонного вида + позиция токена.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% сценариев порядка секций (поздний `Перем`, метод после кода, вложенный метод, локальный `Перем` после оператора) завершаются ошибкой разбора; канонический модуль разбирается.
- **SC-002**: 100% проверенных нарушений контекста (`Возврат` вне метода, пустой `Возврат` в функции, `Возврат` со значением в процедуре, `Прервать`/`Продолжить` вне цикла, `ВызватьИсключение;` вне `Исключение`) дают ошибку с позицией.
- **SC-003**: Валидные варианты тех же операторов (функция со значением, процедура без значения, `Прервать` в цикле, перевыброс в `Исключение`) разбираются без ошибок.
- **SC-004**: Регрессии: `pnpm typecheck`, `pnpm test`, `pnpm build` зелёные; `examples/hello.html` и демо-страницы работают.

## Assumptions

- `Перейти` и проверки меток не входят в задачу (явно исключены пользователем).
- `Асинх`-методы и их проверки — отдельная будущая задача.
- Ограничения аннотаций и `#Область` сверх порядка секций не расширяются.
- Позиция `#Использовать` — правило спеки 008 (FR-014), здесь только ссылка.
- Для канонического порядка примеры `examples/*` и тестовые фикстуры переведены в
  `#Использовать` → `Перем` → методы → код.
