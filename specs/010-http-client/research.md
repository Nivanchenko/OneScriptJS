# Research: HTTP-клиент BSL

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md)

Все пункты ниже сняли неопределённости планирования; `[NEEDS CLARIFICATION]` не осталось.

## R1. Синхронная или асинхронная модель

**Decision**: синхронная, как в эталоне. Методы `Получить`, `ОтправитьДляОбработки` и др.
возвращают `HTTPОтвет` сразу; исключение — только при сетевой ошибке.

**Rationale**: в эталоне (`HttpConnectionContext.GetResponse`) вызов блокирующий; ВМ
OneScriptJS — tree-walking интерпретатор без `Асинх`/`Ждать` (в парсере нет таких токенов).
Асинхронный API нельзя выразить в существующем языке: `fetch`/`http.request` вернули бы
Promise, а ждать его в синхронном `callMethod` нечем.

**Alternatives considered**:
- *Асинхронный движок (`async` интерпретатор)* — переписывает ВМ, все stdlib-методы и
  семантику вызовов; несоразмерно задаче и ломает совместимость.
- *Объект-«обещание» + `Ждать`* — требует нового синтаксиса, узлов AST и приостановки
  стека; отдельная большая фича.

## R2. Транспорт в браузере

**Decision**: синхронный `XMLHttpRequest`; тело ответа читается через
`overrideMimeType('text/plain; charset=x-user-defined')` и `responseText`, байты
восстанавливаются как `charCodeAt(i) & 0xff`. Разрешение URL, заголовки и тело — в ядре.

**Rationale**: XHR — единственный браузерный API, умеющий синхронный запрос. Трюк с
`x-user-defined` — стандартный способ получить байты при запрещённом для sync
`responseType = 'arraybuffer'`. `& 0xff` снимает отображение байтов 0x80–0xFF в
U+F780–U+F7FF. Заголовки читаются через `getAllResponseHeaders()`.

**Alternatives considered**:
- *`fetch` + `AbortController`/`Atomics.wait`* — в браузере нельзя блокировать поток до
  разрешения Promise.
- *`responseType = 'arraybuffer'`* — спецификация запрещает для синхронных запросов из
  документа.
- *Асинхронный XHR* — несовместим с синхронным BSL-вызовом.

**Известные ограничения** (зафиксированы в spec.md, Edge Cases): CORS, запрещённые
браузером заголовки (`User-Agent`, `Cookie`, `Content-Length` и т.п.), авто-редирект
нельзя отключить, таймаут не применяется, синхронный вызов блокирует страницу.

## R3. Транспорт в Node (CLI и тесты)

**Decision**: `spawnSync(process.execPath, ['-e', script])`, где script читает JSON из
stdin, выполняет `fetch`, печатает JSON `{status, headers, bodyBase64}` (или `{error}`).

**Rationale**: в Node нет синхронного HTTP-клиента; `http.request` асинхронен, а
`spawnSync` блокирует родителя до завершения дочернего процесса. Это ровно приём
`happy-dom/lib/fetch/SyncFetch.js` (`SyncFetchScriptBuilder`), проверенный в проде.
`fetch` в дочернем процессе даёт редиректы, таймаут через `AbortSignal.timeout` и
прозрачный gzip.

**Alternatives considered**:
- *`worker_threads` + `Atomics.wait`* — сложнее, требует SharedArrayBuffer и отдельного
  протокола; выигрыш в скорости не оправдан для CLI/тестов.
- *Реализовать `http.request` вручную в дочернем процессе* — больше кода (редиректы,
  gzip, TLS), чем `fetch`, без выгоды.
- *Не поддерживать Node вовсе* — CLI и `pnpm test` не смогли бы проверить фичу; браузер
  остаётся целевой средой, Node — вспомогательной.

## R4. Инъекция транспорта

**Decision**: `createGlobalContext(httpTransport?: HttpTransport)`; ядро регистрирует
типы HTTP всегда, но `HTTPСоединение` при создании требует транспорт, иначе бросает
локализованную ошибку. `src/browser/context.ts` передаёт XHR-транспорт,
`src/node/context.ts` — child-process-транспорт, тесты — фейковый.

**Rationale**: сохраняет принцип II конституции (ядро не знает про Node/DOM) и даёт
тестам детерминированный транспорт без сети. Пустой контекст продолжает работать:
остальная stdlib не зависит от HTTP.

**Alternatives considered**:
- *Автоопределение среды внутри `src/stdlib/http.ts`* — протаскивает `node:*`/DOM в ядро,
  запрещено конституцией.
- *Регистрировать типы только в платформенных контекстах* — тогда `createGlobalContext()`
  (публичное API) и `runScript` не знают HTTP; хуже для пользователя библиотеки.

## R5. Кодирование тела запроса

**Decision**: строка кодируется в байты без BOM; третий аргумент `ИспользоватьBOM`
принимается и не влияет на байты. Кодировка по умолчанию — UTF-8.

**Rationale**: в эталоне `SetBodyFromString` вызывает `Encoding.GetBytes`, который **не
пишет preamble**: `new UTF8Encoding(useBom)` влияет только на `GetPreamble`, а не на
`GetBytes`. Значит фактическое поведение эталона — UTF-8 без BOM. Байты берём из
существующих `encode`/`decode` в `src/stdlib/binary.ts` (они уже понимают
`КодировкаТекста` и строковые имена).

**Alternatives considered**:
- *Добавлять BOM по умолчанию* — разошлось бы с эталоном и ломало бы JSON на бэкендах.

## R6. Тело ответа и его отсутствие

**Decision**: транспорт всегда возвращает `body: Uint8Array` (возможно пустой) и `status`.
`HTTPОтвет` считает тело отсутствующим (`Неопределено`) для `204`, `304`, `HEAD` и
`Content-Length: 0`; иначе `ПолучитьТелоКакСтроку` возвращает строку (пустую, если байтов
нет), `ПолучитьТелоКакДвоичныеДанные` — `ДвоичныеДанные`.

**Rationale**: эталон возвращает `Неопределено`, когда `ContentLength == 0` или тело не
создано; для `HEAD` с непустым `Content-Length` — пустую строку. Полное повторение
тонкостей `.NET`-обёртки не даёт пользователю ничего, кроме непредсказуемости; выбран
простой и объяснимый инвариант, он закреплён тестами.

**Alternatives considered**:
- *Всегда возвращать пустую строку* — расходится с эталоном для `204`/отсутствующего тела.

## R7. Декодирование строки ответа

**Decision**: `charset` из `Content-Type` (регистронезависимо, с кавычками и без), по
умолчанию `utf-8`; явный аргумент `ПолучитьТелоКакСтроку(Кодировка)` переопределяет.
Декодирование — `TextDecoder` (utf-8, utf-16, windows-1251 и др. из Encoding Standard).

**Rationale**: повторяет `HttpResponseContext.GetBodyAsString` (по умолчанию charset из
ответа, иначе utf-8). Браузер и Node 20 поддерживают `TextDecoder` с нужными кодировками.

**Alternatives considered**:
- *Всегда UTF-8* — ломает windows-1251-бэкенды (типичны для 1С).

## R8. gzip и заголовки ответа

**Decision**: платформа распаковывает прозрачно (XHR/fetch делают это сами). Если в ответе
был `Content-Encoding` (gzip/deflate/br), он удаляется из `Заголовков`, а `Content-Length`
заменяется фактическим размером.

**Rationale**: повторяет `HttpResponseContext` для `AutoDecompress`. Иначе пользователь
видит `Content-Encoding: gzip` и неверный `Content-Length` при уже распакованном теле.

## R9. Специальные заголовки запроса

**Decision**: заголовки из `Запрос.Заголовки` передаются как есть (кроме запрещённых
платформой, которые тихо отбрасываются). `Content-Type`, `Accept`, `Range`, `Date`,
`Referer` и т.п. — обычные заголовки.

**Rationale**: `.NET`-ветка `SetRequestHeaders` нужна была из-за ограничений
`HttpWebRequest`; XHR/fetch таких ограничений не имеют. Дублировать её — мёртвый код.
`Content-Length` в браузере запрещён, в Node-транспорте вычисляется платформой —
поэтому фильтруется.

**Alternatives considered**:
- *Переносить `SetRequestHeaders` один-в-один* — несовместимо с браузерными запретами и
  добавило бы код без наблюдаемого эффекта.

## R10. Аутентификация

**Decision**: если `Пользователь` или `Пароль` непустые — заголовок
`Authorization: Basic base64(UTF-8 "user:password")`. `ИспользоватьАутентификациюОС` —
свойство без эффекта в браузере (нечего аутентифицировать на уровне ОС).

**Rationale**: эталон делает то же самое (`NetworkCredential` + явный `Authorization`
из-за 1С-серверов). OS-аутентификация в браузере невозможна; свойство сохранено для
совместимости кода.

## R11. URL и параметры соединения

**Decision**: `Сервер` без схемы → `http://`; допускаются только `http`/`https`;
`Порт != 0` переопределяет порт URL; ресурс разрешается `new URL(resource, base)`
(ведущий `/` — от корня, относительный — от пути). `Сервер`/`Порт` в свойствах — без
схемы/как в URL (порт по умолчанию 80/443).

**Rationale**: `UriBuilder` + `new Uri(base, resource)` в эталоне ведут себя так же;
`new URL` — стандартное браузерное API, доступное и в Node.

## R12. SSL-параметр и прокси

**Decision**: переданный SSL-объект (не `Неопределено`) → исключение, как в эталоне.
`Прокси` принимается, но всегда `Неопределено`; тип `ИнтернетПрокси` не реализуется.

**Rationale**: клиентские сертификаты в браузере не выбираются из скрипта; прокси в
браузере не настраивается. Явная ошибка на SSL лучше молчаливого игнорирования.

## R13. Ошибки

**Decision**: ошибки конфигурации (схема, порт, тип `Заголовки`, SSL, отсутствие
транспорта) — до сети; сетевые ошибки оборачиваются в
`Не удалось выполнить HTTP-запрос <METHOD> <URL>: <причина>`. Ответы 4xx/5xx — не ошибка.

**Rationale**: эталон возвращает `HTTPОтвет` для protocol error и бросает исключение для
остальных `WebException`; локализованное сообщение с URL ускоряет отладку на фронте.
