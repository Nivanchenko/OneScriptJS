# Feature Specification: HTTP-клиент BSL (HTTPСоединение, HTTPЗапрос, HTTPОтвет)

**Feature Branch**: `feature/speckit_intergation`

**Created**: 2026-11-11

**Status**: Implemented (браузерный транспорт проверен happy-dom; реальный браузер — ручная приёмка)

**Input**: Пользователь: «Нам необходимо на фронте получать данные с бэка. В оскрипте есть
объекты HTTPЗапрос, и HTTPСоединение. изучи исходники референса, и реализуй у нас такоеже».

Эталон: `reference/OneScript/src/OneScript.StandardLibrary/Http/*.cs`
(`HttpConnectionContext`, `HttpRequestContext`, `HttpResponseContext`, `HttpResponseBody`).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Скрипт на странице получает данные с бэкенда (Priority: P1)

Разработчик пишет BSL-код внутри `<one-script>` на странице, создаёт `HTTPСоединение`
с адресом своего бэкенда и `HTTPЗапрос` с путём ресурса, вызывает `Получить` и читает
тело ответа как строку. Скрипт печатает полученные данные через `Сообщить`.

**Why this priority**: Это ровно та задача, ради которой запрошен HTTP-клиент — «на фронте
получать данные с бэка». Без GET-сценария объекты не нужны.

**Independent Test**: Поднять локальный HTTP-сервер, отдающий JSON, и прогнать BSL-скрипт
`Новый HTTPСоединение(...)` → `Новый HTTPЗапрос(...)` → `Получить(Запрос)`; в выводе —
статус `200` и тело JSON, разобранное `ПрочитатьJSON`.

**Acceptance Scenarios**:

1. **Given** сервер отдаёт `200` и JSON с `Content-Type: application/json; charset=utf-8`,
   **When** скрипт выполняет `Получить` для пути `/api/users`, **Then** `Ответ.КодСостояния = 200`,
   а `Ответ.ПолучитьТелоКакСтроку()` возвращает JSON, который `ПрочитатьJSON` разбирает в структуру.
2. **Given** соединение создано с адресом `https://api.example.com/base/`, **When** запрос
   указывает ресурс `users`, **Then** запрос уходит на `https://api.example.com/base/users`;
   ресурс `/users` — на `https://api.example.com/users` (разрешение как у браузера).
3. **Given** ответ объявляет `charset=windows-1251`, **When** тело читается как строка без
   явной кодировки, **Then** строка декодируется в windows-1251; явный аргумент кодировки
   переопределяет заголовок.
4. **Given** сервер отвечает `404` с телом, **When** скрипт вызывает `Получить`, **Then**
   возвращается `HTTPОтвет` со статусом `404` и телом — это не исключение.
5. **Given** ответ `204 No Content` или `HEAD`-запрос, **When** тело читается как строка,
   **Then** возвращается `Неопределено` — тело считается отсутствующим, но сам ответ и его
   заголовки доступны (не ошибка).

---

### User Story 2 - Скрипт отправляет данные на сервер (Priority: P2)

Разработчик отправляет на бэкенд строку (JSON/форму) или двоичные данные методами
`ОтправитьДляОбработки`, `Записать`, `Удалить`, `Изменить`, `ПолучитьЗаголовки` или
произвольным HTTP-методом. Заголовки запроса задаются в `Запрос.Заголовки`.

**Why this priority**: «Получить данные» часто означает POST/PUT с телом и заголовками;
без этого клиент годится только для чтения.

**Independent Test**: Сервер-эхо возвращает метод, заголовки и тело запроса; BSL-скрипт
отправляет строку в UTF-8 и двоичные данные, сверяет эхо.

**Acceptance Scenarios**:

1. **Given** `Запрос.УстановитьТелоИзСтроки("...")` и `Запрос.Заголовки.Вставить("Content-Type", "application/json")`,
   **When** вызывается `ОтправитьДляОбработки(Запрос)`, **Then** сервер получает метод `POST`,
   заголовок и тело в UTF-8.
2. **Given** тело задано `УстановитьТелоИзДвоичныхДанных`, **When** вызывается `Записать`,
   **Then** сервер получает метод `PUT` и те же байты.
3. **Given** произвольное имя метода `"OPTIONS"`, **When** вызывается `ВызватьHTTPМетод("OPTIONS", Запрос)`,
   **Then** сервер получает `OPTIONS`.
4. **Given** `Удалить` и `Изменить`, **When** они вызваны, **Then** сервер получает `DELETE` и `PATCH`.
5. **Given** `ПолучитьЗаголовки`, **When** сервер вернул заголовки без тела, **Then** `Ответ.Заголовки`
   содержит заголовки сервера, а тело пустое.
6. **Given** тело задано для `GET`/`HEAD`, **When** запрос выполняется, **Then** тело не отправляется
   (как в эталоне: `ContentBodyAllowed`).

### User Story 3 - Понятные ошибки и параметры соединения (Priority: P3)

Разработчик настраивает порт, basic-аутентификацию, таймаут, авто-перенаправление и видит
понятные ошибки на недоступный сервер, неверную схему адреса, неверный тип `Заголовки`
или неподдерживаемый SSL-параметр.

**Why this priority**: Без предсказуемых ошибок отладка на фронте превращается в гадание;
вторично по отношению к самим запросам.

**Independent Test**: Скрипты с неверной схемой `ftp://`, недоступным хостом, `Заголовки`
не-`Соответствие` и переданным SSL-объектом дают локализованные исключения; при
`Пользователь`/`Пароль` сервер видит `Authorization: Basic …`.

**Acceptance Scenarios**:

1. **Given** `Новый HTTPСоединение("ftp://example.com")`, **When** объект создаётся,
   **Then** исключение о недопустимой схеме (эталон: `InvalidArgumentValue`).
2. **Given** недоступный хост, **When** выполняется запрос, **Then** исключение содержит адрес
   и причину, а не «неизвестная ошибка».
3. **Given** `Пользователь`/`Пароль` заданы, **When** выполняется запрос, **Then** отправлен
   заголовок `Authorization: Basic <base64(UTF-8 user:password)>`.
4. **Given** третий аргумент конструктора `Заголовки` — не `Соответствие`, **When** создаётся
   `HTTPЗапрос`, **Then** исключение о неверном типе.
5. **Given** в конструктор соединения передан SSL-объект (не `Неопределено`), **When** объект
   создаётся, **Then** исключение о неподдерживаемом SSL (как в эталоне).

---

### Edge Cases

- Адрес хоста без схемы (`"example.com"`) — считается `http://`; порт из аргумента
  переопределяет порт из URL; нечисловой/отрицательный порт — ошибка.
- Пустой `АдресРесурса` — запрос уходит на корень хоста.
- Ответ с `Content-Encoding: gzip` — платформа распаковывает прозрачно; в `Заголовках`
  не остаётся `Content-Encoding`, `Content-Length` отражает фактический размер (как в эталоне).
- Заголовки запроса с одинаковым именем в разном регистре — отправляется один заголовок
  (последнее значение), как в `Соответствии`.
- Пользователь в браузере: запрещённые браузером заголовки (`User-Agent`, `Cookie`,
  `Content-Length` и т.п.) не отправляются; это ограничение среды, а не ошибка скрипта.
- CORS: кросс-доменный запрос без разрешения бэкенда завершается исключением с причиной;
  same-origin и бэкенд с настроенным CORS работают.
- Синхронность: вызов блокирует страницу до ответа (язык синхронный, `Ждать` не поддерживается).
- Тело ответа большого размера держится в памяти; файловый режим и потоки не поддерживаются.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Движок ДОЛЖЕН предоставлять типы `HTTPСоединение`/`HTTPConnection`,
  `HTTPЗапрос`/`HTTPRequest`, `HTTPОтвет`/`HTTPResponse` с русскими и английскими именами
  (конституция, принцип I).
- **FR-002**: `HTTPЗапрос` создаётся без аргументов либо с `(АдресРесурса, Заголовки)`;
  `Заголовки` обязаны быть `Соответствие`/`Map`, иначе — исключение о неверном типе.
- **FR-003**: `HTTPЗапрос` ДОЛЖЕН поддерживать свойства `АдресРесурса`/`ResourceAddress`,
  `Заголовки`/`Headers` и методы `УстановитьТелоИзСтроки`/`SetBodyFromString`,
  `ПолучитьТелоКакСтроку`/`GetBodyAsString`, `УстановитьТелоИзДвоичныхДанных`/
  `SetBodyFromBinaryData`, `ПолучитьТелоКакДвоичныеДанные`/`GetBodyAsBinaryData`.
  Кодировка по умолчанию — UTF-8 с BOM (эталон), третий аргумент `ИспользоватьBOM` учитывается.
- **FR-004**: `HTTPСоединение` создаётся с `(Сервер, Порт, Пользователь, Пароль, Прокси,
  Таймаут, SSL, ИспользоватьАутентификациюОС)`; обязателен только `Сервер`.
  Схема адреса — только `http`/`https` (иначе исключение); отсутствие схемы означает `http`.
- **FR-005**: `HTTPСоединение` ДОЛЖЕН предоставлять свойства `Сервер`/`Host`, `Порт`/`Port`,
  `Пользователь`/`User`, `Пароль`/`Password`, `Прокси`/`Proxy` (для нас — всегда `Неопределено`),
  `Таймаут`/`Timeout`, `РазрешитьАвтоматическоеПеренаправление`/`AllowAutoRedirect`,
  `ИспользоватьАутентификациюОС`/`UseOSAuthentication`.
- **FR-006**: `HTTPСоединение` ДОЛЖЕН предоставлять методы `Получить`/`Get`,
  `ОтправитьДляОбработки`/`Post`, `Записать`/`Put`, `Удалить`/`Delete`, `Изменить`/`Patch`,
  `ПолучитьЗаголовки`/`Head`, `ВызватьHTTPМетод`/`CallHTTPMethod` с семантикой эталона.
- **FR-007**: Адрес запроса ДОЛЖЕН разрешаться относительно адреса соединения как URL
  (ведущий `/` — от корня хоста, относительный путь — от пути соединения).
- **FR-008**: Заголовки запроса из `Заголовки` ДОЛЖНЫ передаваться серверу; заголовки ответа
  ДОЛЖНЫ быть доступны в `Ответ.Заголовки` как `Соответствие` (имена в регистре сервера).
- **FR-009**: Тело запроса ДОЛЖНО отправляться для всех методов, кроме `GET`, `HEAD`, `CONNECT`;
  строковое тело кодируется в UTF-8 (или указанной кодировкой), двоичное — байт-в-байт.
- **FR-010**: `HTTPОтвет` ДОЛЖЕН предоставлять `КодСостояния`/`StatusCode`, `Заголовки`/`Headers`,
  `ПолучитьТелоКакСтроку(Кодировка)`/`GetBodyAsString`, `ПолучитьТелоКакДвоичныеДанные`/
  `GetBodyAsBinaryData`, `Закрыть`/`Close`. Строка декодируется по `charset` из `Content-Type`,
  по умолчанию UTF-8; если тело отсутствует (`204`, `304`, `HEAD`, `Content-Length: 0`) —
  возвращается `Неопределено`.
- **FR-011**: Ответы с любым статусом (2xx, 3xx, 4xx, 5xx) возвращаются как `HTTPОтвет`;
  исключение — только при сетевой ошибке/недоступности сервера.
- **FR-012**: При непустых `Пользователь`/`Пароль` ДОЛЖЕН отправляться заголовок
  `Authorization: Basic <base64 UTF-8>`.
- **FR-013**: Ошибки ДОЛЖНЫ быть локализованными и содержать адрес запроса и причину;
  ошибки конфигурации (схема, порт, тип `Заголовки`, SSL) обнаруживаются до сети.
- **FR-014**: Gzip-ответ ДОЛЖЕН распаковываться прозрачно; `Content-Encoding` удаляется из
  `Заголовков`, `Content-Length` равен фактическому размеру.
- **FR-015**: В браузере транспорт ДОЛЖЕН использовать только браузерные API и работать в
  основном потоке синхронно; в Node (CLI/тесты) — вспомогательный транспорт с той же
  BSL-поверхностью. Ядро не импортирует `node:*` и не обращается к DOM.
- **FR-016**: При отсутствии транспорта (окружение без HTTP) создание соединения или запрос
  ДОЛЖНЫ давать понятное исключение, а остальная стандартная библиотека продолжает работать.
- **FR-017**: Вызов `Закрыть` освобождает ресурсы и идемпотентен; повторное чтение после
  закрытия даёт `Неопределено` (тело освобождено), код состояния и заголовки остаются.

### Key Entities

- **HTTPСоединение** — параметры сервера (схема, хост, порт, учётные данные, таймаут,
  перенаправление) и операции над ресурсами.
- **HTTPЗапрос** — адрес ресурса, заголовки и тело (строка или двоичные данные).
- **HTTPОтвет** — статус, заголовки и тело ответа; умеет отдавать тело строкой или байтами.
- **Транспорт запроса** — средовая операция «выполнить HTTP-запрос синхронно», подменяемая
  в тестах и различающаяся между браузером и Node.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: BSL-скрипт на странице получает JSON с бэкенда и печатает значение поля —
  приёмка проходит в браузере (CORS разрешён) и в Node-тесте с локальным сервером.
- **SC-002**: Все семь методов соединения плюс произвольный метод доходят до сервера
  с ожидаемым HTTP-методом и телом (проверяется эхо-сервером, 100% сценариев).
- **SC-003**: Ответы `2xx/3xx/4xx/5xx` неразличимы по способу получения (всегда `HTTPОтвет`),
  а сетевые ошибки дают исключение — 100% проверенных случаев.
- **SC-004**: `pnpm typecheck` и `pnpm test` зелёные; `dist/onescript.js` собирается и содержит
  HTTP-объекты; новых зависимостей нет.

## Assumptions

- Семантика синхронная, как в эталоне: движок не поддерживает `Асинх`/`Ждать`, поэтому
  HTTP-вызов блокирует исполнение (в браузере — до ответа сервера).
- Браузер — целевая среда; ограничения sync XHR (CORS, запрещённые заголовки, авто-редирект,
  отсутствие таймаута) считаются ограничениями продукта и документируются.
- Node-транспорт нужен для CLI и тестов; он не влияет на браузерное поведение.
- Прокси (`ИнтернетПрокси`), клиентские SSL-сертификаты, файловое тело
  (`УстановитьИмяФайлаТела`), потоки (`ПолучитьТелоКакПоток`) и временные файлы для больших
  тел — вне scope: в браузере они нереализуемы или не нужны для «получить данные с бэка».
- Тело ответа и запроса помещается в память; целевой размер — до нескольких мегабайт.
- Кодировка по умолчанию — UTF-8; поддерживаются кодировки, доступные `TextDecoder`
  (utf-8, utf-16, windows-1251 и т.п.).
- Бэкенд для кросс-доменных запросов настроен на CORS; same-origin запросы работают без
  дополнительной настройки.
