# Data Model: События BSL

**Date**: 2026-11-11 | **Plan**: [plan.md](plan.md) | **Spec**: [spec.md](spec.md)

## 1. AST-узлы

### AddHandlerStatement / RemoveHandlerStatement

| Поле | Тип | Смысл | Валидация |
|---|---|---|---|
| `kind` | `'AddHandlerStatement' \| 'RemoveHandlerStatement'` | Операция | — |
| `pos` | `Pos` | Позиция первого токена | обязательно |
| `eventSource` | `Expression` | Объект-источник события | вычисляется в рантайме; должен дать `BslObject` |
| `eventName` | `Expression` | Имя события | `StringLiteral` (из свойства) или индексное выражение (динамическое имя) |
| `handlerTarget` | `Expression \| null` | Объект, чей метод вызывать | `null` → текущий объект скрипта (`ЭтотОбъект`) |
| `handlerMethod` | `Expression` | Имя метода | `StringLiteral` или индексное выражение |

Инварианты AST: `eventName` и `handlerMethod` — уже нормализованные выражения; литералы
создаёт парсер, поэтому рантайм не различает «статическую» и «динамическую» форму.

## 2. Реестр подписок (`src/runtime/events.ts`)

### EventProcessor

| Поле | Тип | Смысл |
|---|---|---|
| `handlers` | `Map<BslObject, Map<string, Handler[]>>` | источник → (имя события в нижнем регистре) → упорядоченный список обработчиков |

Операции:

- `add(source: BslObject, eventName: string, target: BslObject, method: string): void`
- `remove(source: BslObject, eventName: string, target: BslObject, method: string): void`
- `raise(source: BslObject, eventName: string, args: Value[]): void`

### Handler

| Поле | Тип | Смысл |
|---|---|---|
| `target` | `BslObject` | Объект, у которого вызывается метод |
| `method` | `string` | Имя метода в исходном регистре |

Идентичность обработчика: `(target по ссылке, method.toLowerCase())`.

### Инварианты реестра

1. **Порядок**: обработчики вызываются в порядке `add`; удаление не меняет порядок остальных.
2. **Дедупликация**: повторный `add` той же идентичности — no-op (не второй вызов).
3. **Отписка без подписки** — no-op без ошибки.
4. **Отсутствие проверки события**: `raise` для события без обработчиков молча завершается;
   реестр не знает, «существует» ли событие у источника.
5. **Снимок при вызове**: `raise` копирует список перед обходом (подписка/отписка внутри
   обработчика не искажает текущий обход).
6. **Изоляция источников**: события с одинаковым именем у разных источников независимы.

### Валидация на границах

| Ситуация | Поведение |
|---|---|
| `target.hasMethod(method) === false` (объект умеет проверять) | ошибка «Метод объекта не обнаружен (<метод>)», подписка не создаётся |
| `target` не `BslObject` | ошибка типа значения (через `isBslObject`) |
| `source` не `BslObject` | ошибка типа значения |
| имя события/метода — не строка (при динамической форме) | `toStringValue(...)` как в остальном движке |

## 3. Объект-модуль (`src/runtime/script-object.ts`)

### ScriptModuleObject implements BslObject

| Член | Поведение |
|---|---|
| `typeName` | `'Сценарий'` |
| `callMethod(name, args)` | метод существует и экспортный → `interpreter.invokeMethod(name, args)`; иначе «Метод объекта не обнаружен (<name>)» |
| `hasMethod(name)` | `true` только для экспортных методов модуля |
| `getProp` / `setProp` / `getIndex` / `setIndex` | ошибка с описанием («Свойство … недоступно для типа Сценарий») |

`shortcut: доступ к модульным переменным через ЭтотОбъект не поддержан, добавить вместе с рефлексией (T45)`.

### Связь с существующими сущностями

| Существующая сущность | Роль |
|---|---|
| `Interpreter` | Владеет `Ctx` модуля; создаёт `ScriptModuleObject` лениво; выполняет операторы и встроенные `ВызватьСобытие`/`ЭтотОбъект` |
| `GlobalContext` | Владеет `EventProcessor` (`events`), поэтому подписки общие для всех интерпретаторов процесса/теста |
| `BslObject` | Контракт «объект с методами»; получает опциональный `hasMethod` |
| `BslScript` | Загруженный сценарий может быть и источником события, и целью обработчика (он реализует `BslObject`) |
| `BslArray` | Второй аргумент `ВызватьСобытие` — параметры события (через `iterate()`) |
