# Contract: вывод ошибок в CLI и браузере

**Feature**: `specs/020-runtime-error-info` | **Тип**: наблюдаемое поведение хостов

## CLI (Node)

- Ошибка исполнения печатается в **stderr**, stdout не меняется.
- Формат:

```
<ИмяМодуля>:<НомерСтроки>: <Описание>
Стек вызовов:
  <Метод> (<ИмяМодуля>:<НомерСтроки>)
  ...
```

- Код возврата — `1` (как сейчас). Ошибки использования CLI (`--help`, нет файла и т.п.) не
  меняются.
- Скрипт из stdin: `ИмяМодуля` = `<stdin>`.
- Ошибка в импортированном модуле: `ИмяМодуля` и строки — из этого модуля; стек содержит
  цепочку вызовов.
- Если позиция недоступна (ошибка вне BSL, например чтение файла до исполнения) — печатается
  прежнее сообщение без позиции (деградация без падения).

## Браузер

- Ошибка блока `<script type="text/osjs">` печатается в `console.error` тем же форматом.
- `ИмяМодуля`:
  - внешний `.osjs` по `src` — абсолютный URL файла;
  - inline-блок — `<URL страницы>#<id>` или `<URL страницы>#block<N>` (N — 1-based порядок
    среди блоков `text/osjs` в документе), если `id` нет.
- Ошибка одного блока по-прежнему не останавливает остальные блоки.
- Ошибки декларативных обработчиков (`data-os-*`) и BSL-событий печатаются тем же форматом
  (включая позицию обработчика).

## Необработанные ошибки `Обещаний` и фоновых заданий

- Необработанная ошибка `Обещания` печатается в `console.error`/stderr тем же форматом.
- `ФоновоеЗадание.ИнформацияОбОшибке` отдаёт те же свойства и стек, что обычный
  `ИнформацияОбОшибке`; формат печати — общий.

## Неизменность

- Тексты `ОписаниеОшибки()` и `ИнформацияОбОшибке().Описание` — прежние.
- Парсерные ошибки (`Ошибка разбора: ...`) — без изменений.
- `console.log` из `Сообщить()` — без изменений.
