# Data Model: Позиция, модуль и BSL-стек в ошибках исполнения

**Feature**: `specs/020-runtime-error-info` | **Date**: 2026-11-24

## Сущности

### ErrorSnapshot (внутренняя, не BSL-объект)

Снимок ошибки, снимается в момент возникновения и переносится через `Попытка/Исключение`,
перевыброс, async и фоновые задания.

| Поле | Тип | Правила |
|---|---|---|
| `description` | `string` | Текст ошибки; ровно тот, что сейчас попадает в `ОписаниеОшибки()` |
| `module` | `string` | Идентификатор источника (см. «Идентификаторы источников») |
| `line` | `number` | 1-based номер строки возникновения |
| `sourceLine` | `string` | Текст исходной строки; `""`, если текст недоступен |
| `frames` | `FrameSnapshot[]` | Снимок BSL-стека, **изнутри наружу** (первый — кадр возникновения) |

### FrameSnapshot (внутренняя)

| Поле | Тип | Правила |
|---|---|---|
| `method` | `string` | Имя BSL-метода; маркеры: `<модуль>` (тело модуля), `<Выполнить>`, `<Вычислить>`, `<обработчик>` (если у события нет имени метода) |
| `module` | `string` | Идентификатор источника кадра |
| `line` | `number` | 1-based строка, исполнявшаяся в кадре на момент ошибки |

### ИнформацияОбОшибке / ErrorInfo (BSL-объект, `BslErrorInfo`)

| Свойство | Тип | Доступ | Алиас EN | Примечание |
|---|---|---|---|---|
| `Описание` | `Строка` | чтение | `Description` | Не меняется |
| `ИмяМодуля` | `Строка` | чтение | `ModuleName` | `""` для пустой ошибки |
| `НомерСтроки` | `Число` | чтение | `LineNumber` | 0 для пустой ошибки |
| `ИсходнаяСтрока` | `Строка` | чтение | `SourceLine` | `""`, если недоступна |
| `Причина` | `Null` | чтение | `Cause` | Всегда `Null` (вне объёма) |

| Метод | Параметры | Возвращает | Алиас EN |
|---|---|---|---|
| `ПодробноеОписаниеОшибки` | — | `Строка` | `DetailErrorDescription`, `DetailedDescription` (эталонный алиас) |
| `ПолучитьСтекВызовов` | — | `КоллекцияКадровСтекаВызовов` (индексация 0-based, `Для Каждого`, `Количество()`) | `GetStackTrace` |

> Совместимость: `ПодробноеОписаниеОшибки` сейчас доступно как свойство (возвращает
> `Описание`). Оставляем свойство как алиас, но метод — основной 1С-совместимый способ;
> оба возвращают подробное описание со стеком. Пустая ошибка (вне блока `Исключение`):
> `Описание` = `""`, `НомерСтроки` = 0, `ИмяМодуля`/`ИсходнаяСтрока` = `""`,
> `ПолучитьСтекВызовов()` = пустая коллекция.

### КадрСтекаВызовов / CallStackFrame (BSL-объект)

| Свойство | Тип | Доступ | Алиас EN |
|---|---|---|---|
| `Метод` | `Строка` | чтение | `Method` |
| `НомерСтроки` | `Число` | чтение | `LineNumber` |
| `ИмяМодуля` | `Строка` | чтение | `ModuleName` |

`typeName` = `КадрСтекаВызовов`; `ТипЗнч` возвращает его; `Тип("CallStackFrame")`
канонизируется (по образцу `ИнформацияОбОшибке`/`ErrorInfo`).

### КоллекцияКадровСтекаВызовов / CallStackFramesCollection (BSL-объект)

Возврат `ПолучитьСтекВызовов()`. Живёт в `src/runtime` (не stdlib), чтобы не нарушать
направление слоёв.

| Член | Вид | Тип | Примечание |
|---|---|---|---|
| `Количество` | метод | `Число` | `Count` |
| `[i]` | индексация | `КадрСтекаВызовов` | 0-based; выход за диапазон — исключение |
| `Для Каждого` | итерация | `КадрСтекаВызовов` | порядок — изнутри наружу |

`typeName` = `КоллекцияКадровСтекаВызовов`; `Тип("CallStackFramesCollection")`
канонизируется. Пустая ошибка — пустая коллекция (в эталоне `Неопределено`; расхождение
фиксируется в `docs/status.md`).

## Идентификаторы источников (`ИмяМодуля`)

| Ситуация | Идентификатор | Пример |
|---|---|---|
| Главный скрипт Node (CLI) | путь, переданный в `run` (как аргумент CLI) | `script.osjs` |
| Главный скрипт Node (stdin) | `<stdin>` | `<stdin>` |
| Импортированный модуль/класс (Node) | разрешённый путь | `/app/lib.osjs` |
| Главный скрипт (библиотека/тесты) | `RunOptions.path`, иначе `<скрипт>` | `/app/main.os` |
| Внешний `.osjs` в браузере | абсолютный URL | `http://localhost/app.osjs` |
| Inline-блок в браузере | URL страницы + `#<id>` или `#block<N>` | `http://localhost/app/#block2` |
| Код `Выполнить` / `Вычислить` | `<Выполнить>` / `<Вычислить>` | `<Выполнить>` |
| Динамический сценарий (`ЗагрузитьСценарийИзСтроки`) | имя сценария, если задано; иначе `<скрипт>` | `МойСценарий` |

## Машина состояний ошибки

```
возникновение (throw)
  ├─ ВызватьИсключение <значение>  → snapshot = {описание значения, текущая позиция, текущий стек}
  ├─ ошибка интерпретатора/stdlib  → snapshot = {текст, текущая позиция, текущий стек}
  └─ ВызватьИсключение; (без арг.) → snapshot = текущий snapshot из Попытка (без изменений)
обработка (Исключение)
  ├─ ctx.currentError = snapshot
  ├─ ОписаниеОшибки()      → snapshot.description
  ├─ ИнформацияОбОшибке()  → объект над snapshot
  └─ ВызватьИсключение <ИнформацияОбОшибке> → snapshot перевыбрасываемого объекта
выход из Исключение → восстановить предыдущий ctx.currentError
```

Правила:

- Снимок снимается **один раз** — в момент возникновения; перевыброс его не перезаписывает.
- `ВызватьИсключение "новый текст"` — новый снимок в позиции оператора перевыброса.
- Ошибки stdlib (обычный `Error`) аннотируются на границе ближайшего BSL-оператора
  (позиция оператора вызова), если снимка ещё нет.
- `Попытка` ловит любые `Error` (как сейчас); сигналы `Возврат/Прервать/Продолжить/Перейти`
  снимка не получают и не меняют текущую ошибку.

## Стек

- Порядок: изнутри наружу (текущий кадр первым) — см. research.md.
- Включаются: тело модуля верхнего уровня, методы BSL, конструкторы, обработчики событий,
  динамические кадры (`<Выполнить>`/`<Вычислить>`), кадры импортированных модулей.
- Не включаются: кадры stdlib/платформы (не BSL), служебные обёртки хоста.
- Глубина ограничена фактической глубиной BSL-вызовов; снимок — копия массива кадров.

## Формат подробного описания (фиксируется тестом)

```
<Описание>
Стек вызовов:
  <Метод> (<ИмяМодуля>:<НомерСтроки>)
  ...
```

Для пустой ошибки — пустая строка.
