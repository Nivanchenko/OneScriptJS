# Feature Specification: Загрузка сценария по ссылке — `<script type="text/osjs" src="…">`

**Feature Branch**: `feat/src_import`

**Created**: 2026-11-12

**Status**: Implemented (runtime + тесты + пример; ручная приёмка в браузере выполнена владельцем)

**Input**: Решение владельца проекта: «у нас была заготовка спеки на загрузку скриптов по
ссылке `<script type="text/osjs" src="path.osjs">`? Давай сделаем». Заготовка — резерв
`src` в спеке 016 (FR-010, Clarifications), где атрибут был явно отложен до будущей версии.

## Context

Спека 016 сделала каноном встраивание `<script type="text/osjs">`, но в v1 поддерживала
только inline-код: атрибут `src` игнорировался и был зарезервирован (FR-010). Это
неудобно для реальных страниц: BSL-код хочется держать отдельным `.osjs`-файлом (в
репозитории, кешируемым, версионируемым, анализируемым редактором как обычный `.osjs`),
а не вклеивать в HTML.

Внешний файл по ссылке — привычная семантика HTML (`<script src>`): страница ссылается
на файл, браузер скачивает его и исполняет. Для OneScriptJS это значит: `src` блока
загружается через `fetch` (в браузере), тело файла исполняется в том же контексте, что и
inline-блок, а inline-содержимое тега при наличии `src` игнорируется. Формат файла —
`.osjs`; грамматика и стандартная библиотека не меняются.

## Clarifications

### Session 2026-11-12

- Q: Что делать, если у блока одновременно есть `src` и inline-содержимое? →
  A: `src` побеждает, inline-содержимое игнорируется (как у `<script src>` в HTML).
- Q: Что делать с пустым/пробельным `src`? → A: Считать, что `src` нет, и исполнять
  inline-содержимое (не скачивать страницу и не падать).
- Q: Относительно чего разрешается `src`? → A: Относительно `document.baseURI` (как
  `#Использовать` в спеке 016), включая абсолютные и кросс-доменные URL.
- Q: Относительно чего разрешается `#Использовать` внутри внешнего файла? → A:
  Относительно URL самого файла, а не страницы: файл — самостоятельный сценарий.
- Q: Виден ли внешний файл в `ТекущийСценарий()`? → A: Да: `Источник` — абсолютный URL
  файла, `Каталог`/`Имя` — из него (URL в браузерной нотации, percent-encoded).
- Q: Кешируются ли внешние файлы между блоками/запусками? → A: Нет. Каждый блок с `src`
  исполняется один раз за загрузку страницы в своём контексте; два блока с одним URL —
  два независимых исполнения. HTTP-кеш браузера — забота HTTP, не движка.
- Q: Что при ошибке скачивания? → A: `console.error` для этого блока; остальные блоки
  исполняются, `id`-контекст неуспешного блока не регистрируется.
- Q: Меняются ли редакторные инструменты (спеки 015/018)? → A: Нет. Внешний файл —
  отдельный `.osjs`-документ, его анализирует существующий слой `.osjs`; анализ содержимого
  внешнего файла из HTML — вне scope.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Код в отдельном `.osjs` подключается ссылкой (Priority: P1)

Разработчик держит BSL в файле `app.osjs` и подключает его к странице тегом
`<script type="text/osjs" src="app.osjs"></script>`. При открытии страницы движок
скачивает файл, исполняет его тело в свежем контексте (как inline-блок) и продолжает
исполнять остальные блоки в порядке документа.

**Why this priority**: Это суть задачи — без загрузки по ссылке атрибут бесполезен.

**Independent Test**: страница с одним блоком `src` (fetch замокан) исполняет код файла;
inline-содержимое того же тега не исполняется; fetch-запрос идёт на URL, разрешённый
от `document.baseURI`.

**Acceptance Scenarios**:

1. **Given** страница `http://host/app/index.html` и блок `src="app.osjs"`, **When**
   страница открыта, **Then** скачивается `http://host/app/app.osjs` и исполняется его код.
2. **Given** блок с `src` и непустым inline-содержимым, **When** страница открыта,
   **Then** исполняется только внешний файл, inline-содержимое игнорируется.
3. **Given** блок с пустым/пробельным `src`, **When** страница открыта, **Then** fetch не
   выполняется, исполняется inline-содержимое.

---

### User Story 2 - Внешний файл — самостоятельный сценарий (Priority: P2)

Внешний `.osjs` может иметь `#Использовать`; импорты разрешаются от URL файла, а
`ТекущийСценарий()` внутри него указывает на этот файл, а не на страницу. `id` блока
регистрирует контекст для декларативных обработчиков так же, как у inline-блока.

**Why this priority**: Без этого внешний файл нельзя переиспользовать как модуль-сценарий:
импорты и рефлексия указывали бы не туда.

**Independent Test**: внешний файл в `scripts/app.osjs` импортирует `lib/Модуль.osjs`
(скачивается `scripts/lib/Модуль.osjs`); `ТекущийСценарий().Источник` равен URL файла;
кнопка `data-os-script="app"` исполняется в контексте внешнего блока.

**Acceptance Scenarios**:

1. **Given** внешний файл с `#Использовать "lib/Модуль.osjs"`, **When** он исполняется,
   **Then** модуль скачивается относительно URL файла, а не страницы.
2. **Given** внешний блок с `id="app"`, **When** срабатывает `data-os-script="app"`,
   **Then** обработчик видит переменные внешнего файла.
3. **Given** внутри внешнего файла вызывается `ТекущийСценарий()`, **Then**
   `.Источник` — абсолютный URL файла.

---

### User Story 3 - Ошибки изолированы, порядок сохранён (Priority: P3)

Если файл не скачался (404, сеть, CORS) или содержит ошибку разбора/рантайма, ошибка
уходит в `console.error` этого блока, остальные блоки исполняются; порядок документа не
нарушается даже при медленной загрузке.

**Why this priority**: Страница не должна «белеть» из-за одного плохого файла; порядок —
существующий контракт спек 016.

**Independent Test**: страница «404-блок → inline-блок»: inline исполняется, ошибка в
`console.error` содержит URL; страница «медленный src-блок → inline-блок»: вывод в
порядке документа.

**Acceptance Scenarios**:

1. **Given** `src` отдаёт 404, **When** страница открыта, **Then** `console.error`
   содержит URL и статус, следующий блок исполняется.
2. **Given** первый блок с медленным `src`, **When** страница открыта, **Then** второй
   блок исполняется после первого (документный порядок).
3. **Given** во внешнем файле ошибка разбора, **When** страница открыта, **Then**
   `console.error` с позицией (и подсказкой для обрыва `</script>`), остальные работают.

### Edge Cases

- **404/сетевая ошибка/CORS** — ошибка блока в `console.error` (`Не удалось загрузить
  '<url>': …`), остальные блоки исполняются.
- **Некорректный URL в `src`** (например, `http://[`) — `new URL` бросает; ошибка блока в
  `console.error`, страница не падает.
- **Пустой/пробельный `src`** — inline-режим (без fetch).
- **Один URL в двух блоках** — два независимых исполнения (кеша нет).
- **BOM/`#!` в начале внешнего файла** — обрабатываются как у любого сценария
  (`preloadModuleSources` снимает BOM).
- **`#Использовать` внутри внешнего файла** — от URL файла; ошибка загрузки импорта —
  в `console.error` блока.
- **Кросс-доменный `src`** — работает, если сервер отдаёт CORS; иначе ошибка блока.
- **CSP** — data block по-прежнему не исполняется браузером; скачивание подчиняется
  `connect-src` (не `script-src`). Политика страницы — ответственность автора.
- **Unicode-имена файлов** — `ТекущийСценарий().Источник` в URL-нотации (percent-encoded),
  как у любого URL.
- **`src` + inline + `id`** — `id` регистрирует контекст после успешной загрузки; при
  ошибке контекст не регистрируется.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Блок `script[type="text/osjs"]` с непустым атрибутом `src` ДОЛЖЕН загружать
  исходник по этому URL и исполнять его; inline-содержимое блока MUST быть проигнорировано.
- **FR-002**: `src` ДОЛЖЕН разрешаться относительно `document.baseURI` (относительные,
  абсолютные и кросс-доменные URL); пустой/пробельный `src` MUST считаться отсутствующим.
- **FR-003**: Внешний файл исполняется в свежем контексте блока; `#Использовать` внутри
  него ДОЛЖЕН разрешаться относительно URL файла, а `ТекущийСценарий().Источник` — указывать
  на URL файла.
- **FR-004**: Порядок исполнения MUST оставаться документным: блоки загружаются и
  исполняются последовательно, медленная загрузка не переупорядочивает вывод.
- **FR-005**: `id` внешнего блока ДОЛЖЕН регистрировать контекст для `data-os-*`
  обработчиков так же, как у inline-блока (дубликаты — «последний побеждает»).
- **FR-006**: Ошибки загрузки (HTTP/сеть/URL), разбора и рантайма MUST попадать в
  `console.error` этого блока и MUST NOT прерывать остальные блоки; `id`-контекст
  неуспешного блока не регистрируется.
- **FR-007**: Внешние файлы MUST NOT кешироваться движком: каждый блок исполняется ровно
  один раз за загрузку страницы, два блока с одним URL — независимые исполнения.
- **FR-008**: Изменение MUST затрагивать только браузерную обёртку
  (`src/browser/onescript.ts`), тесты, примеры и документацию; ядро, `src/node`, CLI,
  `.osjs`-формат и stdlib не меняются; новых зависимостей нет.
- **FR-009**: Примеры (`examples/`) и документация (README, `docs/status.md`,
  `docs/architecture.md`) ДОЛЖНЫ описывать и демонстрировать загрузку по ссылке;
  спека 016 (FR-010, «src не поддерживается») ДОЛЖНА быть помечена как расширенная этой
  спекой.
- **FR-010**: Браузерные тесты ДОЛЖНЫ покрывать: загрузку и исполнение внешнего файла,
  приоритет `src` над inline, пустой `src`, импорты от URL файла, `ТекущийСценарий`,
  `data-os-*` по `id`, документный порядок при медленной загрузке, изоляцию ошибок
  (404 и некорректный URL), демо-страницу `examples/external.html`.

### Key Entities

- **Блок с `src`**: `script[type="text/osjs"][src]`; источник — результат `fetch` по URL,
  разрешённому от `document.baseURI`.
- **Внешний сценарий**: `.osjs`-файл, исполняемый как тело блока; URL — его `Источник`
  для `ТекущийСценарий` и база для `#Использовать`.
- **Контекст блока**: свежий `GlobalContext`, регистрируется по `id` после успешной
  загрузки.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Страница с `<script type="text/osjs" src="app.osjs">` исполняет код файла;
  inline-содержимое того же тега не исполняется (100% проверено тестом).
- **SC-002**: `#Использовать` во внешнем файле резолвится от URL файла (проверено порядком
  fetch-запросов), `ТекущийСценарий().Источник` равен URL файла.
- **SC-003**: Ошибка одного внешнего блока (404) не мешает остальным; порядок документа
  сохранён при искусственно медленной загрузке.
- **SC-004**: `id`+`data-os-*` работают для внешнего блока.
- **SC-005**: Демо `examples/external.html` исполняется в автотесте (`browser-demo`);
  ручная проверка в реальном браузере выполнена владельцем — работает.
- **SC-006**: `pnpm typecheck && pnpm test` зелёные; браузерный бандл собирается;
  ядро/Node/CLI не изменены (diff ограничен браузерной обёрткой, тестами, примерами,
  документацией и спеками).

## Out of Scope

- Редакторный анализ содержимого внешнего файла из HTML (внешний `.osjs` анализируется
  как отдельный `.osjs`-документ существующим слоем).
- Динамическая вставка блоков/MutationObserver (как в 016).
- Кеширование исполнения, import maps, `defer`/`async`-семантика, ES-модули.
- Изменение CSP-политики и обхода CORS (ошибки CORS — обычная ошибка загрузки блока).
- Изменение `.osjs`-формата, Node/CLI и stdlib.
- Автоматическая миграция страниц.

## Assumptions

- Семантика `<script src>` в HTML — источник решения: `src` побеждает inline-содержимое.
- Внешний файл — обычный `.osjs`-сценарий: формат, грамматика и stdlib не меняются.
- `fetch` есть во всех целевых браузерах; CORS — обычное HTTP-ограничение, не ослабляем.
- `document.baseURI` — та же база, что у `#Использовать` inline-блоков (спека 016).
