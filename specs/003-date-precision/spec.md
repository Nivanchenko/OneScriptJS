# Feature Specification: Точность и арифметика дат 1С

**Feature Branch**: `feature/speckit_intergation`

**Created**: 2026-11-11

**Status**: Draft

**Input**: Задача T40b из `docs/plan.md`: даты 1С имеют точность 1/10000 секунды, а рантайм использует JS `Date` (миллисекунды). Нужна модель «тиков» и корректная арифметика дат.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Арифметика дат как в 1С (Priority: P1)

Разработчик прибавляет к дате число секунд и вычитает одно число из другого, получая
ожидаемые значения: `Дата + 1` — следующая секунда, `Дата - Дата` — число секунд с дробной
частью. Недопустимые комбинации (дата + дата, число + дата, дата * число) дают ошибку
преобразования, а не склейку строк.

**Why this priority**: Сегодня `Дата + 1` превращается в конкатенацию строк, а `Дата - Дата`
падает. Это самый заметный и ломающий сценарий, ради которого нужна модель дат.

**Independent Test**: Скрипт строит две даты, прибавляет/вычитает секунды и даты, печатает
результаты; проверяются значения и ошибки для недопустимых операций.

**Acceptance Scenarios**:

1. **Given** дата `15:30:45`, **When** `Дата + 1`, **Then** результат — `15:30:46`; `Дата - 1` — `15:30:44`.
2. **Given** две даты, **When** `Дата - Дата`, **Then** возвращается число секунд (дробное, со знаком), а не ошибка.
3. **Given** дата и дата, **When** `Дата + Дата`, **Then** ошибка преобразования к числу.
4. **Given** число и дата, **When** `1 + Дата`, **Then** ошибка преобразования к числу.

---

### User Story 2 - Точность и нормализация (Priority: P2)

Разработчик оперирует долями секунды: сравнение и равенство дат происходят по тикам
1/10000 секунды, лишняя точность нормализуется «половина от нуля», а отображение доли
отбрасывает, не округляя.

**Why this priority**: Без тиков неверны сравнения и разности на малых дельтах; без правил
нормализации — расходится поведение при граничных значениях (0.00005, 0.00015).

**Independent Test**: Разность дат с дельтой 0.00015 секунды равна 0.0002; дата + 0.00004 при
сравнении равна исходной; `Строка` и `Формат` долей не показывают.

**Acceptance Scenarios**:

1. **Given** дата + 0.00005, **When** вычисляется разность с базой, **Then** результат 0.0001 (half-away-from-zero).
2. **Given** дата + 0.00004, **When** сравнивается с базой, **Then** даты равны.
3. **Given** дата + 0.123, **When** применяется `Строка`, **Then** результат совпадает со строкой базовой даты.

---

### User Story 3 - Компоненты даты и функции (Priority: P3)

Разработчик получает компоненты (`Год`, `Месяц`, `День`, `Час`, `Минута`, `Секунда`),
прибавляет месяцы с прижатием дня, конструирует даты из строки или компонентов и работает с
текущим временем и часовыми поясами.

**Why this priority**: Без компонент и конструктора модель дат нельзя ни проверить, ни
использовать; но они вторичны по отношению к арифметике.

**Independent Test**: `Дата(1, 1, 1)` даёт `01.01.0001`, `ДобавитьМесяц(Дата(2024,1,31), 1)` —
`29.02.2024`, `ТекущаяДата()` отличается от `ТекущаяУниверсальнаяДата()` на смещение зоны.

**Acceptance Scenarios**:

1. **Given** `Дата(2024, 1, 31)`, **When** `ДобавитьМесяц(…, 1)`, **Then** результат `29.02.2024` (день прижат к концу месяца).
2. **Given** `Дата(1, 1, 1)`, **When** печатается `Строка`, **Then** `01.01.0001 0:00:00`.
3. **Given** строка `"20260201153045"`, **When** `Дата(строка)`, **Then** разобрана дата `01.02.2026 15:30:45`.
4. **Given** `ТекущаяДата()` и `ТекущаяУниверсальнаяДата()`, **When** вычисляется разность, **Then** она равна смещению часового пояса.

### Edge Cases

- Разность `(База + 0.00005) - База` = 0.0001; `(База + 0.00004)` равна базе.
- Разность `(База + 0.00015) - База` = 0.0002 и `(База + 0.00016) - База` = 0.0002 (half-away).
- `(База - 0.00005) - База` = −0.0001; `(База + 0.5) - База` = 0.5 и не равно `Цел()` от него.
- `(База + 0.00006)` равно `(База + 0.0001)`; `(База + 0.00016)` не равно `(База + 0.0001)`.
- `Формат(дата, "ДФ=сс")` = `"45"`; `Формат(дата, "ДФ=ггггММддЧЧммсс")` = `"20260201153045"`.
- `Дата + Дата`, `Число + Дата`, `Дата * Число` — ошибка преобразования к числу.
- `ДобавитьМесяц(Дата(2024, 1, 31), 1)` = 29.02.2024; `ДобавитьМесяц(Дата(2024, 3, 31), -1)` = 29.02.2024.
- Пустая дата (нули в строке) — `01.01.0001`; `Формат` с `ЧГ=0` даёт пустую строку.
- JSON-запись даты — наивный ISO без миллисекунд и без `Z` (поведение меняется относительно сегодняшнего).
- Годы меньше 100 (`Дата(1,1,1)`) не должны сдвигаться на 1900 (текущий дефект).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Внутренняя модель даты MUST хранить точность 1/10000 секунды; все значения MUST нормализоваться к этому шагу с округлением half-away-from-zero.
- **FR-002**: `Дата + Число` и `Дата - Число` MUST прибавлять/вычитать секунды (аргумент округляется до 4 знаков half-away) и возвращать дату.
- **FR-003**: `Дата - Дата` MUST возвращать число секунд (дробное, со знаком); `Дата + Дата`, `Число + Дата`, `Дата * Число` MUST приводить к ошибке преобразования к числу.
- **FR-004**: Сравнение и равенство дат MUST выполняться только между датами по тикам; сравнение даты с числом MUST быть ошибкой.
- **FR-005**: `Строка`, `Формат` (ДФ) и запись в JSON MUST отбрасывать доли секунды, не округляя; JSON-представление — наивный ISO без миллисекунд и `Z`.
- **FR-006**: `ТекущаяДата` MUST возвращать местное время без долей, `ТекущаяУниверсальнаяДата` — UTC без долей; `МестноеВремя`/`УниверсальноеВремя` MUST сохранять доли.
- **FR-007**: `Год`, `Месяц`, `День`, `Час`, `Минута`, `Секунда` MUST возвращать компоненты; `ДобавитьМесяц` MUST прибавлять месяцы с прижатием дня к концу месяца.
- **FR-008**: `Дата(...)` MUST поддерживать строку `ГГГГММДД[ЧЧММ[СС]]` (нули — пустая дата `01.01.0001`) и 3–6 числовых компонент с валидацией; годы меньше 100 MUST NOT сдвигаться на 1900.
- **FR-009**: `Формат` дат (`ДФ=…`, `ЧГ=0`) MUST работать на новой модели без регрессий.
- **FR-010**: Изменение MUST не ломать существующие сценарии: литералы дат, сравнение, `Формат`, JSON-тесты остаются корректными; число регрессий — ноль.

### Key Entities

- **Дата**: значение с точностью 1/10000 секунды от `0001-01-01`; сравнима, выводима, участвует в арифметике.
- **Число секунд**: дробное смещение (для `Дата ± Число` и `Дата - Дата`), округляемое до 4 знаков.
- **Компоненты даты**: год/месяц/день/час/минута/секунда; источник для конструктора и `ДобавитьМесяц`.
- **Часовой пояс**: смещение между местным и универсальным временем для `МестноеВремя`/`УниверсальноеВремя`.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Все примеры арифметики из Edge Cases (не менее 10) проходят в автоматическом наборе: `Дата ± Число`, `Дата - Дата`, ошибки недопустимых операций.
- **SC-002**: Точность и нормализация подтверждены на границах: 0.00004, 0.00005, 0.00015, 0.00016 дают значения из Edge Cases (100%).
- **SC-003**: `Дата(1,1,1)` печатается как `01.01.0001 0:00:00`, `Дата("20260201153045")` разбирается, `ДобавитьМесяц` даёт 2 из 2 эталонных результата.
- **SC-004**: `ТекущаяДата` — местное время, `ТекущаяУниверсальнаяДата` — UTC; разность равна смещению зоны.
- **SC-005**: Регрессии: существующий набор тестов остаётся зелёным, число регрессий — ноль; браузерная сборка собирается.
- **SC-006**: Полный `date-behavior.os` остаётся заблокированным JSON/XML-подсистемами (вне scope), но арифметическая часть покрыта собственным набором тестов на 100%.

## Assumptions

- Модель — целое число тиков (1/10000 с) в обычном `number`: диапазон до `0001..9999` укладывается в точность представления, BigInt не нужен.
- JSON/XML-подсистемы (объектные `ЗаписьJSON`/`ЧтениеJSON`, `XMLСтрока`, `ФорматДатыJSON`, `ПрочитатьДатуJSON`, `ЗаписатьДатуJSON`), чтение дат по именам свойств, `ЗначениеЗаполнено` и нестандартные форматы (`JavaScript`, `Microsoft`) — вне scope T40b.
- Полный прогон `date-behavior.os` не является приёмкой этой фичи: он зависит от перечисленных подсистем; приёмка — собственный набор сценариев из Edge Cases.
- `МестноеВремя`/`УниверсальноеВремя` используют системный часовой пояс; DST-переходы проверяются по смещению, а не по историческим правилам.
- `toNumber(дата)` продолжает быть ошибкой: даты не становятся числами неявно.
