# Feature Specification: Embedded language mode VS Code — грамматическая инъекция `<script type="text/osjs">`

**Feature Branch**: `feat/editor_tools`

**Created**: 2026-11-12

**Status**: Implemented (грамматика/тесты/сборка + ручная приёмка UI в VS Code)

**Input**: Решение владельца: «делай слой C» — после слоя B (тонкий клиент VS Code)
добавить embedded language mode для встроенных блоков HTML: VS Code должен считать
содержимое `<script type="text/osjs">` языком `osjs` (подсветка/комментарии/скобки/
фолдинг/word pattern), а не HTML.

## Context

После слоя B в VS Code уже работают `.osjs` (полная поддержка) и HTML-блоки через
LSP (диагностика/подсказки/hover/`gd`/semantic tokens — слой A 015). Но **редактор**
по-прежнему считает содержимое `<script type="text/osjs">` HTML-текстом: `Ctrl+/` вставляет
`<!-- -->`, авто-скобки/кавычки и отступы идут по HTML-конфигурации, `#Область` не
складывается, двойной клик по кириллице использует HTML word pattern, Emmet может
срабатывать на `<` внутри BSL. Подсветка блока — только semantic tokens сервера (нет
пунктуации/директив полноценно, и она пропадает без сервера/при тяжёлых ошибках).

Слой C добавляет **TextMate-инъекцию**: грамматика, которая находит
`<script type="text/osjs">` внутри `text.html.basic`, объявляет содержимое
`meta.embedded.block.osjs` и включает туда существующую грамматику `source.osjs`
(из `editors/osjs/`), плюс `embeddedLanguages`-мэппинг на язык `osjs` — VS Code
подхватывает нашу `language-configuration` для региона (комментарии, скобки, word
pattern, фолдинг). Вне блока всё остаётся HTML.

Это последний «редакторный комфорт» слой: новых возможностей анализа нет, меняется
поведение редактора внутри региона. Другие редакторы (Neovim/Zed) TextMate-инъекции не
используют — там остаются semantic tokens (уже работают).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Внутри блока HTML — поведение как в `.osjs` (Priority: P1)

Разработчик открывает HTML со `<script type="text/osjs">`: внутри блока работает полная
подсветка BSL (ключевые слова RU/EN, строки и `|`-продолжения, числа, даты, комментарии,
директивы `#Область`/`#Если`/`#Использовать`, аннотации), `Ctrl+/` даёт `//`, скобки и
кавычки парные, `#Область`/`#Если` складываются, двойной клик по кириллическому слову
корректен, Emmet/автозакрытие тегов внутри кода не мешают. Вне блока — обычный HTML.

**Why this priority**: Это и есть суть слоя C; без этого писать BSL в HTML неудобно.

**Independent Test**: открыть HTML-фикстуру в VS Code: конструкции внутри блока получают
`source.osjs`-скоупы (проверяется грамматическим тестом без VS Code); вручную — `Ctrl+/`,
фолдинг, двойной клик, Emmet; вне блока ничего не изменилось.

**Acceptance Scenarios**:

1. **Given** HTML с `<script type="text/osjs">`, внутри — BSL, **When** файл открыт,
   **Then** внутри блока подсвечиваются ключевые слова/строки/директивы/аннотации как в
   `.osjs`, а разметка вне блока — как HTML.
2. **Given** курсор внутри блока, **When** пользователь нажимает `Ctrl+/`, **Then**
   вставляется `//`, а не HTML-комментарий.
3. **Given** `#Область … #КонецОбласти` внутри блока, **When** пользователь сворачивает
   регион, **Then** блок складывается по BSL-маркерам.
4. **Given** внутри блока набирается `<` в BSL-сравнении, **When** срабатывает автодополнение
   редактора, **Then** HTML/Emmet-вставки тега не появляются (регион — язык `osjs`).
5. **Given** `<script type="text/javascript">` или обычный HTML, **When** файл открыт,
   **Then** наше поведение в них не применяется.

---

### User Story 2 - Подсветка не зависит от сервера и не ломает `.osjs` (Priority: P2)

Подсветка/комментарии/скобки внутри блока работают, даже если LSP-сервер выключен или
файл содержит ошибки разбора (TextMate-грамматика статична). Semantic tokens сервера
дополняют её, не конфликтуя; `.osjs`-файлы и HTML вне блоков не регрессируют.

**Why this priority**: Грамматика — базовый слой; она не должна зависеть от процесса
сервера и не должна портить существующие сценарии.

**Independent Test**: отключить расширение/сервер — в VS Code (встроенная проверка
грамматики) подсветка блока остаётся; в `.osjs` всё как было; LSP-функции при включённом
сервере работают поверх.

**Acceptance Scenarios**:

1. **Given** сервер не запущен, **When** открыт HTML с блоком, **Then** подсветка блока
   работает (грамматика), LSP-функции недоступны.
2. **Given** недописанный/битый код в блоке, **When** открыт HTML, **Then** лексическая
   подсветка не пропадает целиком.
3. **Given** `.osjs`-файл, **When** открыт, **Then** подсветка/фичи как раньше.
4. **Given** semantic tokens сервера включены, **When** открыт HTML, **Then** они
   накладываются поверх грамматики без визуального хаоса (как в VS Code для встроенных языков).

---

### User Story 3 - Поставка грамматики и обновление `.vsix` (Priority: P3)

Мейнтейнер получает инъекционную грамматику и `embeddedLanguages` в расширении:
`pnpm build:vscode` кладёт её в `.vsix`, автоматические тесты проверяют, что инъекция
работает на реальной HTML-грамматике (вендоренной фикстурой) и что другие `script`
не затронуты. Установка/обновление `.vsix` не меняет `.osjs` и HTML-сценарии вне блоков.

**Why this priority**: Без поставки и тестов грамматика — «магия», которую нельзя проверить.

**Independent Test**: `pnpm build:vscode`; в `.vsix` есть инъекционная грамматика;
грамматический тест проходит; установка в VS Code даёт поведение US1.

**Acceptance Scenarios**:

1. **Given** собранный `.vsix`, **When** распакован, **Then** содержит инъекционную
   грамматику и `embeddedLanguages`-мэппинг, сервер и `.osjs`-грамматику.
2. **Given** тест грамматики, **When** он выполняется, **Then** содержимое
   `text/osjs`-блока получает scopes `source.osjs`, а `text/javascript`-блок — нет.
3. **Given** установленное обновление расширения, **When** открыт HTML, **Then**
   `Ctrl+/`/фолдинг/подсветка работают; вне блоков — HTML-поведение.

---

### Edge Cases

- **Инлайн-блок** `<script type="text/osjs">код</script>` — инъекция работает.
- **`type` в другом регистре** (`TEXT/OSJS`) — блок распознаётся.
- **Другие `script`** (`text/javascript`, `module`, пустой `type`) — не затрагиваются.
- **HTML-комментарий** `<!-- <script type="text/osjs"> … -->` — инъекция не должна
  активироваться (или ведёт себя как HTML-комментарий; фиксируется тестом).
- **Несколько блоков**, блоки в `<head>`/body — работают.
- **Незакрытый/оборванный блок** (`</script>` в BSL-строке) — подсветка ведёт себя
  предсказуемо (как HTML-грамматика обрывает script); диагностика — отдельно (015).
- **Отсутствие/другая версия HTML-грамматики** в VS Code — инъекция не должна ронять
  подсветку HTML (fallback: без инъекции).
- **Отключённое расширение** — HTML работает как обычно.
- **Neovim/Zed и другие LSP-клиенты** — не затрагиваются (TextMate-инъекции нет).
- **`.osjs`** — не затрагивается; `scopeName source.osjs` не дублируется.
- **Semantic tokens поверх инъекции** — не ломают раскраску; при отсутствии сервера
  остаётся грамматика.
- **Пробелы/переносы/регистр тега** — `<SCRIPT TYPE='text/osjs'>` распознаётся.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ДОЛЖНА быть инъекционная TextMate-грамматика, которая находит
  `script[type="text/osjs"]` в `text.html.basic` (type и имя тега case-insensitive,
  атрибуты/кавычки, несколько/инлайн/незакрытый блок) и применяет к содержимому
  существующую грамматику `source.osjs` (`editors/osjs/`) без копирования её правил.
- **FR-002**: Расширение ДОЛЖНО регистрировать инъекцию (`injectTo: ["text.html.basic"]`,
  корректный `injectionSelector`) и `embeddedLanguages`-мэппинг, чтобы VS Code применял
  `language-configuration` языка `osjs` к региону (комментарии, скобки, word pattern,
  фолдинг `#Область`/`#Если`).
- **FR-003**: Внутри региона ДОЛЖНЫ работать: полная подсветка BSL (как `.osjs`),
  `Ctrl+/` → `//`, парные скобки/кавычки по нашей конфигурации, фолдинг BSL-регионов,
  кириллический word pattern; HTML/Emmet-автозакрытия внутри региона не применяются.
- **FR-004**: Вне `<script type="text/osjs">` поведение HTML ДОЛЖНО остаться прежним;
  другие `script`-типы и `.html` без блоков не затрагиваются; `.os` не заявляется.
- **FR-005**: Подсветка блока ДОЛЖНА работать без LSP-сервера и при синтаксических
  ошибках (статическая грамматика); semantic tokens сервера (если включены)
  накладываются поверх без регрессий.
- **FR-006**: `.osjs`-файлы и их грамматика/поведение НЕ ДОЛЖНЫ меняться; никакого
  дублирования правил `source.osjs`.
- **FR-007**: Сборка `.vsix` ДОЛЖНА включать инъекционную грамматику и обновлённый
  манифест; `pnpm build:vscode` остаётся воспроизводимым; перечень файлов пакета
  расширяется предсказуемо.
- **FR-008**: ДОЛЖЕН быть автоматический тест на реальной HTML-грамматике (вендоренная
  фикстура зафиксированной версии VS Code с указанием лицензии/источника): содержимое
  `text/osjs`-блока получает `source.osjs`-scopes; `text/javascript`-блок — нет;
  комментарии/инлайн/регистр/несколько блоков покрыты.
- **FR-009**: Манифест-тест ДОЛЖЕН проверять новую grammar-контрибуцию
  (`injectTo`, `injectionSelector`, `embeddedLanguages`), сохранение правил `.osjs`
  (`scopeName`, extensions без `.os`), настройки/команды.
- **FR-010**: Новая реализация не вводит runtime-зависимостей; для тестов используется
  уже установленный `vscode-textmate`/`vscode-oniguruma`; вендоренная HTML-грамматика —
  только тестовая фикстура с NOTICE.
- **FR-011**: Документация: README/extension README/`docs/status`/`docs/architecture`,
  quickstart спеки 018 (что проверить в VS Code, включая отключённый сервер), обновление
  спеки 017/015 (слой C выполнен).
- **FR-012**: Ручная приёмка в VS Code: подсветка/`Ctrl+/`/фолдинг/Emmet/word pattern в
  блоке, отсутствие регрессий `.osjs` и HTML вне блоков; результат фиксируется.

### Key Entities

- **Инъекционная грамматика** — `scopeName` (например `osjs.embedded.injection`),
  `injectionSelector`, begin/end `script`-блока, `contentName` (`meta.embedded.block.osjs`),
  включение `source.osjs`.
- **Регион** — содержимое `<script type="text/osjs">`, размеченное как `meta.embedded.block.osjs`
  и маппящееся на язык `osjs`.
- **Контрибуция грамматики** — запись в `package.json` расширения: `injectTo`,
  `injectionSelector`, `embeddedLanguages`, путь к файлу.
- **Вендоренная HTML-грамматика (тест)** — фикстура `html.tmLanguage.json` из VS Code
  зафиксированной версии, с NOTICE.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В VS Code в HTML-блоке подсветка BSL визуально совпадает с `.osjs`
  (ключевые слова/строки/директивы/аннотации/комментарии/числа/даты), а вне блока —
  HTML; проверено вручную и грамматическим тестом.
- **SC-002**: `Ctrl+/` внутри блока даёт `//`; `#Область`/`#Если` складываются; двойной
  клик по кириллице выделяет слово; Emmet/автозакрытие тегов в блоке не срабатывают.
- **SC-003**: `<script type="text/javascript">`, `<script type="module">`, пустой `type`,
  HTML-комментарий и HTML без блоков — поведение не меняется (тесты).
- **SC-004**: При отключённом LSP-сервере подсветка/комментарии/скобки/фолдинг в блоке
  работают (грамматика); при включённом — LSP-функции работают поверх.
- **SC-005**: `.osjs`-сценарии не регрессировали: 790+ тестов зелёные, ручная проверка
  `.osjs` в VS Code.
- **SC-006**: `pnpm build:vscode` собирает `.vsix` с инъекционной грамматикой; тест
  грамматики на вендоренной HTML-грамматике проходит; пакет не содержит лишнего.
- **SC-007**: Документация обновлена (README/extension README/status/architecture/quickstart),
  слой C отмечен выполненным в спеках 015/017; ручная приёмка зафиксирована.

## Out of Scope

- Форматирование, rename, рефакторинг, отладчик, задачи VS Code.
- Support embedded languages в других редакторах (TextMate-инъекции — VS Code-семейство;
  Neovim/Zed остаются на semantic tokens).
- Изменение LSP-сервера/диагностики/автодополнения (слой A/B уже сделаны).
- Marketplace, автообновление, подпись `.vsix`.
- Собственная HTML-грамматика/подмена HTML-инструментов; `.html` не заявляется языком `osjs`.
- Поддержка `<one-script>` (удалён в 016).

## Assumptions

- **Инъекция возможна**: HTML-грамматика VS Code даёт `<script>`-содержимому `source.js`, но
  TextMate-инъекция с приоритетом может переопределить регион; это проверяется
  **спайком до реализации** (критический риск). План содержит fallback-варианты.
- **Версия HTML-грамматики**: фиксируем версию VS Code (например, тег 1.146.0) и вендорим
  `html.tmLanguage.json` в тестовые фикстуры с NOTICE (MIT); в рантайме используется
  встроенная грамматика VS Code.
- **`embeddedLanguages`** — поддерживаемый VS Code механизм (>=1.61/1.90): маппинг
  `meta.embedded.block.osjs` → `osjs` включает нашу `language-configuration` для региона.
- **Никаких новых зависимостей**: `vscode-textmate`/`vscode-oniguruma` уже есть для тестов;
  новых нет.
- **Грамматика — VS Code-семейство**: другие редакторы не получают инъекцию; это
  осознанно (слой C — VS Code UX).

## Dependencies & Open Decisions

- **Зависимости**: 014 (грамматика `source.osjs`, `language-configuration`), 015 слой A
  (LSP в HTML), 017 (клиент VS Code/`.vsix` — реализован), `vscode-textmate`/`oniguruma`
  (тесты), VS Code HTML-грамматика (вендоренная фикстура).
- **Открытые решения для реализации (не блокируют план)**: точный `injectionSelector`
  (`L:text.html.basic` vs `L:source.js`), нужен ли `tokenTypes`, fallback, если инъекция
  не переопределяет HTML-грамматику (тогда — обсуждение альтернатив до реализации).
