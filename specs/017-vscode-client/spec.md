# Feature Specification: Тонкий клиент VS Code для OneScriptJS (`.osjs` и встроенные блоки HTML)

**Feature Branch**: `feat/editor_tools`

**Created**: 2026-11-12

**Status**: Implemented (сборка/тесты + ручная приёмка в GUI VS Code)

**Input**: Решение владельца: следующим слоем после серверного embedded-режима (015, слой A)
делать **слой B — тонкий клиент VS Code**. Спека 014 сознательно вынесла клиент за скобки
(FR-018); без него VS Code-пользователь не может воспользоваться готовым LSP-сервером и
грамматикой.

## Context

В репозитории уже есть всё, что клиент должен упаковать и запустить:

- **014**: LSP-сервер `dist/lsp/server.mjs` (stdio) с диагностикой, completion, hover,
  semantic tokens, `documentSymbol`, `definition`; TextMate-грамматика и
  `language-configuration` в `editors/osjs/`; каталог API.
- **016**: каноническая форма встраивания `<script type="text/osjs">`.
- **015, слой A**: серверный embedded-режим — HTML-документ с script-блоками получает
  mapped-диагностику, подсказки, semantic tokens и навигацию; `.html` не заявляется.

Не хватает **клиента**: расширения VS Code, которое (1) регистрирует язык `osjs` только для
`*.osjs`, (2) подключает грамматику/конфигурацию, (3) запускает наш сервер, (4) по желанию
подключает его к HTML-документам для встроенных блоков, (5) ставится локально из `.vsix` без
отдельной установки Node.js и без Marketplace.

Это **тонкий** клиент: он не реализует провайдеров сам, не форматирует, не отлаживает и не
заявляет чужие форматы. Грамматическая инъекция и настоящий embedded language mode
(подсветка/скобки региона) — слой C, отдельная работа.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Установил `.vsix` — `.osjs` работает целиком (Priority: P1)

Разработчик ставит собранный `.vsix` в VS Code (локально, вне Marketplace), открывает
`.osjs` и получает: подсветку (TextMate-грамматика), диагностику с Problems, автодополнение,
hover, semantic tokens, Outline (`documentSymbol`) и переход к определению. Ничего не нужно
настраивать и отдельно устанавливать: сервер и грамматика лежат внутри расширения, работают
офлайн и используют рантайм VS Code.

**Why this priority**: Это закрывает главную продуктовую дыру: без клиента готовый сервер
недоступен в основном редакторе. Это же — MVP.

**Independent Test**: установить `.vsix` в чистый VS Code (без других расширений), открыть
`examples/editor.osjs`: язык `OneScriptJS (osjs)`, есть подсветка; в файле с ошибкой —
диагностика; completion по `Сооб`; hover на `Сообщить(`; Outline и `gd`; семантическая
подсветка внутри файла. Проверка — вручную в VS Code + автоматическая валидация пакета.

**Acceptance Scenarios**:

1. **Given** чистый VS Code и установленный `.vsix`, **When** открыт `examples/editor.osjs`,
   **Then** статус-бар/язык показывает `osjs`, подсветка BSL работает, в Problems нет
   ошибок о нашем языке.
2. **Given** `.osjs` с синтаксической ошибкой, **When** файл открыт, **Then** диагностика
   появляется в Problems/подчёркиванием с верными позициями; после исправления исчезает.
3. **Given** курсор в `.osjs` после `Сооб`, **When** вызван автокомплит, **Then** есть
   `Сообщить`/`Message`; hover на `Сообщить(` показывает сигнатуру.
4. **Given** `.osjs` с методами и `#Область`, **When** открыт Outline, **Then** видны
   методы/регионы; `Перейти к определению` из вызова локального метода работает.
5. **Given** нет сети, **When** расширение активировано, **Then** всё вышеперечисленное
   работает (никаких скачиваний в рантайме).
6. **Given** установлен `.vsix` без отдельного Node.js в PATH, **When** VS Code открывает
   `.osjs`, **Then** сервер запускается (используется Node-рантайм VS Code).

---

### User Story 2 - HTML со `<script type="text/osjs">`: инструменты внутри блоков (Priority: P2)

Разработчик открывает HTML-страницу с блоками `script[type="text/osjs"]` (канон 016) и
получает внутри блоков диагностику, completion, hover, semantic tokens и переходы — через
серверный embedded-режим 015/слой A. Вне блоков наш клиент ничего не делает, language id
документа остаётся `html`, HTML-инструменты и другие расширения работают как обычно.
Поведение включается настройкой `onescriptjs.embeddedInHtml`.

**Why this priority**: Продукт браузерный: `<script type="text/osjs">` — основной способ
запуска кода; слой A уже готов, клиент должен дать к нему доступ из VS Code.

**Independent Test**: открыть HTML-фикстуру 015 (`tests/fixtures/lsp/embedded/manual-check.html`)
в VS Code: диагностика/подсказки/токены только в блоках, `gd` локальный и импорт; вне
блоков — тишина; HTML-расширение/валидатор не конфликтуют; `.html` не помечен нашим языком.

**Acceptance Scenarios**:

1. **Given** настройка `embeddedInHtml` включена (значение по умолчанию), **When** открыт
   HTML с нашим блоком, **Then** внутри блока работают диагностика/completion/hover/tokens,
   а вне его — нет.
2. **Given** настройка выключена, **When** открыт HTML, **Then** наш сервер к HTML не
   подключается; `.html` обслуживают только HTML-инструменты.
3. **Given** HTML без блоков, **When** он открыт, **Then** никаких наших диагностик/подсказок.
4. **Given** `.os`-файл (чужой формат), **When** он открыт, **Then** наше расширение его не
   заявляет и не обслуживает.
5. **Given** одновременно установлено расширение для ванильного `.os` (1c-syntax),
   **When** открыты `.os` и `.osjs`, **Then** каждое обслуживается своим инструментом без
   конфликта.

### User Story 3 - Настройки, логи и восстановление (Priority: P3)

Разработчик может включить/выключить HTML-режим, посмотреть лог сервера в Output,
перезапустить сервер командой. Если сервер не стартовал (битый пакет, ошибка запуска),
появляется понятное уведомление с подсказкой и запись в логе, а не «тихая» неработающая
подсветка; VS Code продолжает работать.

**Why this priority**: Тонкий клиент должен быть диагностируемым; иначе проблемы сервера
выглядят как «расширение не работает».

**Independent Test**: изменить настройку — клиент перезапускает/отключает подключение;
выполнить «OneScriptJS: Restart Language Server» — лог показывает перезапуск; имитировать
недоступный сервер — уведомление и лог, без падения VS Code.

**Acceptance Scenarios**:

1. **Given** включён HTML-режим, **When** пользователь выключает настройку, **Then** клиент
   перестаёт обслуживать HTML (без перезапуска VS Code).
2. **Given** команда перезапуска, **When** она выполнена, **Then** сервер перезапускается,
   Output-канал содержит запись об этом.
3. **Given** сервер не может стартовать, **When** открыт `.osjs`, **Then** появляется одно
   уведомление с причиной и подсказкой (лог/переустановка), VS Code не падает.
4. **Given** обычная работа, **When** открыт Output-канал OneScriptJS, **Then** видны
   сообщения сервера/клиента, без секретов и лишнего шума.

---

### User Story 4 - Воспроизводимая сборка и поставка `.vsix` (Priority: P4)

Мейнтейнер одной командой собирает самодостаточный `.vsix` из репозитория:
`pnpm build:vscode`. Пакет содержит скомпилированное расширение, сервер, грамматику и
конфигурацию языка; версия берётся из `package.json`; установка/удаление не оставляют
мусора; пакет не требует Marketplace и сети.

**Why this priority**: Без воспроизводимой упаковки клиент нельзя передать пользователю и
нельзя проверить в чистом VS Code.

**Independent Test**: на чистой копии репозитория `pnpm build:vscode` создаёт
`dist/vscode/*.vsix`; распаковка пакета содержит все заявленные файлы; установка в чистый
VS Code работает; удаление расширения чистое.

**Acceptance Scenarios**:

1. **Given** чистый checkout, **When** выполнен `pnpm build:vscode`, **Then** появляется
   `.vsix`, сборка повторяема, без ручных шагов.
2. **Given** собранный `.vsix`, **When** его содержимое проверено, **Then** внутри есть
   сервер, грамматика, language-configuration, манифест, README/NOTICE, нет node_modules и
   исходников.
3. **Given** `.vsix` установлен и удалён, **When** VS Code перезапущен, **Then** язык `osjs`
   и настройки не остаются «битыми» (настройки могут сохраняться — допустимо).
4. **Given** изменение версии в корневом/расширенческом `package.json`, **When** сборка
   выполнена, **Then** версия `.vsix` соответствует ожидаемой.

---

### Edge Cases

- **Нет открытой папки (single-file mode)**: `.osjs` открывается по одному файлу — сервер
  запускается в single-file режиме (root не обязателен).
- **Untitled-буфер с языком `osjs`**: диагностика/подсказки работают; `gd` в импорт — без
  файла может быть `null` (как в 014).
- **Очень большой workspace**: активация только по языку/настройке, без индексации всего
  проекта; сервер получает только открытые документы.
- **Сервер упал/перезапущен**: клиент не входит в цикл падений; уведомление, ограниченное
  число авто-перезапусков, ручная команда.
- **HTML-режим и другие расширения**: language id `html` не меняется; наши диагностики
  имеют `source: 'osjs'`; форматирование/валидация HTML не перехватываются.
- **Отсутствие `dist/lsp/server.mjs` при сборке** — сборка расширения падает с понятной
  ошибкой (не собирать «пустой» `.vsix`).
- **`.os`** никогда не заявляется и не обслуживается.
- **Смена настройки `embeddedInHtml`**: применяется без перезапуска VS Code (перезапуск
  LSP-клиента допустим).
- **Оффлайн/корпоративный прокси**: никаких сетевых запросов; установка — из файла.
- **Windows/macOS/Linux**: пути и запуск сервера кроссплатформенны (без shell-специфики).
- **Расширение ванильного OneScript** уже установлено: конфликта за `.os`/`.osjs` нет.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Расширение ДОЛЖНО регистрировать язык `osjs` и связывать с ним только
  `*.osjs`; `*.os` не заявляется и не обслуживается (граница 013/014).
- **FR-002**: Расширение ДОЛЖНО включать грамматику `source.osjs` и
  `language-configuration` из `editors/osjs/` (без дублирования исходников).
- **FR-003**: Расширение ДОЛЖНО запускать LSP-сервер 014/015 (`dist/lsp/server.mjs`) по
  stdio, используя Node-рантайм VS Code; документ-селектор: `osjs` всегда, `html` — при
  включённой настройке; lifecycle сервера привязан к активации/деактивации расширения.
- **FR-004**: `.vsix` ДОЛЖЕН быть самодостаточным: сервер, грамматика, конфигурация внутри
  пакета; никаких скачиваний в рантайме, отдельный Node.js не требуется, Marketplace не
  нужен.
- **FR-005**: Настройки: `onescriptjs.embeddedInHtml` (boolean; включает обслуживание HTML;
  значение по умолчанию — `true`), `onescriptjs.trace` (off/messages/verbose → LSP trace в
  Output). Изменение настройки применяется без перезапуска VS Code (перезапуск клиента
  допустим).
- **FR-006**: Команды: `OneScriptJS: Restart Language Server` и `OneScriptJS: Show Output`
  (открыть Output-канал). Ошибки запуска сервера — одно уведомление с причиной и
  подсказкой; ограниченное число авто-перезапусков.
- **FR-007**: Активация — ленивая: по языку `osjs` или (при включённой настройке) по
  `html`; отсутствие `.osjs`/HTML-документов не должно запускать сервер.
- **FR-008**: Расширение НЕ ДОЛЖНО реализовывать собственные провайдеры, форматирование,
  rename, отладку, грамматическую инъекцию или embedded language mode — только
  регистрация языка/грамматики + LSP-клиент (тонкая обёртка).
- **FR-009**: Сборка `pnpm build:vscode` ДОЛЖНА быть воспроизводимой и создавать
  `dist/vscode/<name>-<version>.vsix`; версия — из манифеста расширения; сборка включает
  сервер (сборка `build:lsp`) и копирование грамматики/конфигурации; при отсутствии
  сервера/грамматики сборка падает.
- **FR-010**: Пакет ДОЛЖЕН содержать только runtime-файлы (собранный JS расширения,
  `server.mjs`, грамматика, конфигурация, README/NOTICE), без `node_modules` и исходников;
  установка/удаление не ломают другие расширения.
- **FR-011**: Автоматическая проверка ДОЛЖНА валидировать манифест и пакет: engine VS Code,
  contributes (languages/grammars/commands/configuration), наличие файлов грамматики и
  сервера в сборке, запрет `.os` в `extensions`; входит в `pnpm test`.
- **FR-012**: Документация: README (установка `.vsix`, настройки, ограничения), `docs/status`,
  `docs/architecture`, quickstart спеки; пример проверки в чистом VS Code.
- **FR-013**: Никаких новых runtime-зависимостей; dev-зависимости (типы VS Code, упаковщик)
  обоснованы в плане; движок/сервер/`.osjs`-поведение не меняются.
- **FR-014**: Расширение не отправляет телеметрию; в логах нет содержимого файлов сверх
  необходимого для диагностики проблем.

### Key Entities

- **Манифест расширения** — `package.json`: `engines.vscode`, `main`, `activationEvents`,
  `contributes` (languages, grammars, configuration, commands), `version`.
- **Пакет `.vsix`** — собранные артефакты: JS расширения, `server.mjs`, грамматика,
  language-configuration, README/NOTICE.
- **LSP-клиент** — `vscode-languageclient`: транспорт, документ-селекторы, lifecycle,
  обработка ошибок/логов.
- **Настройки** — `onescriptjs.embeddedInHtml`, `onescriptjs.trace`.
- **Команды** — перезапуск сервера, показ Output.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Свежий VS Code + установленный `.vsix` + `examples/editor.osjs` → подсветка,
  диагностика, completion (`Сообщить`), hover, Outline/`gd`, semantic tokens работают без
  настройки и без сети; отдельный Node.js не требуется.
- **SC-002**: `.osjs` с ошибкой показывает диагностику в Problems с корректными позициями;
  после исправления — исчезает.
- **SC-003**: HTML-фикстура 015 (`manual-check.html`): внутри блоков диагностика/completion/
  hover/tokens/`gd` работают, вне блоков — пусто; language id `html` не меняется;
  выключение `embeddedInHtml` убирает обслуживание HTML.
- **SC-004**: `.os` не заявляется; совместная установка с расширением ванильного OneScript
  не создаёт конфликта.
- **SC-005**: `pnpm build:vscode` на чистом checkout создаёт `.vsix`, содержимое которого
  проходит автоматическую проверку (FR-011); повторная сборка даёт тот же набор файлов;
  версия соответствует манифесту.
- **SC-006**: Установка/удаление `.vsix` в чистом VS Code не ломает другие расширения;
  настройки языка `osjs` не остаются «полузарегистрированными».
- **SC-007**: Ошибка запуска сервера даёт одно уведомление и запись в Output; VS Code
  продолжает работать; команда перезапуска восстанавливает клиент.
- **SC-008**: `pnpm typecheck && pnpm test && pnpm build` зелёные; автоматические проверки
  пакета входят в `pnpm test`; новых runtime-зависимостей нет.
- **SC-009**: Документация (README/status/architecture/quickstart спеки) описывает установку,
  настройки и ограничения; ручная приёмка в VS Code зафиксирована.

## Out of Scope

> Слой C (грамматическая инъекция/embedded language mode) реализован отдельно —
> [`specs/018-embedded-language-mode`](../018-embedded-language-mode/spec.md).

- Публикация в VS Code Marketplace, автообновление, каналы релизов (только локальный `.vsix`).
- Грамматическая инъекция `<script type="text/osjs">` и embedded language mode (слой C;
  может стать отдельной спекой/фазой после B).
- Собственные провайдеры в расширении, форматирование, rename/refactor, quick fixes,
  отладчик, задачи/тесты в VS Code.
- Поддержка других редакторов (Neovim/Zed уже работают через LSP-конфиг).
- Изменение движка, LSP-сервера, формата `.osjs`, конституции.
- Телеметрия, аккаунты, сетевые сервисы.

## Assumptions

- **Монorepo**: расширение живёт в `extensions/vscode/` этого репозитория; версия — своя у
  расширения (можно синхронизировать с корневой вручную/скриптом).
- **Минимальная версия VS Code** — актуальная стабильная на момент реализации (фиксируется
  в `engines.vscode`), с поддержкой API `vscode-languageclient`.
- **Запуск сервера**: stdio через Node-рантайм VS Code (`ELECTRON_RUN_AS_NODE` или
  эквивалентный поддерживаемый способ), сервер — готовый `dist/lsp/server.mjs`; конкретный
  транспорт проверяется спайком в плане.
- **HTML-режим по умолчанию включён**; пользователь может выключить настройкой. Это
  «явное включение» на стороне клиента, а не заявление `.html`.
- **Упаковка** — `.vsix` через официальный упаковщик (dev-зависимость), локальная установка
  `code --install-extension`.
- **Тесты**: автоматическая валидация манифеста/пакета в Vitest; полноценный
  `@vscode/test-electron` не обязателен в первой версии — ручная приёмка фиксируется.
- **Сервер/грамматика/**`.osjs`-поведение не меняются**; расхождения — дефекты.

## Dependencies & Open Decisions

- **Зависимости**: 014 (реализована), 015 слой A (реализован), 016 (реализована),
  доступный `code` CLI для локальной установки.
- **Открытые решения для `/speckit-clarify`**: (1) default для `embeddedInHtml` (в спеке
  принято `true`); (2) версия VS Code/движка; (3) нужен ли `@vscode/test-electron` в v1
  (в спеке — нет, достаточно валидации пакета + ручной приёмки). Не блокируют план.
