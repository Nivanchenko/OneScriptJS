# Feature Specification: Системные настройки OneScript (`config.os`)

**Feature Branch**: `feature/speckit_intergation`

**Created**: 2026-11-11

**Status**: Draft

**Input**: Остаток T36 из `docs/plan.md`: `ОбновитьНастройкиСистемы` / `ПолучитьЗначениеСистемнойНастройки` (подсистема `config.os`).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Скрипт читает системную настройку (Priority: P1)

Скрипт запрашивает настройку по имени (`ПолучитьЗначениеСистемнойНастройки("SystemLanguage")`) и
получает строку, собранную движком из конфигурационных источников. Неизвестный ключ не является
ошибкой — возвращается `Неопределено`.

**Why this priority**: Без чтения настройки функция бесполезна; это минимальная ценность `config.os`.

**Independent Test**: Скрипт с `сообщить(ПолучитьЗначениеСистемнойНастройки("encoding.script"));`
печатает значение из конфигурации, а для выдуманного ключа — `Неопределено`.

**Acceptance Scenarios**:

1. **Given** в конфигурации есть `encoding.script = utf-8`, **When** скрипт запрашивает этот ключ, **Then** возвращается `"utf-8"`.
2. **Given** ключа нет ни в одном источнике, **When** скрипт его запрашивает, **Then** возвращается `Неопределено`, без исключения.
3. **Given** имя ключа передано в другом регистре, **When** выполняется запрос, **Then** значение найдено (регистронезависимость).

---

### User Story 2 - Приоритет источников и явное обновление (Priority: P2)

Настройка может быть задана в трёх местах: конфиг рядом с движком, конфиг рядом со скриптом и
переменная среды `OSCRIPT_CONFIG`. Более близкий к запуску источник перекрывает дальний. Движок
читает снимок один раз, а изменения применяются только после явного обновления.

**Why this priority**: Без приоритетов и снимка поведение непредсказуемо и расходится с версией
OneScript, где `ОбновитьНастройкиСистемы` — единственная точка перечитывания.

**Independent Test**: Задать значение файлом и перекрыть его через `OSCRIPT_CONFIG`; до вызова
`ОбновитьНастройкиСистемы` виден старый снимок, после — новое значение; сброс переменной среды в
пустую возвращает файловое значение (или `Неопределено`).

**Acceptance Scenarios**:

1. **Given** ключ задан и в файле, и в `OSCRIPT_CONFIG`, **When** настройки обновлены, **Then** побеждает переменная среды.
2. **Given** настройки уже загружены, **When** переменная среды изменилась без `ОбновитьНастройкиСистемы`, **Then** возвращается прежнее значение.
3. **Given** то же изменение, **When** вызван `ОбновитьНастройкиСистемы`, **Then** возвращается новое значение.

---

### User Story 3 - Форматы файла и переменной среды устойчивы (Priority: P3)

Разработчик пишет конфиг вручную: комментарии `#`, пробелы вокруг `=`, BOM, дубликаты ключей.
Переменная среды задаётся списком пар. Ошибочные данные не должны ронять движок без причины, а
неверный ключ должен давать понятную ошибку.

**Why this priority**: Конфиг — ручной файл; без терпимости к оформлению он будет ломаться на
первом же редактировании, а молчаливое проглатывание ошибок скроет опечатки.

**Independent Test**: Файл с `# комментарием`, `  SystemLanguage = en  `, BOM и дубликатом ключа
читается; последнее значение побеждает; пустой ключ в запросе даёт ошибку.

**Acceptance Scenarios**:

1. **Given** файл с комментариями, пробелами и BOM, **When** настройка запрашивается, **Then** значение прочитано.
2. **Given** ключ повторяется дважды, **When** настройка запрашивается, **Then** возвращается последнее значение.
3. **Given** в запросе пустой ключ или только пробелы, **When** выполняется вызов, **Then** возникает ошибка формата ключа.

### Edge Cases

- Отсутствующий конфиг рядом со скриптом — не ошибка: значения берутся из остальных источников.
- Нечитаемый конфиг рядом с движком — ошибка; нечитаемый конфиг рядом со скриптом — игнорируется.
- Строки без `=` и пустые строки в файле игнорируются.
- Переменная среды пустая или отсутствует — переопределений нет.
- Кавычки в значении переменной среды с `;` внутри: разделитель не срабатывает.
- Имя в переменной среды начинается с цифры/дефиса — разбор пары обрывается, остаток игнорируется.
- Изменение файла на диске без `ОбновитьНастройкиСистемы` не видно (снимок).
- В браузере файловых настроек нет: функция возвращает `Неопределено`, обновление — no-op, без ошибок.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Движок MUST предоставлять `ПолучитьЗначениеСистемнойНастройки(Имя)` / `GetSystemOptionValue`, возвращающую строку или `Неопределено`.
- **FR-002**: Движок MUST предоставлять `ОбновитьНастройкиСистемы()` / `RefreshSystemConfig`, перечитывающую источники; без вызова значения не меняются.
- **FR-003**: Источники MUST применяться в порядке: `oscript.cfg` рядом с движком → `oscript.cfg` рядом с запускаемым скриптом → переменная среды `OSCRIPT_CONFIG`; более поздний источник перекрывает более ранний.
- **FR-004**: Файл настроек MUST читаться как `ключ = значение`: `#` — комментарий только с первого символа строки; строки без `=` и пустые игнорируются; ключ и значение обрезаются; ключи регистронезависимы; BOM допускается; при дубликате ключа в файле побеждает последнее значение.
- **FR-005**: Значение переменной среды `OSCRIPT_CONFIG` MUST разбираться как список пар (`k=v;k2=v2` или через пробелы); имя ключа — с буквы, затем буквы/цифры/`.`/`_`; значение может быть в кавычках с удвоением кавычки; пустая переменная означает отсутствие переопределений.
- **FR-006**: Неизвестный ключ MUST возвращать `Неопределено`; пустое значение настройки MUST возвращать пустую строку.
- **FR-007**: Пустой ключ (или только пробелы) в запросе MUST приводить к ошибке формата ключа с текстом, содержащим переданный ключ.
- **FR-008**: Отсутствие конфигов MUST NOT быть ошибкой; нечитаемый конфиг рядом с движком MUST быть ошибкой, нечитаемый конфиг рядом со скриптом MUST игнорироваться.
- **FR-009**: В браузерной среде функции MUST существовать и работать без файлового доступа: `Неопределено` для любого ключа, обновление — no-op; ядро MUST NOT импортировать Node-модули.
- **FR-010**: Изменение MUST не ломать существующее поведение: общий набор тестов остаётся зелёным.

### Key Entities

- **Настройка**: пара «ключ (регистронезависимый) → строковое значение».
- **Источник настроек**: файл рядом с движком, файл рядом со скриптом, переменная среды `OSCRIPT_CONFIG`.
- **Снимок настроек**: объединённый набор пар на момент загрузки/обновления; запросы читают только его.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Все 3 теста `reference/OneScript/tests/config.os` проходят при заданной переменной среды (сейчас — «Неизвестная функция»).
- **SC-002**: Приоритет подтверждён: 100% проверяемых пар «файл + среда» дают значение из среды.
- **SC-003**: Снимок: без `ОбновитьНастройкиСистемы` значение не меняется, после — меняется (оба случая 100%).
- **SC-004**: Браузерная сборка собирается и в браузере 100% запросов настроек возвращают `Неопределено` без исключений.
- **SC-005**: Регрессии: существующий набор тестов остаётся зелёным, число регрессий — ноль.

## Assumptions

- Функции возвращают только сырые строки: применение настроек (`SystemLanguage`, `encoding.script`, `lib.*`, `binaryData.*`, `backgroundJobs.*`) — дело потребителей и вне scope.
- Дефолтный `oscript.cfg` в поставке отсутствует; все источники опциональны, кроме поведения ошибок из FR-008.
- Реальное чтение файлов и переменных среды выполняется в Node-слое; в браузере поставляется пустой источник.
- Тест `config.os` использует переменные среды: прогон задаёт их явно, а не полагается на окружение машины.
- Запись настроек, горячая перезагрузка без вызова функции и веб-конфигурация — вне scope.
