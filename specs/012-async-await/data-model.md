# Data Model: Асинхронные методы (`Асинх`/`Ждать`, `Обещание`)

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Contract**: [contracts/async-await-contract.md](contracts/async-await-contract.md)

## 1. AST и парсер

### 1.1 Изменения AST

| Узел | Поле | Тип | Инвариант |
|---|---|---|---|
| `MethodDeclaration` | `isAsync` | `boolean` | `true` только при явном `Асинх`/`Async` |
| `AwaitExpression` (новый) | `operand` | `Expression` | операнд обязателен; не может быть `AwaitExpression` (двойной `Ждать` — ошибка разбора) |

### 1.2 Состояние парсера

| Поле | Назначение | Правило |
|---|---|---|
| `methodKind` | `'procedure' \| 'function' \| null` | как сейчас; `null` — тело модуля |
| `inAsync` | внутри async-метода | сохраняется/восстанавливается в `parseMethod` |
| `awaitAllowed` | производное | `inAsync === true \|\| methodKind === null` |

### 1.3 Распознавание

| Вход | Контекст | Результат |
|---|---|---|
| `Асинх`/`Async` перед `Процедура`/`Функция` | начало метода | метод с `isAsync=true` |
| `Асинх` в иной позиции | любая | обычный идентификатор (`Асинх = …`) |
| `Ждать`/`Await` + токен начала выражения (идентификатор, литерал, `(`, `?`) | awaitAllowed | `AwaitExpression` с операндом `parsePostfix()` |
| `Ждать` + `(` | awaitAllowed | обычный идентификатор/вызов (как эталон) |
| `Ждать` + `= ; ) , ] . [` | любая | обычный идентификатор |
| `Ждать` + начало выражения | `methodKind !== null && !inAsync` | ошибка «Ждать допустим только в асинхронном методе или теле модуля» |
| `Асинх ПриСозданииОбъекта` | начало метода | ошибка |
| `Ждать;` / `Ждать Ждать X` | awaitAllowed | ошибка разбора |

## 2. `Обещание` / `Promise` (`src/runtime/promise.ts`)

### 2.1 Состояние

```text
        resolve(value)            await() → value / cached
pending ───────────────▶ fulfilled
   │
   │ reject(error)           await() → throw cached error
   └──────────────────▶ rejected
```

**I-P1**: переход `pending → fulfilled|rejected` однократен; повторный `resolve/reject` — no-op.
**I-P2**: `await()` на settled возвращает кэш (значение/бросает ту же ошибку), не создаёт
нового ожидания.
**I-P3**: `await()` на pending возвращает `Promise`, который разрешается/отклоняется при
settle; несколько ожидающих просыпаются одновременно.
**I-P4**: `completion` разрешается при settle и **никогда не отклоняется** (для flush).
**I-P5**: при rejected и `awaited === false` окружение получает уведомление
(отложенно, `setTimeout(0)`), не более одного раза; при `Ждать` флаг `awaited` ставится.

### 2.2 BSL-поверхность

| Член | Значение |
|---|---|
| `typeName` | `Обещание` (EN `Promise`) |
| Конструктор | нет; `Новый Обещание` → ошибка «Тип не найден» |
| Методы/свойства | нет (любой доступ → ошибка) |
| `Строка()` | `"Обещание"` |
| `ТипЗнч()` | `Обещание` |

## 3. Исполнение async-метода

| Шаг | Поведение |
|---|---|
| Вызов | аргументы вычисляются по значению слева направо |
| Старт | `drive(invokeAsyncGen(...))` — тело идёт до первой приостановки |
| Завершение без приостановок | `Обещание` сразу fulfilled (значение или `Неопределено` для процедуры) |
| Приостановка | драйвер возвращает Promise; по завершении `Обещание` settle |
| Ошибка | catch → `reject(error)`; вызывающему не бросается |
| `Возврат` | значение функции / `Неопределено` процедуры |
| Срез квантов | при async-исполнении включается `TimeSlicer` (страница не замирает) |

**I-A1**: async-методы разделяют модульный `Ctx` и состояние; отдельного fork нет.
**I-A2**: async-методы не регистрируются в `BackgroundTasksRegistry`.
**I-A3**: job на async-метод получает `Обещание` как `Результат` (не ожидает).

## 4. Окружение и flush

| Поле/хук | Тип | Назначение |
|---|---|---|
| `pendingPromises` | `Set<{ completion: Promise<void> }>` | незавершённые `Обещания` запуска |
| `trackAsync?` | `(tracker) => void` | регистрация/снятие по completion |
| `reportUnhandledError?` | `(error) => void` | необработанная ошибка (по умолчанию `console.error`) |
| `flushAsync` | `() => MaybePromise<void>` | задания (`011`) **и** незавершённые `Обещания` |

**I-F1**: если незавершённых `Обещаний` нет, `flushAsync` остаётся синхронным (sync fast-path).
**I-F2**: flush ждёт до опустошения множества (обещания могут порождать новые).

## 5. Диагностика (двуязычные тексты)

| Ситуация | Текст (ориентир) |
|---|---|
| await вне async-метода/модуля | «Ждать допустим только в асинхронном методе или теле модуля» |
| await без операнда | «Ожидается выражение после Ждать» |
| двойной await | «Нельзя ожидать результат ожидания» |
| `Асинх` не перед методом | «Ожидается Процедура или Функция после Асинх» |
| `Асинх ПриСозданииОбъекта` | «Асинхронный конструктор не поддерживается» |
| доступ к `Обещание` | «Метод/свойство … не найдено у типа Обещание» |

## 6. Связь с сущностями спеки 011

| Сущность 011 | Связь |
|---|---|
| Генераторный драйвер (`drive`, `yieldMaybe`) | общий механизм приостановки async-методов |
| `Приостановить`/`Sleep` | доступна внутри async-метода |
| `ФоновыеЗадания` | доступны внутри async-метода; реестры независимы |
| `flushAsync` | расширяется ожиданием незавершённых `Обещаний` |
| Логический поток | async-метод исполняется в логическом потоке вызывающего (тело модуля) |
