# Research: Асинхронные методы (`Асинх`/`Ждать`, `Обещание`)

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md)

Неопределённостей планирования не осталось; `[NEEDS CLARIFICATION]` нет.

## R1. Где взять синтаксис и диагностику

**Decision**: портировать контекстную логику из парсера эталона: `Асинх` — только
непосредственно перед `Процедура`/`Функция`; `Ждать` — унарный префикс с операндом
уровня постфиксных выражений; вне async-контекста оба — обычные идентификаторы.

**Rationale**: `reference/OneScript/src/OneScript.Language/SyntaxAnalysis/DefaultBslParser.cs`
и `.../Tests/OneScript.Language.Tests/ParserTests.cs` уже фиксируют поведение
(приоритет await, запрет двойного await, контекстные идентификаторы). Наш лексер не знает
ключевых слов — все слова `Identifier`, решение принимает парсер (как `Новый`, `Не`).

**Alternatives considered**: новые токены лексера — отклонено: сломает идентификаторы
`Ждать`/`Асинх`; call-site `Асинх Метод()` из исходной формулировки — отклонено в пользу
модели 1C/эталона (объявление метода), согласовано с пользователем при спеке 011.

## R2. Семантика исполнения

**Decision**: async-функция и async-процедура при вызове сразу создают `Обещание` и
начинают исполнение **eagerly** до первой приостановки. Завершение без приостановок сразу
переводит `Обещание` в fulfilled. Ошибка (в т.ч. до первой приостановки) не бросается
синхронно, а переводит `Обещание` в rejected.

**Rationale**: так работает `async`/Promise в JS и `Асинх`/`Обещание` в 1C: вызывающему
не нужно оборачивать вызов в `Попытку`, ошибка ловится в точке `Ждать`. Наш драйвер
`drive()` даёт это бесплатно: первый `gen.next()` исполняет тело до `yield`.

**Alternatives considered**: ленивый старт (как job через `queueMicrotask`) — отклонено:
`А = Ждать Ф();` терял бы синхронную часть и усложнял порядок побочных эффектов.

## R3. Тип `Обещание`

**Decision**: непрозрачный `BslObject` с `typeName='Обещание'`, без публичных методов и
свойств, без конструктора (`Новый Обещание` → «Тип не найден»). Состояния
`pending/fulfilled/rejected`, кэш результата/ошибки, `await()` для интерпретатора,
`completion: Promise<void>` для flush, флаг `awaited` для unhandled-ошибок.
`Строка(Обещание) = "Обещание"`, `ТипЗнч` → `Обещание`.

**Rationale**: 1C 8.3.18 тоже отдаёт `Обещание` без конструкторов/методов; закрытый объект
не даёт блокирующих API, которые в браузере дали бы дедлок, и не расширяет поверхность без
запроса.

**Alternatives considered**: Task-подобный API (`Результат`, `Завершено`, `Затем`) —
отклонено: в браузере `Результат`/`Ждать` не могут блокировать; отмена/`КогдаВсе` — вне scope.

## R4. `Ждать` и приостановка

**Decision**: `Ждать` вычисляет операнд; если это `Обещание`:
- fulfilled → значение; rejected → бросает сохранённую ошибку;
- pending → текущий генератор отдаёт `Promise` драйверу (приостановка логического потока).
Не-`Обещание` возвращается как есть. Повторное ожидание — из кэша; ошибка бросается при
каждом ожидании.

**Rationale**: повторяет 1C/JS; `gen.throw` доставляет отказ в точку `yield`, поэтому
`Попытка` ловит его как обычное исключение без доработок.

**Alternatives considered**: строгая ошибка при `Ждать` не-`Обещания` (C#/Python) —
отклонено ради эргономики и терпимости JS.

## R5. Top-level `Ждать` (расширение проекта)

**Decision**: `Ждать` разрешён в исполняемом теле модуля (и импортируемых модулей), помимо
async-методов. В обычных синхронных методах — ошибка с позицией.

**Rationale**: у нас нет платформенного event loop, который бы стартовал async-метод и
дожидался `Обещания`; без top-level `Ждать` новая функциональность не вызывается из
`<one-script>`/CLI. Хост и так уже дожидается `run()` (Promise-контракт спеки 011), значит
top-level ожидание бесплатно и не блокирует браузер. Эталон разбирает top-level `Ждать` как
идентификатор — расхождение осознанное, фиксируется тестом и `docs/status.md`.

**Alternatives considered**: хост-функция `ЗапуститьОжидание`/неявный await main — лишняя
поверхность; строгий запрет — сделал бы фичу неприменимой.

## R6. Параметры и объявления

**Decision**: параметры async-методов передаются по значению (значения вычисляются в
вызывающем контексте; `Знач` необязателен). `Возврат` — с обычными проверками
функция/процедура. `Асинх ПриСозданииОбъекта` запрещён парсером.

**Rationale**: 1C-семантика асинхронных методов; передача по ссылке через точку
приостановки требует живой ссылки на вызывающий scope, что противоречит модели 1C.

## R7. Необработанные ошибки и flush

**Decision**: `BslPromise` при rejected и `awaited=false` откладывает сообщение
(`setTimeout(0)`), проверяя флаг; сообщение идёт `env.reportUnhandledError` (по умолчанию
`console.error`). Окружение трекает `completion` всех `Обещаний`; `GlobalContext.flushAsync`
ждёт сначала фоновые задания, затем незавершённые `Обещания` (включая «fire-and-forget»).

**Rationale**: FR-009 (ошибка не роняет сценарий) и FR-014 (хост дожидается async-вывода);
CLI не должен выходить раньше отложенной работы и терять ошибки. Отложенная проверка
подавляет ложные срабатывания для `О = Упасть(); Ждать О;` в том же тике.

**Alternatives considered**: microtask-проверка — чаще ложные срабатывания; не ждать
detached-обещания — теряются ошибки и вывод в CLI.

## R8. Взаимодействие с фоновыми заданиями

**Decision**: async-методы и фоновые задания используют один планировщик и генераторный
драйвер, но разные реестры: async-методы не видны в `ФоновыеЗадания.ПолучитьФоновыеЗадания`.
Внутри async-метода работают `Приостановить` и ожидания заданий. Job, нацеленный на
async-метод, получает `Обещание` как `Результат` (не ждёт его) — комбинация вне основной
ценности, фиксируется тестом/документацией.

## R9. Совместимость идентификаторов (эталонные случаи)

**Decision**: покрыть тестами из `ParserTests.cs`: `А = Ждать;`, `А = Ждать();`,
`А = П.Ждать;`, `А = П.Ждать();`, `Процедура Ждать()`, `Перем Ждать;`,
`Если Ждать ВтороеСлово Тогда`, `Ждать = "МояПеременная";`, `Асинх = "МояПеременная2";`,
`Ждать Ждать X` — ошибка. Поведение — как в эталоне, кроме top-level `Ждать <выражение>`.

## R10. Что не входит

Отмена, таймауты ожидания, `КогдаВсе`/`КогдаЛюбой`, async-конструкторы, async-обработчики
событий с ожиданием, async-импорт модулей, async HTTP (`fetch`) — отдельные работы.
