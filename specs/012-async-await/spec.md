# Feature Specification: Асинхронные методы (`Асинх`/`Ждать`, `Обещание`)

**Feature Branch**: `feature/async`

**Created**: 2026-11-11

**Status**: Implemented (happy-dom + `examples/async.html`, ручная приёмка)

**Input**: Исходный запрос: «Ждать \ Асинх. Любой пользовательский метод можно вызвать с
асинх, и получить Ожидание. Которое можно ждать: `МоеОжидание = Асинх МойМетод(Параметр1,
Параметр2);` … `Результат = Ждать МоеОжидание;`. Ожидание — какой-то объект, который может
вернуть результат, если это функция, или что-то ещё, если это процедура. Подумай сам, как
лучше сделать API, по аналогии с другими языками программирования». Уточнение порядка работ:
«сначала `МенеджерФоновыхЗаданий` и инфраструктура вокруг него, потом поверх этого API —
`Асинх`/`Ждать`». Фоновая часть реализована в спеке 011.

Эталон:
- **Синтаксис и диагностика** уже приняты в OneScript, но рантайма нет:
  `reference/OneScript/src/OneScript.Language/LanguageDef.cs` (`Token.Async`, `Token.Await`),
  `.../SyntaxAnalysis/DefaultBslParser.cs` (async-метод, await-оператор, контекстные
  ключевые слова), `.../Tests/OneScript.Language.Tests/ParserTests.cs` (семантика разбора);
  компилятор намеренно отклоняет async-методы: «Асинхронные методы не поддерживаются»
  (`StackMachineCodeGenerator.cs`, `ModuleCompiler.cs`, `LocalizedErrors.cs`).
- **Семантика исполнения** — 1C:Enterprise 8.3.18+ (`Обещание`, `Асинх`, `Ждать`):
  вызов async-функции возвращает `Обещание`, `Ждать` разворачивает значение или бросает
  ошибку, ошибки ловятся `Попыткой` в точке `Ждать`, параметры async-методов — только по
  значению.

**Осознанные расхождения** (конституция, принцип I — фиксируются в `docs/status.md` и тестами):

1. **Рантайм реализуется** — в эталоне его нет, есть только разбор.
2. **`Ждать` разрешён в исполняемом теле модуля** (наше расширение). Эталон разбирает
   top-level `Ждать` как обычный идентификатор; без этого расширения в нашем движке
   `Ждать` неоткуда вызвать: нет платформенного цикла, который бы дожидался `Обещания`.
   Вне async-контекста и в выражениях `Ждать`/`Асинх` остаются обычными идентификаторами.
3. **Вызов `Асинх Процедуры` тоже возвращает `Обещание`** (разрешается в `Неопределено`).
   В 1C async-процедура не даёт результата; пользователь явно просил handle и для процедур,
   а единообразие упрощает композицию. Ошибка async-процедуры всплывает только при `Ждать`
   или уходит в обработчик хоста, если `Обещание` не ожидали.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Асинхронная функция и `Ждать` в главном сценарии (Priority: P1)

Разработчик объявляет `Асинх Функцию`, внутри неё ждёт медленную операцию
(`Приостановить`, ожидание фонового задания), а в исполняемом коде модуля получает
результат через `Ждать`. Страница в браузере не замирает, пока функция ждёт. Ошибка внутри
async-функции всплывает в точке `Ждать` и ловится обычной `Попыткой`.

**Why this priority**: Это минимальный полезный сценарий — без него async-функции нечем
пользоваться, а `Ждать` неоткуда вызвать. Он же — доказательство неблокирующего исполнения.

**Independent Test**: BSL-скрипт в `<one-script>`: `Р = Ждать Считать(1, 100);`
печатает `5050` после паузы; маркер до паузы появляется сразу; ошибка в async-функции
перехватывается `Попыткой` и печатает описание.

**Acceptance Scenarios**:

1. **Given** `Асинх Функция Считать(Знач Начало, Знач Конец)`, внутри `Приостановить(50)`,
   **When** скрипт выполняет `Результат = Ждать Считать(1, 100);`, **Then** получает `5050`,
   а во время паузы страница обрабатывает таймеры/события.
2. **Given** async-функция завершается без единой приостановки, **When** её результат ждут
   через `Ждать`, **Then** значение возвращается без задержки.
3. **Given** async-функция бросает `ВызватьИсключение "ошибка"`, **When** её ждут в
   `Попытке`, **Then** `Ждать` бросает то же исключение и `Попытка` его ловит.
4. **Given** async-функция возвращает значение, **When** вызывающий код не ожидает
   `Обещание` сразу, **Then** в переменной лежит `Обещание`, а `Ждать` позже даёт результат.
5. **Given** повторное `Ждать` одного и того же `Обещания`, **When** оно уже завершено,
   **Then** каждое ожидание возвращает тот же результат (или ту же ошибку).
6. **Given** `Ждать` применён к обычному значению (не `Обещанию`), **When** выражение
   вычисляется, **Then** значение возвращается как есть (без ошибки).

---

### User Story 2 - Async-процедура и «запустил — жди позже» (Priority: P2)

Разработчик объявляет `Асинх Процедуру`, запускает её и получает `Обещание`-handle; позже
дожидается завершения или не ждёт вовсе (fire-and-forget). Необработанная ошибка
async-процедуры не ломает сценарий, а попадает в обработчик ошибок хоста
(`console.error` в браузере, stderr в CLI).

**Why this priority**: Процедуры без результата — половина практических сценариев
(побочные эффекты, «обнови в фоне»); пользователь явно просил handle и для процедур.

**Independent Test**: BSL-скрипт запускает `Асинх Процедуру`, печатает маркер, затем
`Ждать`-ит handle (получает `Неопределено`) и проверяет побочный эффект; отдельный скрипт
с падающей async-процедурой без ожидания печатает свой результат, а ошибка уходит в
`console.error`.

**Acceptance Scenarios**:

1. **Given** `Асинх Процедура Обновить()` с приостановкой и побочным эффектом, **When**
   скрипт делает `Обещание = Обновить();` и позже `Ждать Обещание;`, **Then** `Ждать`
   возвращает `Неопределено`, а побочный эффект выполнен.
2. **Given** async-процедура бросила ошибку и её `Обещание` никто не ожидал, **When**
   скрипт завершается, **Then** ошибка не прерывает основной сценарий и попадает в
   обработчик ошибок хоста.
3. **Given** async-процедура вызвана из обычной (синхронной) процедуры, **When** та
   возвращает `Обещание`, **Then** handle можно сохранить/передать, а ожидать — в
   async-методе или в теле модуля.

---

### User Story 3 - Композиция, совместимость и контекстные имена (Priority: P3)

Асинхронные методы вызывают друг друга, `Обещания` хранятся в переменных/коллекциях и
передаются параметрами; async-методы используют фоновые задания и `Приостановить`.
Старые скрипты, где `Асинх`/`Ждать` — обычные идентификаторы (переменная `Ждать`, метод
`Ждать()`, свойство `Объект.Ждать`), продолжают работать без изменений.

**Why this priority**: Без композиции async-методы годятся только для одиночных вызовов;
совместимость идентификаторов — требование эталонного разбора и обратной совместимости.

**Independent Test**: скрипт с `Асинх Функцией Внешняя()`, вызывающей `Ждать Внутренняя();`,
даёт корректный результат; скрипт с `Перем Ждать;` и `Процедура Асинх()` исполняется как
раньше; async-метод внутри ждёт `ФоновыеЗадания.ОжидатьВсе`.

**Acceptance Scenarios**:

1. **Given** async-функция `Внешняя` ожидает `Внутреннюю`, **When** обе объявлены `Асинх`,
   **Then** `Ждать Внешняя()` даёт итоговый результат, а промежуточные паузы не блокируют хост.
2. **Given** async-функция вызывает `ФоновыеЗадания.ОжидатьВсе`/`Приостановить`, **When**
   её ждут, **Then** задания и паузы работают как в спеке 011.
3. **Given** в модуле объявлена переменная `Ждать` или метод `Ждать()`, **When** скрипт
   исполняется, **Then** поведение прежнее (вне async-контекста это обычные идентификаторы).
4. **Given** `Обещание` сохранено в `Массив`/`Структуру` и передано в async-метод, **When**
   его ожидают в другом месте, **Then** результат/ошибка те же (handle — обычное значение).
5. **Given** async-метод объявлен `Экспорт`, **When** он вызывается из импортированного
   модуля, **Then** возвращается `Обещание`, ожидаемое вызывающей стороной.

---

### Edge Cases

- `Ждать` без операнда (`Ждать;`) и `Ждать Ждать X` — синтаксические ошибки (как в эталоне).
- `Ждать` вне async-метода и вне тела модуля (например, в обычной процедуре) — ошибка
  «Ждать допустим только в асинхронном методе или теле модуля».
- `Асинх` перед чем-то, кроме `Процедура`/`Функция`, — ошибка разбора; `Асинх
  ПриСозданииОбъекта` запрещён.
- Ошибка, возникшая в async-методе до первой приостановки, не бросается синхронно
  вызывающему, а сохраняется в `Обещании` (как в 1C/JS) и всплывает при `Ждать`.
- `Обещание`, которое никто не ожидал и которое завершилось ошибкой, не теряется молча:
  хост печатает ошибку; сценарий продолжается.
- Взаимное ожидание двух async-функций (A ждёт B, B ждёт A) не обнаруживается — дедлок,
  как и в фоновых заданиях; документируется.
- `Ждать` из двух разных логических потоков одного `Обещания` — оба просыпаются при
  завершении; повторное ожидание разрешено.
- `Обещание` нельзя создать через `Новый`, у него нет публичных методов/свойств; `ТипЗнч`
  возвращает `Обещание`; `Строка(Обещание)` — осмысленное представление.
- Параметры async-методов передаются только по значению; `Знач` необязателен и не меняет
  поведения; изменения параметра внутри не видны вызывающему.
- `Возврат` в `Асинх Процедуре` без значения, в `Асинх Функции` — со значением
  (проверки контекста как у обычных методов).
- Нельзя ожидать `Обещание`, созданное в «уже завершившемся» запуске после завершения
  хоста; `Ждать` после завершения хоста не рассматривается (out of scope).
- `Асинх`-методы не участвуют в `ФоновыеЗадания.ПолучитьФоновыеЗадания`; фоновые задания
  и async-методы — разные сущности одного планировщика.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Парсер ДОЛЖЕН принимать `Асинх`/`Async` непосредственно перед
  `Процедура`/`Функция` (в модуле, импортируемых модулях, динамическом коде) и помечать
  объявление как асинхронное.
- **FR-002**: Парсер ДОЛЖЕН разбирать `Ждать`/`Await` как унарный префиксный оператор в
  выражении и как оператор-выражение; приоритет — ниже постфиксных операций
  (`Ждать Вызов().Поле` = `Ждать (Вызов().Поле)`), операнд обязателен.
- **FR-003**: `Асинх` и `Ждать` ДОЛЖНЫ оставаться контекстными: вне async-контекста и в
  позициях идентификаторов (`Перем Ждать;`, `Процедура Ждать()`, `Объект.Ждать`,
  `Ждать = 5;`) это обычные имена — обратная совместимость со скриптами и тестами эталона.
- **FR-004**: `Ждать` ДОЛЖЕН быть допустим в теле асинхронного метода и (расширение
  проекта) в исполняемом теле модуля; в обычных синхронных методах — ошибка с позицией.
- **FR-005**: Вызов асинхронного метода ДОЛЖЕН немедленно возвращать `Обещание`:
  исполнение начинается сразу и идёт до первой приостановки; приостановка возвращает
  управление хосту/вызывающему, не блокируя страницу.
- **FR-006**: Вызов `Асинх Функции` и `Асинх Процедуры` ДОЛЖЕН возвращать `Обещание`;
  ожидание `Обещания` процедуры даёт `Неопределено`, функции — её `Возврат`.
- **FR-007**: `Ждать` ДОЛЖЕН: для завершённого `Обещания` — сразу вернуть значение/бросить
  ошибку; для незавершённого — приостановить текущий логический поток до завершения; для
  не-`Обещания` — вернуть значение как есть; повторное ожидание ДОЛЖНО быть допустимо и
  кэшировать результат/ошибку.
- **FR-008**: Ошибка из async-метода ДОЛЖНА храниться в `Обещании` и всплывать в точке
  `Ждать` как исходное исключение, ловимое `Попыткой`; синхронно вызывающему она не
  бросается.
- **FR-009**: Необработанная ошибка `Обещания` (async-процедура без ожидания) НЕ ДОЛЖНА
  прерывать основной сценарий; она ДОЛЖНА попадать в обработчик ошибок хоста (в браузере —
  `console.error`, в CLI — stderr), сценарий продолжается.
- **FR-010**: `Обещание` ДОЛЖНО быть непрозрачным значением: без конструктора
  (`Новый Обещание` — ошибка) и без публичных методов/свойств (как в 1C 8.3.18); его можно
  хранить, передавать, возвращать, класть в коллекции; `ТипЗнч` даёт `Обещание`.
- **FR-011**: Параметры асинхронных методов ДОЛЖНЫ передаваться по значению (как в 1C);
  `Знач` необязателен; изменения параметра внутри не видны вызывающему.
- **FR-012**: Асинхронный метод ДОЛЖЕН поддерживать `Экспорт`, рекурсию, вызовы обычных и
  других асинхронных методов, `Возврат` с проверками контекста (функция/процедура).
- **FR-013**: Асинхронные методы ДОЛЖНЫ использовать существующие кооперативные
  приостановки (`Приостановить`, ожидания фоновых заданий); `Асинх`-методы не
  регистрируются в реестре `ФоновыеЗадания`, но используют тот же планировщик.
- **FR-014**: `run`/хосты ДОЛЖНЫ дожидаться завершения async-исполнения тела модуля:
  `<one-script>` — перед привязкой обработчиков, CLI — перед выходом; вывод `Сообщить`
  идёт в `console.log` по мере выполнения.
- **FR-015**: Диагностика ДОЛЖНА быть двуязычной и содержать позицию: `Ждать` без
  операнда, двойной `Ждать`, `Ждать` в недопустимом контексте, `Асинх` не перед методом,
  `Асинх ПриСозданииОбъекта`, `Ждать` в объявлении модуля как ключевом слове не ломает
  обычные идентификаторы.
- **FR-016**: Английские алиасы `Async`/`Await` и тип `Обещание`/`Promise` ДОЛЖНЫ
  поддерживаться наравне с русскими именами (конституция, принцип I).
- **FR-017**: Обратная совместимость: скрипты без новых ключевых слов и прежние 474 теста
  остаются зелёными; новых зависимостей нет; синхронные скрипты не становятся async.
- **FR-018**: В браузере async-исполнение не ДОЛЖНО блокировать страницу дольше кванта;
  длинные вычисления в async-методе уступают хост по квантам, как фоновые задания.

### Key Entities

- **Обещание / Promise** — непрозрачный handle асинхронного вызова: состояние
  «ожидание/успех/ошибка», кэшированные результат или ошибка; ожидание — только через `Ждать`.
- **Асинхронный метод** — `Процедура`/`Функция`, помеченная `Асинх`; исполняется в
  логическом потоке планировщика, может приостанавливаться; вызов возвращает `Обещание`.
- **Оператор `Ждать`** — точка приостановки текущего логического потока и разворачивания
  `Обещания` в значение/исключение.
- **Логический поток** — исполнение тела модуля, async-метода или фонового задания;
  переключение только в точках приостановки и по квантам (спека 011).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Async-функция с `Приостановить(100)` возвращает результат через `Ждать`;
  20 параллельно запущенных async-вызовов по 100 мс завершаются заметно быстрее
  последовательных 2 секунд (цель — менее 1 секунды).
- **SC-002**: Браузерная страница остаётся отзывчивой: во время async-ожидания в 300 мс
  хост успевает обработать не менее 10 таймеров (happy-dom-тест + `examples/async.html`).
- **SC-003**: 100% ошибок async-методов: при `Ждать` ловятся `Попыткой`; без ожидания
  попадают в `console.error`/stderr и не роняют сценарий.
- **SC-004**: Повторное ожидание 100% случаев возвращает тот же результат/ошибку; ожидание
  не-`Обещания` возвращает значение без ошибки.
- **SC-005**: Диагностика разбора покрыта тестами для ≥ 12 сценариев из
  `ParserTests.cs` (async-процедура/функция, приоритет await, запрет вне контекста,
  двойной await, без операнда, контекстные идентификаторы `Ждать`/`Асинх`); расхождение
  «top-level await разрешён» зафиксировано отдельным тестом и в `docs/status.md`.
- **SC-006**: `pnpm typecheck && pnpm test && pnpm build` зелёные; прежние 474 теста не
  изменены; `dist/onescript.js` собирается; новых зависимостей нет.
- **SC-007**: Скрипт из `examples/async.html` в браузере печатает результат после
  async-ожидания, а нативный счётчик страницы продолжает тикать (ручная приёмка).

## Assumptions

- Порядок работ: база — спека 011 (фоновые задания, генераторный драйвер, `flushAsync`);
  `Асинх`/`Ждать` — сахар/API поверх той же модели исполнения, а не второй планировщик.
- `Ждать` в теле модуля — осознанное расширение; в остальном синтаксис и диагностика
  портируются из парсера эталона (включая английские алиасы).
- Вызов async-процедуры возвращает `Обещание` (расхождение с 1C, но единообразно и по
  запросу пользователя).
- `Обещание` непрозрачно, как в 1C 8.3.18: без методов/свойств и конструктора; отмена,
  таймауты и `КогдаВсе`/`КогдаЛюбой` — вне scope (композиция через код пользователя).
- Параметры по значению; async-конструкторы, async-обработчики событий с ожиданием,
  async-импорт модулей и async HTTP (`fetch`) — вне scope этой спеки.
- Необработанные ошибки `Обещаний` печатаются хостом; политики «unhandled rejection
  как фатальная ошибка» нет.
- Тестовый раннер xUnit остаётся синхронным (`shortcut` из спеки 011): async-тесты в нём
  не поддерживаются; покрытие — Vitest-тестами движка.
- Реальный браузер для приёмки — вручную (Playwright — спека 007); автотесты — happy-dom.
