# Contract: каталог API движка

Каталог — **единственный источник** данных для completion, hover и семантических проверок
(FR-012). Ручные списки запрещены. Источник истины — `docs/reference.md`; имена сверяются с
кодом движка существующим `scripts/check-api-docs.mjs`.

## Артефакт

`src/lsp/generated/api-catalog.ts` — сгенерированный TS-модуль, **коммитится**:

```ts
// Сгенерировано scripts/build-api-catalog.mjs из docs/reference.md. Не редактировать вручную.
export const API_CATALOG = { /* ApiCatalog, см. data-model.md §2 */ } as const;
```

Схема и инварианты — в `data-model.md` §2. Генератор детерминирован: одинаковый
`docs/reference.md` даёт побайтно одинаковый файл (порядок разделов/строк сохраняется).

## Генерация

- Команда: `pnpm build:catalog` (`node scripts/build-api-catalog.mjs`).
- Вход: `docs/reference.md`; вспомогательно — скан `src/` для `registerType` (флаг
  `constructible`) и для сверки имён.
- Выход: `src/lsp/generated/api-catalog.ts`.
- Перегенерация обязательна в том же изменении, где меняется API/stdlib или справочник
  (расширение правила 9 `AGENTS.md`).

## Разбор справочника (детерминированные правила)

1. **Функции**: таблицы с заголовком `| Функция | Параметры | Возвращает | Описание |`
   в разделах функций. Строка → `FunctionInfo`; имя `Рус / Eng` → `ru`/`en`.
   Таблицы `| Функция/оператор | Синтаксис | Возвращает | Описание |` (встроенные операторы
   языка) тоже попадают в каталог, но с `params: []` и `arityKnown: false` — синтаксис
   операторов не парсится, арность не проверяется.
2. **Объекты**: заголовки `### <Рус> / <Eng>`; внутри — таблицы
   `| Метод | Параметры | Возвращает | Описание |` и
   `| Свойство | Тип | Доступ | Описание |`. Строки → `TypeInfo.methods/properties`.
   Типы без таблиц методов/свойств (например, `УникальныйИдентификатор`) добавляются по
   заголовку, если имя зарегистрировано через `registerType`.
3. **Перечисления**: раздел `## Перечисления`; заголовки `### <Рус> / <Eng>`;
   таблица `| Значение | Англ. алиас | Смысл |` → `EnumInfo.values`.
4. **Параметры**: ячейка `Имя?: Тип`, несколько через запятую верхнего уровня;
   `?` → `optional`; `…`/`...` в имени/типе → `variadic: true`.
5. **Среда**: если раздел/строка явно помечены «только Node»/`[Node]` → `env: 'node'`;
   «браузер» → `'browser'`; иначе поле отсутствует. Фильтрация по среде не делается
   (диагностика `[Node]`-API вне объёма).
6. **Constructible**: `true` только для имён, зарегистрированных через `registerType`;
   прочие разделы (`Тип`, `ИнформацияОбОшибке` и т.п.) при автодополнении `Новый` не
   предлагаются.
7. **Глобалы**: имена из `registerGlobal` (`Ожидаем`, `ФоновыеЗадания`, …) попадают в
   `ApiCatalog.globals` и в `knownGlobalNames` (для разрешения имён), но не в функции.

## Инварианты и тесты

| Инвариант | Проверка |
|---|---|
| Каждое имя из каталога — допустимый BSL-идентификатор | drift-тест |
| Каждое публичное имя из `src/` присутствует в каталоге | тест кросс-сверки: кандидаты из логики `check-api-docs.mjs` ⊆ имена каталога |
| `ru`/`en` не пустые; `en` либо корректный алиас, либо отсутствует | drift-тест |
| Арность согласована: `required ≤ max`; variadic — последний | drift-тест |
| Сгенерированный файл соответствует текущему справочнику | drift-тест: генерация в память + сравнение с коммитом (при расхождении — подсказка `pnpm build:catalog`) |
| `check-api-docs` и drift-тест зелёные вместе (нет «двух правд») | `pnpm test` |

## Использование в сервере

- Completion: функции/типы/перечисления/глобалы — `label = ru`, `detail = сигнатура`,
  `documentation = description` (markdown); английские алиасы — отдельные items с тем же
  описанием.
- Hover: markdown `Рус / Eng`, сигнатура, параметры, возврат, описание, раздел.
- Семантика: `knownGlobals` = функции + типы + перечисления + глобалы; арность — по
  `required`/`max` (см. `contracts/diagnostics.md`, OSJS3002).
